# 设备循环重启修复（2026-11-04）

## 现场证据

点云卡顿实际伴随循环重启。串口 `evidence/device-status-20261104.log` 连续记录 ESP_ERR_NO_MEM，崩溃位置为官方 SDK phy_common.c 的 phy_track_pll_init，esp_timer_create 申请内部 RAM 失败。

## 修改范围

仅修改固件 main/main.cpp：

- 网络就绪、配对完成后再初始化音频，配对和配网不启动音频前端。
- 使用官方 heap_caps_malloc_extmem_enable(1024)，让超过1KB的通用分配优先使用PSRAM，保留内部RAM给PHY、DMA和系统控制结构。显式要求内部RAM的分配不受影响。
- 增加启动阶段内存日志；音频初始化失败保留错误画面，不立即触发重启循环。
- 唤醒模型、检测阈值、音量和点云参数不变。

仅调整启动顺序不足以解决问题：`device-startup-memory-20261104.log` 证明模型启动时仍会崩溃。最终内存策略修复后，音频初始化后的内部空闲内存由约80219字节提高至104467字节，模型mn6_cn正常初始化。
