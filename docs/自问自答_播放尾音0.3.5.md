# 2026-11-02：小燕子"无限自我对话"（0.3.5 播放尾音静音 + 网关自触发熔断）

牛牛反馈"后台小燕子在无限自我对话"。查网关日志确认：0.3.4 固件在回答播放结束后，编解码器/I2S 尾音被云端 VAD 判成人声，云端自动生成新回答，回答播完再触发，形成自问自答死循环；0.3.4 的"播放期上传置零"只覆盖到 `g_speaking=false` 为止，没盖住结束后的尾音。

## 证据（会话 09dd524742264c029e3ebeaa1060c428，本地时间 10:48:54–10:50:26，共 91 秒）

- 9 段语音回答（约 39.8 秒 TTS）、10 次模型回合、771 输出 token；上下文从 3.4k 涨到 15.3k（中途进入 `executing`，疑似触发工具调用）。
- 全程 **无任何真人打断**：没有 `device_interrupt`、`barge_in`、`abort` 记录。
- 每轮节奏：`pcm_delivery`（回答播完）→ `state=listening`（设备恢复上行）→ 0.4–2.3 秒后 `speech_stopped/thinking` → 新的 `response.created`；播放结束到下一轮"人声"结束的间隔稳定在 **0.77–0.99 秒**。
- 最后一轮回答播完后没有再触发（尾音恰好没被 VAD 命中），30 秒后由 `idle_seconds` 看门狗自动结束会话。
- 日志摘录：`evidence/self-turn-loop-session-09dd5247-20261102.log`。

## 机制

1. 服务端 `tts stop` 到达时，设备把结束 chunk 入队；播放任务读完结束 chunk 后置 `g_speaking=false`，但 codec/I2S 里还有约 100–300ms 尾音。
2. 0.3.4 只在 `g_speaking==true` 时清零上行帧；一旦置 false，采集循环立即上传真实麦克风数据，这段尾音就进了上行。
3. 云端 qwen `server_vad`（threshold 0.75、silence_duration_ms 600）把尾音判成人声，`speech_stopped` 后自动生成回答（`session_settings` 里 `turn_detection=server_vad`，不是手动触发）。
4. 新回答播完 → 尾音再次上传 → 再触发，无限循环。0.3.3 的"回答-打断循环"被 0.3.4 修掉后，同一根因变成了"回答-自问自答循环"。

## 0.3.5 修复

### 固件（根因）：播放结束尾音静音窗口

`firmware/assistant_espidf/main/control_protocol.cpp`：

- 新增 `g_playback_end_us` 与常量 `kUplinkEchoTailUs = 400000`（400ms）。
- 新增 `note_playback_stopped()`：仅当 `g_speaking` 由 true 变 false 时"先记时间戳、再置 false"；所有停播路径（自然结束、`tts stop` 队列失败、`tts_stop`/`interrupt`、custom idle、上行队列溢出、断线、abort）统一调用。
- 采集循环在 `g_listening` 且非 `g_speaking` 时，若距播放结束 <400ms：`memset(frame,0,bytes)` 后**照常发送静音帧**（不跳过，避免云端误判断流），窗口内不喂唤醒词、清零 `g_loud_hold_us`。
- barge candidate/confirmed、唤醒词打断逻辑未改；`confirm_barge` 与 barge 超时路径故意不写结束时间戳，避免 barge-in 后把用户真实语音清零。
- `version.txt` → 0.3.5（构建日志确认 `-- App assistant_espidf version: 0.3.5`）。

产物：`firmware/assistant_espidf/build/assistant_espidf.bin`，2,478,448 字节，app_desc 版本 0.3.5，SHA256 `E3F1E53795DE6E8F3265F6FAE9780EFDF5216723B920DD3B8503280858200EF2`（Docker `espressif/idf:v5.5.2`，构建日志 `evidence/firmware-0.3.5-build-20261102.log`）。

2. 回答中/刚播完时真人说话，仍能正常打断或接新内容（固件 400ms 静音窗口可能吞掉紧贴播完开头的 400ms，属预期取舍）。
3. 若仍偶发自问自答：看 `stt_text`/`vad_self_turn_cancelled` 记录的人声时长，再调 `kUplinkEchoTailUs`（500–600ms）或 `SELF_TURN_*` 阈值。
4. 回滚：固件改回小值并重编 OTA，或网关把 `SELF_TURN_STREAK_LIMIT` 调大/停用熔断。

## 已知取舍

- 固件 400ms 静音窗口：回答结束后 400ms 内用户开口，开头会被吞；唤醒词在这 400ms 内不参与检测（云端口语内容仍可在窗口后正常接收）。
- 网关熔断：播放结束后 1.2s 内 <500ms（无音频时间戳时 <1000ms 间隔）的真实短指令（如"停"）会被当疑似，第 1 次只取消该回答，连续 2 次会结束会话；阈值是常量，可调。
- 熔断依赖云端事件顺序（`speech_stopped` 先于 `response.created`）；顺序异常时最坏漏取消一轮，不影响固件根因修复。
