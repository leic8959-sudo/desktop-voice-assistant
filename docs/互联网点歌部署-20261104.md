# QQ Music → Music Assistant → 小燕子实体喇叭

后续状态：牛牛明确授权代理执行安装并本人完成MA/QQ登录，Music Assistant 2.10.9已部署，小燕子播放器注册、网关连接和0.3.12 OTA已完成；真实歌曲短测、暂停/续播及登录持久性证据见`互联网点歌实机接入-20261104.md`。下文“本轮未安装/未启动”描述最初子模块源码交付阶段，不代表当前状态。

本实现把 Music Assistant 已授权曲库中的正式音频流交给本机网关，再使用设备音乐 PCM 通道送至小燕子实体喇叭。电脑浏览器只做搜索和控制，不承担最终播放。QQ/微信扫码必须由账号本人在 Music Assistant 页面完成；本项目不收集 QQ 密码、不解析未授权音源，不绕过订阅、地区限制或 DRM。

## 由牛牛执行的部署步骤

本轮没有拉取镜像、安装依赖、启动 Music Assistant、登录音乐账号、重启在线网关或烧录硬件。以下 Docker 命令会下载镜像并创建长期运行服务，需要牛牛在 PowerShell 执行：

```powershell
Set-Location 'I:\new find\desktop_voice_assistant'
docker compose -f docker-compose.music.yml up -d
```

固定镜像为 `ghcr.io/music-assistant/server:2.10.9`，官方稳定版本发布日期为 2026-10-30，不使用 `latest`。官方提供 Docker 部署和 `amd64` 构建，包含 MA 所需的 FFmpeg 和原生依赖。本机 Windows Docker Desktop 使用 Linux 容器。现有 Home Assistant 的 8123 端口不被修改。

| 项目 | 本项目配置 |
| --- | --- |
| 管理 UI 和正式命令 API | `http://127.0.0.1:8095`，仅宿主本机映射 |
| MA 完整音频流 | `http://127.0.0.1:8097`，仅宿主网关读取 |
| MA 数据与账号授权 | `runtime/music-assistant` → 容器 `/data`，不得上传 |
| 自定义播放器扩展 | `tools/music_assistant_player` 只读挂载至固定 2.10.9 / Python 3.14 的 `site-packages/music_assistant/providers/xiaoyanzi` |
| 日志 | Docker `json-file`，单文件 10 MiB，最多 3 份 |

本路径使用自定义播放器，免用 mDNS 发现实体喇叭，因此没有把 Linux 的 `network_mode: host` 照搬到 Windows。MA 流服务可能向扩展返回容器 172.x 地址；客户端先校验固定播放器的真实 `/single/` 会话路径，再将源站替换为管理员明确配置的 `stream_base_url`。不让 Windows 网关直接连接容器地址。

部署后：

1. 打开 [本机 Music Assistant](http://127.0.0.1:8095)，建立 MA 本身的管理员并完成首次设置。
2. 在 MA 添加播放器提供商 **小燕子网关**，得到固定播放器 `xiaoyanzi_gateway`。这是本项目附带的本地扩展，必须和固定版本一起维护；它不等于官方 Universal Player，也不冒充 MA 原生支持 ESP32。
3. 在 MA 添加 **QQ Music** 音源，选择 QQ 或微信扫码，由本人扫描并确认。账号凭据由 MA 自己保存；会员/曲库权限由 MA 的 QQ 提供商处理。
4. 在 MA 用户/访问令牌管理功能中创建供本机小燕子使用的访问令牌。此流程需要 `library.read`、`queues.control` 和 `players.control` 权限，并允许访问固定播放器 `xiaoyanzi_gateway`。不要把 QQ 密码或小燕子的 `device_token` 当成 MA 访问令牌。
5. 在网关的 `/static/music.html` 本机登录，保存管理地址 `http://127.0.0.1:8095`、音频地址 `http://127.0.0.1:8097` 和 MA 访问令牌。令牌留空保留，显式勾选才清除。地址和令牌保存成功只表示写入本机 DPAPI，尚未核验音源。
6. 确保网关已经加载本次代码，并且唯一在线设备已经安装支持音乐通道的固件。修改源文件不会自动让正在运行的旧网关加载新路由。
7. 搜索一个账号有权完整播放的歌曲。核对歌名、歌手和版本，再点击 **在小燕子播放**。只有实体设备回执 `started` 才显示播放中。暂停后用设备实际回报进度续播；没有确认位置时不虚构恢复点。

MA 自身的虚拟播放器没有直接向设备发命令；播放、暂停、继续、停止请使用小燕子点歌页面或已经接线的语音工具。只在 MA UI 中点虚拟播放器播放不会让设备自动发声，没有设备回执的流准备会在 15 秒后释放。

### 找不到 Music Assistant 设置时

小燕子管理后台和 Music Assistant 是两个服务、两套登录。小燕子的「本机登录」不会替你登录 8095 上的 Music Assistant。

先打开 [Music Assistant 首页](http://127.0.0.1:8095)。如果已经建立过 MA 账号，请用那个账号登录；`/setup` 显示 `Setup has already been completed` 表示不能重复创建首次账号，不代表 QQ 已授权。登录后可以直接使用已从当前容器前端路由核对的入口：

| 要做的事 | 页面及操作 |
| --- | --- |
| 打开设置总页 | [设置](http://127.0.0.1:8095/#/settings) |
| 添加 QQ Music | [音乐来源](http://127.0.0.1:8095/#/settings/providers?types=music)，点带加号的「添加音乐提供商 / Add music provider」，在弹窗搜索 `QQ Music`，选择后由本人选 QQ/微信并扫码 |
| 添加小燕子播放器扩展 | [播放器提供商](http://127.0.0.1:8095/#/settings/providers?types=player)，点带加号的「添加播放器提供商 / Add player provider」，搜索 `小燕子网关` |
| 查看已注册播放器 | [播放器](http://127.0.0.1:8095/#/settings/players)，核对「小燕子实体喇叭（网关控制）」 |
| 创建访问令牌 | [个人资料](http://127.0.0.1:8095/#/settings/profile)，找到「长期令牌 / Long-lived tokens」，点「创建令牌 / Create token」，取一个用途名称；新令牌只在创建后展示，复制到小燕子点歌页的密码输入框 |

初次登录可能先看到设置向导卡片，其中分别有「添加音乐」和「添加播放器」按钮，它们进入同样的音乐/播放器提供商页。设置和添加提供商是管理员功能；普通用户可能看不到这些入口。容器实际前端的设置键为 `settings.music_sources`、`settings.playerproviders`、`auth.profile`、`auth.long_lived_tokens`、`auth.create_token`，具体中文翻译随语言包显示。

如果“已添加列表”没有小燕子，这还不能说明扩展缺失：必须在 `types=player` 的页面点击 **加号添加播放器提供商**，在弹出的候选列表搜索中文 **小燕子**，并清除阶段筛选。容器重启或新增本地扩展后，先 `Ctrl+F5` 刷新浏览器，更新前端缓存的提供商清单。没有 `types=player` 的通用提供商页默认只列音乐来源，QQ Music 所在列表不会列播放器扩展。小燕子扩展不要求额外填写表单，选中后官方零输入设置流程应直接完成添加；随后到「播放器」核对固定实体喇叭条目。

这里的 MA 访问令牌与设备配对码、小燕子管理员认证均不是同一项。不要重新解绑设备来解决 MA 设置入口问题。

可由牛牛执行的状态核查命令，不会改变业务账号：

```powershell
docker compose -f docker-compose.music.yml ps
docker compose -f docker-compose.music.yml logs --tail 80 music-assistant
```

日志可能包含提供商错误和媒体信息，分享前检查敏感内容。停止此新增服务可执行 `docker compose -f docker-compose.music.yml stop`，保留数据目录。

## 已核查的官方合同

核查的是官方仓库 **2.10.9 标签**，不是按旧文章猜接口。

- [稳定发布 2.10.9](https://github.com/music-assistant/server/releases/tag/2.10.9)。[官方 Dockerfile](https://github.com/music-assistant/server/blob/2.10.9/Dockerfile) 安装目录是 `/app/venv`；[.python-version](https://github.com/music-assistant/server/blob/2.10.9/.python-version) 为 3.14。[官方安装说明](https://music-assistant.io/installation/)。
- [webserver/controller.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/controllers/webserver/controller.py)：注册 `POST /api`，请求为 `{command,args}`，通过 `Authorization: Bearer ...` 认证；成功直接返回命令结果 JSON，非二次 `result` 包裹。`/api-docs/commands.json` 是服务实时命令目录。`/preview` 是 30 秒样本，未用作全曲入口。
- [music/controller.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/controllers/music/controller.py)：`music/search` 参数为 `search_query`、`media_types:["track"]`、`limit`、`library_only:false`，响应 `tracks`。本客户端最多取 10 项；上层点歌服务最多取 5 项，再生成仅服务端保存的短期选择 token。
- [官方播放器示例](https://github.com/music-assistant/server/tree/2.10.9/music_assistant/providers/_demo_player_provider)：扩展继承 `PlayerProvider` / `Player`，实现 `play_media(media)`，再调用 `mass.streams.resolve_stream_url(player_id, media)`。这个解析方法是 MA 内部方法，并非可直接调用的官方 HTTP 命令；本项目通过本地扩展暴露有限的已认证命令。
- [streams/controller.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/controllers/streams/controller.py)：正式单曲路径为 `/single/{session_id}/{queue_id}/{queue_item_id}/{player_id}.{fmt}`；源码 650–653 按此顺序生成 URL。流服务默认端口 8097。网关只接受 fixed queue/player `xiaoyanzi_gateway` 的此类路径和白名单音频格式，拒绝重定向。
- [player_queues/controller.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/controllers/player_queues/controller.py) 和 [queue_loader.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/controllers/player_queues/queue_loader.py)：`ADD` 只装载，`play_index(...,seek_position=...)` 准备正式恢复点并等待 `PLAYING` 回执。扩展先清空固定队列，只保留一首，关闭自动推荐、重复和交叉淡化，实际实体队列由小燕子上层管理。
- [QQ Music setup_flow.py](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/providers/qqmusic/setup_flow.py)：QQ Music 没有官方 OAuth，此提供商实现 QQ/微信二维码登录；凭据存入 MA 的 `setup_data`。本项目复用该流程，不宣称提供腾讯官方 OAuth。
- [Universal Player README](https://github.com/music-assistant/server/blob/2.10.9/music_assistant/providers/universal_player/README.md)：它自动组合已有协议播放器，不支持手动凭空新增播放器，因此本方案提供独立播放器扩展。
- [models 1.1.205 enums](https://github.com/music-assistant/models/blob/1.1.205/music_assistant_models/enums.py) 和 [auth](https://github.com/music-assistant/models/blob/1.1.205/music_assistant_models/auth.py)：这是 2.10.9 `pyproject.toml` 固定依赖；`PlayerFeature.PLAY_MEDIA` / `PAUSE`、`QueueOption.ADD`、`RepeatMode.OFF` 及上述权限枚举均有实际定义。

## 本地扩展与父应用接口

`integrations/music_assistant.py` 的 `MusicAssistantClient(config,http)` 复用父 HTTP 会话，提供 `start/close/configure/search/resolve_stream/report/stop`。不会构造时访问外部服务。配置保存为独立 `runtime/music-assistant.dpapi`，复用既有 `DpapiTokenVault`；非 Windows 不降级明文，损坏存储不覆盖。令牌不回显、不放 URL、不进入前端持久存储，不发往重定向或代理。配置保存复用现有 HTTPS / loopback 安全边界。

`search()` 返回 `{"items":[{"ref":{"uri","provider","item_id"},"title","artists","album","duration_s","available"}]}`，只把 `ref` 留给服务端。`resolve_stream(ref,position_s)` 返回内部来源 `{kind:"http",trusted_by:"music_assistant",base_url,url,headers:{},format,source_position_s,start_position_s,seek_applied:true,session_id}`。此来源及会话值不能送至模型、页面、日志或持久化播放书签。父层把所选曲目标题和时长补给 PCM 引擎；引擎不重复跳过 MA 已处理的恢复点。

MA 扩展自定义认证命令为 `xiaoyanzi/resolve`、`xiaoyanzi/report`、`xiaoyanzi/stop`，均限制固定播放器并检查用户播放器过滤权限。随机 lease 隔离旧回执；未收到首次播放回执 15 秒释放，后续 90 秒没有设备进度/状态回执也释放。`report` 的 PLAYING 只从实体回执更新，不用“请求已接受”推断已播放。

API 模块导出 `INTERNET_MUSIC_KEY = web.AppKey(..., object)` 和 `register_routes(app)`，必须位于既有 `api_boundary` 中：

| 路由 | 内容 |
| --- | --- |
| `GET /api/music/status` | 父服务脱敏状态 |
| `GET/POST /api/music/config` | 脱敏配置 / 顶层 `base_url,stream_base_url,access_token,clear_token` |
| `GET /api/music/search?q=...&limit=5` | 当前授权曲库候选 |
| `POST /api/music/play` | `{selection_id}`，页面明确点击才播放 |
| `POST /api/music/actions/pause` | `{}`，停止读取并保留确认进度 |
| `POST /api/music/actions/resume` | `{}`，按实际设备位置重新取得流 |
| `POST /api/music/actions/stop` | `{}`，停止并清空实体队列 |
| `POST /api/music/actions/queue` | `{selection_id}`，加入最多 8 首队列 |

## 当前验收边界

本子模块完成代码与官方源码合同审阅；未主动运行测试、构建、类型检查或服务。官方源码的读取不能替代实际容器启动、提供商登录、全曲流和板端扬声器验收。需要依次确认：Docker 成功启动、扩展成功加载、QQ 账号本人扫码、有效访问令牌、网关加载代码、支持媒体的设备在线、实际完整歌曲发声、暂停/继续位置正确、语音抢占以及结束/断线释放。未 Git 写入、未上传、未发布。
