# 设备绑定显示修复

日期：2026-11-04（Asia/Shanghai）。牛牛确认选择“修复后台显示，保留现有绑定”。

## 原因与现场

实际打开 http://localhost:8765/static/devices.html，设备 desk-1770bd2934c31b2f 处于在线状态，固件版本显示 0.3.7；同时出现离线的 desk-prototype-01。设备接口无条件把配置中的默认 ID 当成设备列入结果，造成虚假离线项。设备页远程访问分支还会在检查已有 Cookie 会话前直接要求令牌，且未区分尚未认证与没有绑定设备。

当前固件持有长期凭据时不会重新进入出码流程，服务端解绑也不会清除设备端凭据。因此不能以重新绑定作为后台显示错误的处理方式。本轮没有触发解绑、配对、固件操作或设备重启。

## 修改

- `web/devices.js`：复用现有 `console_api.js` 的 Cookie / 可选 Bearer、超时与取消；先尝试读取已有会话，仅本机未认证且未填写令牌时沿用现有本机登录。明确区分认证失败、读取失败和已认证空列表。状态展示“已绑定 · 在线 / 离线”；兼容当前网关，隐藏没有绑定且不在线的默认配置项。令牌变更或离页时清空页面私有内容并取消旧读取。
- `web/devices.html`：说明管理员登录与设备绑定的区别；按钮改为“添加新设备”，更新 JS 模块入口及资源版本。
- `web/admin_console.js`：总览计数采用同一显示规则，当前在线 / 返回设备数恢复为 1 / 1。
- `control_api.py`：设备接口以持久化绑定记录为基础，旧版默认 ID 仅在实际在线且未重复时加入。绑定过的离线设备仍保留。

没有改变管理员权限、设备绑定记录和凭据，也没有修改固件或规则文件。后端接口改动尚未加载进当前进程；前端兼容处理已在现有服务上生效，未为此重启网关或中断设备。
