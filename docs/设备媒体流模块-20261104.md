# 设备媒体流模块（2026-11-04）

本模块实现 `src/assistant_app/application/device_media_stream.py` 与隔离解码入口 `media_decode.py`。媒体只发给原生设备的 WebSocket 二进制通道，不调用 Windows 播放器、电脑声卡或 VoiceSession，不受语音合成的 30 秒音频限制。

## 父模块合同

```python
stream = DeviceMediaStream(runtime, http)
await stream.start(device, source, position_s=0, playback_id="music-<唯一标识>")
await stream.pause()
await stream.stop()
await stream.close()
await stream.on_device_event(device, event)
state = stream.status()
```

`start` 校验来源、设备在线和协议能力后登记一个独立任务，立即返回 `starting`；不等待整首歌曲。设备必须在 hello 声明媒体能力，由父记录 `device.media_stream_supported=True`。旧设备拒绝播放；收到 `media_start` 的开始回执后才下载、解码和发送音频。设备开始回执把状态变为 `playing`，表示设备接受了本次媒体会话，尚不能证明喇叭已实际出声。

状态枚举为 `starting/playing/paused/stopped/ended/error`。`device_position_s` 仅来自同一设备、同一 playback_id 的有效回执；首次回执前为 `None`。`played_samples`/`position_samples` 按固件合同是绝对音轨样本位置，已经包含开始偏移，不能再加一次偏移。该回执代表 I2S 写入结果，不是独立的物理听音确认。`sent_position_s` 只表示发往设备的累计位置，不能用来宣称实际播放进度。对外状态不含源地址、路径或鉴权头。

父模块必须在 `runtime.voice_lock` 内完成音频仲裁、停止主动播报、确认语音会话已结束，然后调用 `start`。新语音或主动播报开始前，在同一语音锁内调用服务的暂停入口。本模块仅获取自己的锁，不反取语音锁；暂停/停止取消并等待发送任务，真实 kill/wait 解码子进程，然后发控制消息并等待设备停止回执。设备唤醒导致的自主 pause 回执也立即取消下载和解码。无自动恢复或自动重试；显式续播需父重新从 MA 解析新流地址。

## 可信来源

MA 适配器提供的 source：

```python
{
    "kind": "http", "trusted_by": "music_assistant",
    "base_url": "<已配置并验证的 MA 流服务来源>",
    "url": "<适配器解析和验证后的临时媒体流地址>",
    "headers": {}, "format": "wav", "duration_s": 240,
    "source_position_s": 60,
}
```

只允许 URL 与 base_url 的 scheme、host 和有效 port 完全相同；拒绝所有 HTTP 重定向、用户信息、fragment 和不安全的请求头。来源标记只能由父服务/MA 适配器构造，不能从模型工具或用户 URL 参数直接透传。适配器仍负责验证具体的 MA 流路径、真实歌曲引用与配置来源。引擎不会把流地址传给 PyAV、子进程参数或日志。

`source_position_s` 表示流第一个样本的绝对音轨位置；兼容别名 `start_position_s`。MA 已通过官方 seek 从 60 秒开始时，目标位置也是 60 秒，引擎不会再次跳过。来源从零开始时，可在解码输出中有界丢弃目标位置之前的样本；目标位置必须小于 30 分钟，不伪造 HTTP Range 或字节比例 seek。

允许 `wav/flac/mp3/ogg/aac/s16le`；原始 `s16le` 还需显式提供 `sample_rate`、`channels`。MA 当前合同使用自己的 WAV 单音轨流地址。流中其他文件或 URL 的二次打开全部拒绝。源流错误、编码不支持等情况会进入 `error`，停止设备并释放音源引用。

本地环境声只接受父构造的 `{"kind":"trusted_file","path":"<绝对WAV路径>","loop":true,"duration_s":1800}`。路径必须位于引擎确定的 runtime_dir 内；不能由请求参数指定 root 来扩大权限；拒绝 symlink/junction。仅支持普通 PCM16、单/双声道、8～48kHz WAV。循环使用同一 media 会话，逐段重新打开有界管道解码；每段衔接需后续真实听感验收，不能宣称无缝。`playback_limit_s` 可显式覆盖循环总预算，缺省使用 duration_s；最大 30 分钟。

## 设备协议

| 方向 | 消息 |
| --- | --- |
| 网关→设备 | `media_start`，固定 pcm_s16le/24000Hz/1声道，`frame_duration_ms=20`，`position_samples` 为绝对起点，playback_id 为1～63个安全ASCII字符，title 按UTF-8最多192字节，duration_s 为不超过1800的整数时长 |
| 设备→网关 | `media_ack`，`state` 为 start/progress/pause/stop/ended/error，回传 playback_id、绝对 played_samples/position_samples；progress 约每秒一次 |
| 网关→设备 | 开始回执后，二进制 PCM16 每20ms发送960字节；最后一帧可以较短，不补造有效样本 |
| 网关→设备 | `media_pause` / `media_stop`，设备清队列并停止I2S写入后确认 |
| 网关→设备 | `media_end`，设备自然排空队列后返回 ended，作为音轨完成依据 |

固件回传 queue_used/queue_capacity；发送器有队列高水位退让、20ms节拍和事件循环迟延后的时钟重置，避免突发追赶。开始确认等待3秒，控制确认等待2秒，结束排空确认等待4秒，单次设备发送2秒；播放时进度回执超过3秒未更新即失败停止。

## 资源与错误边界

每曲真实墙钟最多30分钟，源输入最多512MiB；512MiB是传输总量上限，不是缓存大小。父按32KiB读取，解码器管道按64KiB级水位背压；发送缓冲最多960字节。单条实际解码音轨最多30分钟PCM24（86,400,000字节），单输入包最多1MiB，最多300,000个包/帧。HTTP连接/建连5秒、读取10秒；解码输出读取15秒，子进程正常退出等待3秒。stdin背压等待受发送任务和整曲30分钟上限约束。无全曲内存缓存、临时落盘或曲库全量读取。

子进程仅接受固定格式与数字参数，只读stdin、写stdout，无网络来源；二次IO拒绝。stderr仅接受最多8KiB的固定JSON诊断字段，包含异常类型和栈帧的文件/行号/函数名，不含异常文本、因果链或媒体元数据；超长栈会明确标记截断。父只记录通过结构校验的栈帧，丢弃其他FFmpeg原文。父网络/设备失败日志保留原始异常的完整调用栈，但替换异常文本与因果链，避免第三方异常中URL/token泄露。对外仅给固定错误说明和错误状态，不回传第三方原始异常。取消后 kill 并排空 stdout/stderr 管道再等待进程，避免管道水位导致退出等待悬挂。
