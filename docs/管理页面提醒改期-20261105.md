# 管理页面提醒改期（2026-11-05）

实际任务入口为 `web/assistant.html`；`web/index.html` 仅跳转企业控制台。本轮复用已实现的 `POST /api/tasks/{id}/reschedule`，给有效未来时间、状态为 pending 且含记录版本的提醒增加“修改时间”行内表单，已到期、已完成、已取消和无时间任务不显示该入口。

表单明确北京时间 UTC+08:00。预填按 `Asia/Shanghai` 格式化，不依赖浏览器所在时区；提交复用固定 `+08:00` 转换并携带原 `updated_at`。只有返回目标 ID 匹配、状态 pending 且提醒时间可解析时才显示服务端真实保存时间；非法 200 回执按结果待核实处理。

在用旧网关会直接读取新静态文件，但未加载新 API 路由。因此新增真实服务端能力标记 `capabilities.task_reschedule=true`，页面严格收到 true 才显示入口；缺失、false 或字符串均隐藏。状态轮询变为支持时只更新按钮，不重绘草稿；能力丢失关闭编辑并阻止旧表单提交。状态请求同样检查认证代数，旧身份的成功或 401 均不回填新身份。没有伪造前端能力开关或自行重载网关。

请求期间禁止再次提交和其他任务行写入。普通列表加载不会重绘尚未提交的表单；显式刷新或切换编辑目标会提醒关闭草稿。没有新增任务轮询，现有状态轮询维持原行为。

列表请求和改期结果受认证代数约束，同令牌重新连接也使旧回调失效；最新列表请求之外的旧 GET 不回填。跨身份尚未结束的写请求不带旧结果、提示或自动刷新进入新身份，结束后只释放当前控件。409 后刷新再提示核对，不自动重试；刷新失败明确提示，200 已保存但刷新失败时保留真实成功时间并注明列表刷新失败。

主代理首次真实浏览器运行暴露原页面“断开”按钮没有绑定已有 `disconnect` 函数，重连用例因此失败；本轮仅补齐按钮绑定。回归使用真实点击并检查“尚未认证”和连接按钮恢复可用，不绕过 UI 调用内部函数。当前阶段副本另存 `app.before-disconnect-binding.js`。

改期请求设 15 秒浏览器等待期限。网络错误、超时、服务端错误或非法成功回执显示“结果待核实”，禁止再次提交，需显式成功刷新后由用户重新编辑；不会自动重发未知写入。所有新增动态文字通过 `textContent` 输出。
