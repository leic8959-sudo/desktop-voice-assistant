# 模拟导航常驻指示修复

牛牛反馈模拟导航句间回到普通会话点云。根因是固件 `control_protocol.cpp` 在每条 `tts stop` 无条件执行 `display_ui_nav_icon(0)`，主动播报每句单独合成并发送 start/stop；因此指示生命周期被绑定到一句音频。

本次固件 0.3.20 使用独立 `navigation` 消息：`state=step` 携带 `navigation_id` 与 `nav_icon`，在每步 TTS 合成前更新方向，下一条指令沿用同一个 ID。普通音频自然结束保留图标；`state=end` 只清理匹配 ID 的导航，避免旧任务收尾误清新任务。收尾消息不修改音频队列或会话状态。

生命周期如下：

- 启动与每步：获得语音入口锁，确认无语音会话占用后，先显示方向再合成并发送本句。
- 句间、等待下一句合成：图标保持；下条指令直接替换方向。
- 正常结束、用户取消或合成/发送异常：导航服务 finally 发送匹配 ID 的结束消息。
- 新唤醒、设备中止、断线、OTA、切换音乐、普通无导航 TTS、无效方向、音频队列失败：固件清理导航，避免残留。
- 忙碌语音、音乐或 OTA 期间：设备拒绝激活新的导航方向。

未修改 `gateway.py` 的模拟导航语音直达登记，也未修改唤醒缓存或显示热重启修复；保留同时存在的音频首包诊断改动。正式 sdkconfig、依赖锁、配置、绑定和凭据未修改。
