# 自然插话0.1.8：实现与验收

2026-10-30，牛牛授权Luna多智能体实现，由root整合验收。本页区分代码实现、模拟回归、设备播放和真人声学结果，未验收项不记为通过。

## 实现

设备端保留0.1.7的稳定显示、离线“小燕子”唤醒、独立采音与软件AEC。新增两阶段插话：

1. 根据AFE语音活动、处理后音量与环境基线形成候选，短暂停止播放并保留原回答队列。
2. 等待约200毫秒的尾音消退，再确认持续用户语音；无持续语音则约700毫秒后恢复原回答。
3. 确认后只清旧回答，等待桥接确认，再上传最多600毫秒前置音频和后续语音。

桥接使用每轮唯一playback_id和candidate_id。候选时暂停物理下发，恢复时续发同一音频块；确认时取消仍在生成的旧响应并丢弃迟到音频。云端已生成完但本地尚未播放完时，仍清本地旧队列，避免发送无活动响应的cancel。

没有擅自向千问发送OpenAI专属历史截断事件。目前实际播放位置已上报，但未播放部分如何从千问上下文删除仍未解决，日志标记`context_sync=unresolved`。

音频参考改成有界时间戳队列，未来参考不提前消费，过期参考记录丢弃。20毫秒软件参考提前量是当前调试参数，尚非已校准的声学结论。播放参考仍为软件PCM，不伪装为硬件回采。

## 设备测试工具

- `tools/barge_in_device_check.py`：仅监听已配对设备令牌，不调用千问或家居；播放本地24kHz WAV，记录候选、恢复、确认及每秒队列/音量/相关性诊断。
- `tools/run_barge_device_check.ps1`：临时停止正常桥接，运行检查，结束或失败后恢复；检查子进程退出码，失败不算通过。
- `--direct-playback`/`-DirectPlayback`：跳过唤醒入口，只在已认证测试连接明确发送诊断请求时进入测试倾听。正常桥接不发送此请求。
- `-NearSpeech`：在测试中通过电脑外放模拟用户声音。电脑外放未被设备麦克风可靠拾取时，该组只能记为无效声学条件，不能当真人测试。
- `-SkipSerial`：可用局域网诊断替代易掉线的USB日志。USB/网络断开分别记录，不因没有串口堆栈而假定设备死机或掉电。
