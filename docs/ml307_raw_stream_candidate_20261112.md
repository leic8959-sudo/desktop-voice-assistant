## 本批实现的源代码路径

| 入口 | 候选行为 |
| --- | --- |
| Create | 接收已初始化、由真正owner独占的AtUart和ID0..5，创建事件组并登记只做通知的URC回调；不创建线程 |
| Connect | 每对象一次连接尝试；串联前轮Configure／Open，共用包装入口剩余时限，不调用旧HEX TCP或模块SSL |
| Read | 固定4KiB本地数组；先消费已有字节，空了才MIPRD，单次底层拉取不超过4096；返回正字节数或错误 |
| Write | 最多接受调用者本次前4096字节，允许短写；成功仍仅是模块栈接受长度，不是服务器或业务回执 |
| RequestStop | 原子停止标志和事件唤醒，只允许任务上下文；不在回调执行关闭，不声称能取消已进入AtUart的事务 |
| Close | 先停止新I/O；仍有读写或连接操作时直接报不可用，owner等这些调用返回后重试；确认模组关闭后停用ID |

回调捕获独立共享通知状态，不捕获流对象this，不读写接收数组，不获取读写／生命周期锁，不发送AT或调用用户代码。缓存通知用事件位合并；每次读入口先探测缓存，空缓存等待事件，并以最长250ms间隔补探测，避免早到或合并通知导致永久等待。通知和探测只表示可尝试读取，不是一次数据交付回执。

不设置后台排空线程，不累积无界队列。上层停止读取后，本地最多保留4KiB，剩余数据留在模组缓存；真实TCP窗口、串口丢段及模组缓存满时行为仍需实物确认。4KiB只指本类数组，不含AtUart固定响应、RX字符串capacity、DMA、临时返回字符串、共享状态、TLS和任务栈，不能冒称总堆上限。

## 忙与超时分开

在AtErrc末尾新增Busy，保持已有枚举顺序；补齐错误消息和NetworkUnavailable映射。只修改ReadMl307TcpCache／SendMl307TcpRaw的发命令前路径：命令／接收／响应锁竞争，或RX仍有待解析字节时返回Busy。检查连接／帧状态仍先拒绝无效状态；登记事务和UART TX之后不存在Busy返回。

同步流只对这类明确尚未登记／发送的Busy退让一个FreeRTOS tick后重试，沿用原包装入口截止时刻。已发命令的超时、错误、格式不符及丢段保留前轮会话锁存，不重发载荷。读写分别一把try-lock，允许一个读者与一个写者并行竞争共享AT通道；同方向第二调用直接拒绝。公平性、持续满载、跨socket调度和高优先级任务影响尚未验证。

所有入口输入时限1..60000ms。正常空缓存等到调用者时限返回Timeout，保留连接；底层已发AT的超时则报错并停止该流／raw会话。包装层向底层传剩余毫秒，各次转换存在向上取整，调度、分配、日志和关闭join不构成严格实时保证。Write的错误可能出现在模块已接收部分或全部载荷之后，任何NetworkError都不能自动映射成“可以安全重发”；本批只有内部Busy分支会自动重试。

## 断线、停止和销毁

空闲对端断线后，已经完成AT事务并存在本地数组的字节可继续交付；本地数据耗尽就返回ServerDisconnected，不再读取模组中尚未确认的尾部，也不返回零字节假装干净EOF。读写中断线、FIFO／帧丢失以及模组MATREADY重启会停止会话，停止后不再交付可能损坏的数据。raw断线通知缺少有效ID也会锁存错误。

**断线后模组缓存能否排空尚无实物证据。HTTP的Connection: close场景可能因此失败，不能据本类宣称HTTP完整接入。** 后续必须补齐断线尾部、TLS close_notify／截断检测以及HTTP长度／分块完成边界，不能把EOF错误直接当下载成功。

RequestStop能唤醒本类的事件等待，已在AtUart中的命令仍最多等待其本次剩余时限。Close不替owner无限等待读写；owner必须停止调用、等待现有调用返回、重试确认关闭，再销毁对象。析构只注销回调和释放本地通知状态，不同步发AT；未确认关闭会记录错误。禁止在UART任务／任何URC回调销毁，禁止调用未结束时销毁；本批没有替未来owner完成这些join与重启流程。

每ID仅对应一个流对象的租约须由未来owner管理，本类不提供ID池。Create拒绝UART任务，I/O／Connect／Close也拒绝在UART任务阻塞；但这些检查不构成完整调用者生命周期证明。事件组和主要对象分配失败有返回，std::function／list／shared_ptr控制块及上游分配失败仍沿库现有策略，未完成全内存故障验收。
