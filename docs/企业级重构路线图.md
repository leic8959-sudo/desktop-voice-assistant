# 企业级重构路线图

## 当前基线

现有 `gateway.py` 同时负责 HTTP 路由、设备协议、会话生命周期、工具调度、供应商降级和应用状态。第一阶段采用模块化单体，保留现有设备协议和离线测试入口；暂不拆分微服务。

## 目标边界

```text
src/assistant_app/
  domain/          领域模型与规则，不依赖框架
  application/     用例编排与事务边界
  adapters/        设备、LLM、邮件、家居和搜索适配器
  infrastructure/  配置、日志、数据库、密钥提供方
  api/             HTTP/WebSocket 路由与 DTO
```

`gateway.py` 在迁移完成前继续作为兼容启动入口，只负责组装应用和启动生命周期。每次迁移保持旧协议路径可用，并提供离线回归命令。

## 阶段顺序

1. 清理发布边界：凭据、运行时状态、证据产物和第三方构建目录。
2. 抽取配置与密钥提供方，禁止业务模块直接读取环境变量或本地密钥文件。
3. 抽取认证、审计和统一错误模型。
4. 抽取设备、LLM、Gmail、Home Assistant 和搜索端口。
5. 将 HTTP/WS 路由迁移到 `api/`，保留兼容入口。
6. 增加 Docker、CI、数据库迁移和多用户权限模型后，再评估多实例部署。

当前已落地的运行时保护包括严格 Bearer 格式、安全响应头、单实例有界速率限制和 API 审计日志。速率限制按来源地址计数，仅适合作为单机保护，不能替代生产网关或共享限流存储。

## 发布门槛

在完成 TLS、短期凭据、角色权限、审计、限流、数据备份恢复和真实设备回归前，不宣称支持生产公网部署。
