# Magiclick 2.4／星智 0.85 NV3023 路径构建

本批推进已有源码入口 `magiclick-2p4`、`nologo-xingzhi-cube-0.85tft-wifi`，用SDK公共DCS绘图操作和板级复位／初始化回调保留NV3023行为，移除这两板的外部NV3023依赖。硬件型号仍记录NV3023，不将SDK工厂函数名作为屏控型号。没有合并各板不同初始化和音频。

## 固定来源与两套初始化

组件registry 78/esp_lcd_nv3023 1.0.1指向MakerM0仓库固定提交 `15dae9531b4fc031bcc12dea1ddfe02517ca7711`。只读取得非截断tree，驱动source／header／manifest／license按Git blob核对，分别保存完整命令与SHA256；没有下载组件二进制或安装组件。

默认25条命令转为 `main/nv3023_default_commands.h`，包含原两个16字节gamma负载、COLMOD05、末尾SLPOUT200ms／DISPON10ms／RAMWR。保留源版权、MakerM0修改来源和Apache-2.0许可全文。星智已有54条专用表保持原文，COLMOD65、拆分gamma寄存器写入、SLPOUT120ms／DISPON10ms不同，不能复用默认表替代。

| 路径 | 保留行为／明确变更 |
| --- | --- |
| reset | 原activeLOW硬件GPIO低10ms、高120ms，或软件01后120ms；新增检查GPIO和IO错误，避免原驱动吞错 |
| init | 原前导SLPOUT100ms、BGR08、COLMOD55，然后发送各自表并保留每项延时和零tick让出；不用SDK默认ST7789 init／RAMCTRL |
| format | 按原表分别写COLMOD05／65；像素帧缓冲仍16位，沿原工厂逻辑，不擅自改成其它像素长度 |
| draw | 相同的gap、0x2a／0x2b末坐标减一、0x2c和16位字节数；SDK传播原NV3023忽略的窗口／像素传输错误 |
| mirror／swap | 表内无MADCTL覆盖，SDK BGR缓存匹配原构造；两板仍仅Y镜像、无换轴、gap0，不反色 |
| optional API | 原无sleep／brightness回调，继续禁用，背光由原GPIO13 PWM控制 |

复用公共 `esp_lcd_panel_t` 接口，没有访问SDK私有状态或修改驱动源码。静态检查表载荷边界、MADCTL和预期格式命令；只覆盖已有owner的一次板级启动，不新增外部任意改格式／镜像后通用reinit能力。真实COLMOD05／65与16位像素流的显示效果仍待各板验收。

## 独立板级差异

Magiclick2.4仍是ES8311输入输出24kHz、PA4、说话21／音量47和0、原LED39电源状态；原PCB2.4的PA无效与2.4A差异继续记录，不将软件PA动作当作两种PCB均可控。

星智0.85仍是独立数字I2S输入16kHz／输出24kHz、BOOT0、RTC21高及GPIO45低；SPI MOSI10／CLK9／DC8／CS14／RST18，不套Magiclick的引脚或ES8311。两板均沿各自固定发布的16MB／Octal候选配置，不当作实物容量测量。

除共享显示文件和CMake的NV3023分支、两板manifest、profile实现说明外，其余main保持原文。音频、完整自定义唤醒、AEC、自然插话与媒体人工决策、绑定、NVS、配网和双OTA源码不改。

`tools/build_firmware.ps1`的固件导出代码补充这两块板的 `third_party/nv3023` 许可文件复制；原星智专用MIT命令表通知继续单独附带。仅新增两行，保留导出脚本内其它既有内容。本轮没有启动Docker或执行镜像构建／产物导出，不能把此源码修改称作已验证的导出产物。
