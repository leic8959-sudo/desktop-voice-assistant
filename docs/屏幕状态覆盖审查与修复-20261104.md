# 屏幕状态覆盖审查与修复

日期：2026-11-04（Asia/Shanghai）。牛牛反馈“很多状态都没有对应的屏幕显示”，并要求直接对照现有功能检查。本轮只改源码和文档，没有重启在线网关、构建或发布新 OTA、改绑定、读凭据或调用真实账号。上一轮已发布0.3.8；本轮源码版本为0.3.9，尚未构建 / 安装。

## 已确认的原因

1. 0.3.8只在部分任务、家居和专用卡片入口手动推送。邮件工具、记忆、通用连接器、工作流预览、配置与授权等没有统一的执行反馈入口，错误也常只有后台响应或语音提示。
2. 固件把 Listening 也当作阻挡卡片的状态；语音回答结束后通常进入 Listening，结果仍可能一直看不到。
3. 普通卡片收到就开始计算8秒 TTL，长语音结束前已过期，卡片没有真正显示就消失。
4. 同一卡片在语音期间更新“处理中→完成”后，没有记录重绘标记；恢复显示可能仍是旧文案。
5. 连续工具共用一个普通卡片槽，后续“处理中”覆盖先前结果；未知 custom 状态又默认为 Idle，容易造成“什么都没有发生”的观感。
6. 基础状态很多只给标题，缺少默认说明。OTA原来只打日志，无下载 / 校验 / 重启前屏幕反馈。

## 统一覆盖矩阵

以下为源码映射覆盖，不是实机全部通过。静态比对当前已注册23个语音工具，没有缺失映射；通用 invoke_connector 按注册 manifest/action 的说明和读写属性动态覆盖当前29项动作，invoke_workflow覆盖4个工作流，不把后台配置项误当业务动作。

| 能力 | 进行中 / 等待 | 结果 / 失败与边界 |
| --- | --- | --- |
| 语音待机、连接、聆听、理解、执行、播放 | 每种基础状态有默认中文说明；执行名由内部工具ID转成中文；模型连接与降级尝试有连接提示 | 停止回答有明确提示；错误在连接正常时显示8秒后返回空闲，避免永远盖住结果。唤醒未验证时仍按原门控拒绝工具，不为了反馈绕过唤醒 |
| 倒计时 / 番茄钟 | 创建、暂停、继续、查询 | 保留专用计时卡；取消补结束反馈；失败、冲突、过期版本有未完成反馈，不假称成功 |
| 待办与提醒 | 创建、查询、完成、取消、稍后提醒 | 显示保存 / 完成 / 取消 / 稍后5分钟；列表说明本次条数，空结果不说“肯定不存在”。提醒投递租约、屏幕知道了与任务完成的区别保留 |
| 记忆 | 保存、查询、更新、删除 | 给操作结果和本次返回条数；不复制记忆值或原始错误到屏幕 |
| 家居设备 | 查询列表、读取状态、控制、手动刷新、授权修改 | 区分平台观察到目标状态、指令提交但未确认、权限阻挡、执行失败或待核实。控制异常不自动重试；平台反馈不冒充物理反馈 |
| Gmail | 搜索、读取、草稿列表 / 内容、创建 / 更新草稿、发送预览、确认发送 | 草稿成功明确“未发送”；预览等待后台确认；发送只接受服务端 sent/already_sent 结果。屏幕不显示邮箱地址、收件人、邮件正文、主题或发送凭证 |
| Gmail OAuth / 配置 | 发起授权、保存、状态刷新、断开 | 配置已保存与授权分开；授权入口生成不代表已授权；已有本地令牌不代表当前有效。Google回调沿用既有代码，需回后台刷新状态才更新屏幕授权摘要 |
| 高德天气 / 地点 / 路线 | 注册动作及专用天气 / 路线入口 | 天气显示预报简要数据；地点返回本次条数；无路线给空结果卡片。专用路线箭头与“非实时导航”边界保留，无定位能力不宣称实时导航 |
| 联网搜索 | 正在检索 | 只在 ok=true且search_confirmed=true时说明获得本次检索确认；未确认、失败、超时不能因模型返回文字就标成功，不展示外部正文 |
| Google / Microsoft 日历、Microsoft Mail、Notion、GitHub、Todoist | 所有已注册动作由manifest生成操作标题 | 读取给结果 / 空结果，写入返回只说明执行结果已返回，保留提供商核实边界；无确认、权限阻挡、参数错误、网络未知各有提示，不展示业务正文 |
| Slack / 飞书 | 真实已授权发送动作有执行反馈；Webhook配置保存有反馈 | 不新增测试发送；只读检查不支持仍返回失败提示；没有凭据或服务异常不伪造成功 |
| 连接检查 | 正在执行只读检查 | 仅 status=verified 显示本次验证通过；不代表全权限 / 长期健康。失败提示检查配置与网络，不泄漏上游访问地址或密钥 |
| 模型 / 音色 / 人格 / 搜索设置 | 保存中 | 成功说明生效时间；配置保存必须有 saved=true才说明已保存，缺确认则“结果待核实”。环境管理 / 校验 / 存储错误不会显示成功 |
| 工作流 | 参数预览、等待确认、执行中 | 未拿到服务端确认凭证不能显示“可确认”；重复执行进行中继续显示等待；失败、结果未知、返回结果分开。通用HTTP200不代表外部业务完成 |
| OTA | 准备下载、每10%进度、校验、切启动分区、即将重启 | 异常显示升级未完成；升级期间普通语音状态不覆盖OTA提示。此为下一固件源码，不能回溯声称已发布0.3.8具备OTA进度屏显 |
| 未识别协议状态 | 显示提醒并记录不支持状态 | 不再静默伪装成Idle；不扩大动作执行权限 |

有意不反复上屏：后台状态 / 本地计时轮询、审计、连接器元数据列表、设置列表、设备列表、固件下载请求。否则每5秒读取就会抢占正在看的卡片。家居仅显式 refresh=true 时提供列表读取反馈；设备配对、解绑、凭据管理仍走原专用流程，不新增操作入口。

## 调度与安全边界

- 普通信息从**首次进入可见绘制路径**才开始计算 TTL。语音期间收到结果会等待显示；未显示超过120秒标过期，避免陈旧结果无限滞留。
- Listening 待命允许显示卡片；Speaking / Thinking / Executing / Error / Updating / 配对遮罩仍优先。语音回答结束后的Listening状态不会永久挡住结果。画面显示回执仍不等同真人已看到。
- 卡片增加 dirty 标记：同ID的结果变化即使发生在隐藏期间，也会在恢复时重绘，不保留“处理中”旧文案。
- 一个普通信息槽再加3个固定暂存结果槽；终态优先于后续“处理中”。满时丢弃最旧待显结果并给 expired 回执；不宣称每个并发事件都永久保留。后台审计仍是核查入口。
- 专用天气 / 日程 / 家居 / 计时卡保留，统一处理中卡完成后仅按自己的card_id清理，不能误删另一操作结果；未知 / 错误仍走统一反馈。
- 统一反馈只取白名单状态、计数、天气等必要字段，不复制错误正文、用户邮件 / 笔记 / 记忆内容、OAuth地址 / state、确认凭证和秘密。动态操作标题来自服务端manifest，不回显任意工具参数。
- 语音工具先经过原唤醒校验，后台API先经过原管理员 / 同源认证，再发送反馈；反馈失败记录堆栈但不改变已完成的业务结果。未给外部写入增加自动重试，未改确认凭证 / 幂等 / 配置保存逻辑。
