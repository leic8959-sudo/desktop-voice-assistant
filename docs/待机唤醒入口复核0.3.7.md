# 待机唤醒入口复核 0.3.7

牛牛反馈“任意对话都会唤醒”。此前只核查到30秒超时回 `idle`，不足以证明下一次会话必须经过完整唤醒词，已纠正该结论。

## 实际发现

现有设备本地模型报告命中后发送 `listen start`；桥接收到该事件便创建会话，没有验证首次语音是否包含唤醒词。日志中曾出现新会话第一条转写为“你就这样”，之后正常生成回答。由于旧日志缺少启动来源，不能仅凭这条记录断言一定是本地模型误识别。

另外，旧固件在云端握手期间继续滚动2秒音频缓存，唤醒词可能被后续音频覆盖。直接检查首次转写而不修缓存，会误拒绝真正的唤醒。

## 当前修改

- 非物理按键的设备新会话，先检查识别结果去除标点、空白后是否以完整“你好小燕子”开头；支持前缀被拆为“你好”与“小燕子”的识别分段。没有唤醒词的普通首句被拒绝，并静默回待机。
- 确认前不向设备转发回答音频，不执行记忆、任务、家居、邮箱等工具，也不发送思考/执行/播报状态；物理按键单独允许。
- 首次验证最多等待10秒，缓存上限128事件、256KB。缺少识别结果、超时或超限均结束候选会话。
- 正常唤醒后保留既有30秒连续接话。超过无有效活动时限回待机，下一次仍需完整唤醒词。当前没有改动空闲时长、唤醒模型、阈值、增益或播放期打断策略。
- 固件冻结触发前4秒唤醒前缀，并保存最多2秒握手后续音频，按前缀再后续的顺序上传；单消息最多32000字节，遵守桥接64KB限制。全部为有界内存，不新增持续录音文件。
- 增加设备 `listen detect/wake_id` 和桥接 `native_listen_start/wake_phrase_verified/wake_phrase_rejected` 日志，后续可以区分本地检测、手动入口与识别复核失败。

语音识别可能漏字或错字；严格复核会选择拒绝候选而非猜测用户意图。因此保留完整唤醒音频是这次修复的必要部分，仍须开机后验证真人和实际设备收音。
