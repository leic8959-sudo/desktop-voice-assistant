## 暂停范围与恢复边界

只把明确未确认合同作为触发：`status=unknown/unconfirmed`、既有 `completed.result` 包装中的同类状态，以及 `request_accepted=true` 且 `target_observed=false`。不把所有 ok=false、local blocked、conflict 或 unavailable 都当作未知。语义控制已有部分步骤可能发生的 unconfirmed 回执也暂停后续步骤。

结果解析仅对字符串 status 做已知状态匹配，列表等非标准字段不会触发类型异常；没有据此推断动作未发生，也不把它们自动归入新的暂停状态。

`VoiceSession` 使用独立的已接受输入代数、暂停标志和本轮最终说明请求标志。用户输入先经过原唤醒、自回声和尾音检查，并等媒体待交接请求清理结束，再在同一无等待区段替换控制上下文、递增代数和解除暂停。VAD、普通工具响应、用量或 response.create 都不能解除暂停。

旧工具执行前捕获输入代数；等待后若用户已开启新请求，不暂停新输入、不清新输入的待交接请求、不回填旧结果，也不请求旧回答。等待语义控制锁的旧任务在拿锁时立即检查代数、控制回合和关闭状态，避免读取或修改新请求的计划。

暂停只取消该 VoiceSession 的电脑/实体音乐待交接请求，不清全局队列、不停止既有播放、不补偿已经发生的动作。固定本地提示说明结果待核实。`execute_tool`、Realtime `process_tools` 和语义控制补执行入口都受主机暂停检查，避免仅在模型循环里限制却留下宿主入口。

## 两种对话通道

Chat 第一次未知后给同批未执行工具补固定暂停结果，保持 assistant/tool 输出对应；再只请求一次没有 tools、tool_choice=none 的最终说明。流式失败降级非流式仍保持无工具。供应商即使继续返回工具，也不再执行，而是终止本轮；不按新 ID 自动重试。

Realtime 每个已接受输入最多主动请求一次无工具最终说明。后续忽略限制的工具调用只收到暂停结果，不产生无限 response.create。每次请求上的 tools/tool_choice/instructions 约束尚未用真实供应商验证；主机执行拒绝和固定本地提示才是确定保证，云端忽略或拒绝字段不能重新启用工具。

Chat 正常生成的最终说明仍按回答完成正常排空音频、发送最终 stop，同时保持 `response_completed=false`，不触发 watchdog 媒体交接。供应商仍请求工具或说明失败时清理本地播放，保留待核查提示。取消继续传播并沿用原 TTS/音频清理，不重放或伪造动作成功。
