## 修改

1. gateway只对有限首句唯一已绑定commit的最终空转写/不完整转写立即拒绝；空结果记empty_transcript。旧流式转写仍允许跨最终片段拼接完整口令，不放宽门禁，不重试上传旧前缀。
2. 有限首句门禁缓冲中的speech_started/stopped继续执行输入授权、回合取消和时间语义，省略已经过期的listening/thinking显示回放。缓存response.created省略thinking，audio.delta照常进入speaking；普通模型回答不变。
3. assets/wake_ack/ack.pcm删除前3840字节纯零，其余字节完全相同，1200ms变1120ms；manifest更新sha256与trimmed_leading_silence_ms。**现网每个新会话会读取此资产，所以素材已经可在新会话生效；网关Python源码修改与固件仍须父代理受控加载。**
4. control_protocol.cpp由原采音任务单一owner在本地命中时提前切WiFi为WIFI_PS_NONE，手动收音、语音、媒体、提示音、OTA活动由既有循环维护。空闲/断线后恢复首次切换前保存的原模式；不新建任务，不在稳定状态重复调用，不因切换失败中断对话。API失败只记录错误，下一次活动状态转换才会再尝试；恢复API失败不能声称省电已恢复。
5. 有限边界附带device_detect_to_ready_ms、device_ready_to_first_upload_ms、device_detect_to_end_ms。网关只记录整数0–60000的白名单项。audio_stats可选增加first_write_after_tts_ms、first_write_after_receive_ms、first_display_ms，起点由WS回调原子记录，播放任务先取快照、写完成后检查generation/tts起点。**write完成仍不是扬声器声学起音。**

WiFi切换收益需现场比较，不能用本机函数验证代替。设备VAD状态仍是最新AFE结果、PCM来自有界ring，二者未逐帧绑定是保留风险；本次没有大改音频队列、提高增益或缩短静音来掩盖该风险。
