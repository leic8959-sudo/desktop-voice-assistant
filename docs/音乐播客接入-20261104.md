## 使用方式

- “播放雨声半小时”对应 `media_play({source: "rain", minutes: 30})`。雨声是本机合成的带限噪音和水滴，白噪音 ID 为 `white_noise`，均无网络音源。噪音短片段按计时循环，音乐/播客单次播放，到音轨结尾或计时到期停止。
- 音乐、播客使用已有自备文件上传：WAV/MP3/OGG/FLAC/M4A，上传时选择分类并填写可读名称。原始单项 10MiB、30 分钟，32 项、转换后总容量 200MiB；隔离 PyAV 转换、SHA256 绑定与原有管理员确认均保留。没有接入未经授权的第三方曲库；自备内容的权利由上传者确认。
- “继续上次的播客”对应新增 `media_resume_podcast({})`，只恢复标记为播客并实际开始过播放的音源，使用 Windows 音轨报告的毫秒位置；没有书签或实际播完会明确拒绝。定时停止不代表播完；定时预算用尽后再次续播恢复原位置并重新使用原计时预算。
- 控制台增加名称、分类、当前实际位置、上次播客位置、待语音结束倒计时与续播按钮。页面仍使用预览与一次性确认；语音只在父入口验证本轮明确指令后可登记低风险播放。

## 播放与持久化

保留原上传和转换链，只将无法读取位置的 winsound 播放层改为 Windows 自带 MCI 的固定 `waveaudio` 本地 WAV 命令。没有 shell 或任意命令入口。音源路径仍限制在媒体目录或本机生成临时文件。开始必须读取到 MCI 的 `playing` 模式，才能报告 `playing`；这表示 Windows 音轨状态，并非扬声器物理听音确认。

`runtime/desktop-media-state.json` 是有界覆盖状态文件：最多 32 份名称/分类、8 项队列、一个当前音轨和一份上次播客书签。读取限 64KiB，恢复时校验类型、来源、位置、计时及数量。播放期间约每 5 秒读取实际位置并以临时文件、fsync、原子替换保存；暂停、停止和正常关闭也保存。重启只恢复暂停状态，不自动发声；异常退出位置可能回退约一个保存周期。磁盘慢或系统调度延迟时不能保证严格 5 秒上界。

取消保存或 MCI 请求后等待真实工作线程退出，避免释放媒体锁后并发写临时文件或遗留未登记播放。上传元数据保存失败会回滚内存登记，并清理刚转存的文件。噪音使用 8 秒本机片段，轮询重播可能有短暂循环间隙，听感未验收。

## 父语音链路接口合同

服务构造后提供 `runtime.media_service`。

- `await before_voice_session()`：在父持有 `runtime.voice_lock`、启动任何语音/主动播报前调用。服务只获取自己的媒体锁，暂停音轨、保存实际位置，并保护会话登记前 2 秒空隙，不反向获取语音锁。
- `await invoke(name, args, subject="voice", voice_authorized=True, voice_session=session)`：授权值仅由父核验本轮用户原话后传入，不能来自模型工具参数。精确允许集合：`media_play`、`media_queue`、`media_pause`、`media_resume`、`media_resume_podcast`、`media_stop`、`media_clear_queue`。上传、系统媒体键、应用、锁屏、OAuth 仍走管理员确认。
- 播放/续播返回 `scheduled` 表示尚未开始。绑定一个 session 的一个请求，最多等 120 秒；新播放、暂停、停止替换或取消旧请求。空队列的语音加入请求同样等待当前回答结束。
- `await voice_response_finished(session) -> bool`：父在最终回答完成、TTS 与工具全部清空后调用；返回 True 表示本轮有待播放请求，仅标 ready。父正常结束本轮会话；服务 worker 必须再等 `session.closed` 且没有其他活跃语音或主动播报才启动媒体，绝不忽略当前活会话。
- `await cancel_voice_request(session)`：父收到本轮新的用户文本时取消旧请求，避免用户改变意图后仍播放旧内容。

语音唤醒后暂停的媒体不会擅自恢复，需用户明确继续。状态提供 `media.pending`、实际位置、当前音轨、队列和错误，超时会取消并显示原因。父对 gateway、assistant_runtime、proactive_speech、chat_pipeline 的接线需独立审阅，不能用本模块说明推断已完成真实语音验收。
