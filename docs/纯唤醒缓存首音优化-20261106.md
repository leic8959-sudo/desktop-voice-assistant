## 实现与范围

- `gateway.py`：原生 PCM、非手动、需要完整唤醒验证的 qwen_realtime 会话，仅在缓存匹配当前模型/音色/格式/哈希时使用优化。首轮 server_vad 保留识别与断句，设置 create_response=false，握手必须明确回执 false；完整口令确认后恢复 true。纯口令注入一次本地缓存响应，附带指令主动请求一次模型响应。后续连续对话沿用原流程。缓存缺失/损坏或音色/模型改变时使用旧流程；不自动生成新缓存、不增加热路径云请求。浏览器、手动、Chat/DeepSeek 不变。
- `src/assistant_app/application/wake_ack.py`：单个缓存，PCM16/24kHz/mono，最大三秒；每会话最多读取一个有界文件。没有新增依赖、后台任务、数据库结构或 Redis。多实例各自读取同一发布资产，无共享写入。
- 音频复用现有播放队列、代数隔离、唯一播放 ID、取消与停止流程。本地应答被取消时不调用云端 response.cancel。后续人声已进入门禁缓冲时不抢播问候。仅能对已返回的转写判断纯唤醒；云端尚未转写的后续声音不能提前预测，后续 VAD 到达后仍沿原有中断流程处理。
- `assistant_runtime.py`：关联设备 wake_id 和网关收到检测事件的单调时间。首包日志新增 wake_to_first_audio_ms/source；该值包括建连和识别，仍不包含本地检测前的时间、设备缓冲与真实扬声器起音。
- `tools/prepare_wake_ack.py`：隔离云端生成固定两个字，严格校验转写后写入单个缓存。当前 Katerina / qwen3.8-omni-flash-realtime，音频长 1200ms，SHA256 `3875c4d1a77cbe094446e9bfd12a3083b0faac33948c021caa35d164858b0305`。准备过程中两次候选未通过文本/PCM校验，未写入缓存；最终显式要求逐字朗读后匹配。所有请求只涉及固定文本或合成音频，没有采集麦克风、读取私人记忆或连接设备执行工具。
