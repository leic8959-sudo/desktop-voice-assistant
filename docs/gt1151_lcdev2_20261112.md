# LCD EV Board 2 的 GT1151 接入与整板构建

SDK链接后续：本页这份镜像已单独核对ELF／镜像入口、实际启动函数表和显式链接输入，未发现对象引用所列强制UND；不能单凭这些名称判定缺少启动代码。实机启动仍未验收。见[只读审阅](sdk_forced_und_audit_20261113.md)。

本批推进已有 `espressif-esp-s3-lcd-ev-board-2`。此前因缺GT1151 1.1.0~1组件未暂存／编译；本次将组件构造时的固定产品读取放到已有板级IO，保留既有报告校验／清除、RGB与音频路径，随后独立构建Board 2和Board 1.5回归。两板并非同一屏幕／采样率，结果分别登记。

小智固定提交仍为 `49b4380b3faa0ceadd28a3e78aaf0f311c46c57e`。本轮重新核对既有27项来源SHA256，并用gh api取得 `espressif/esp-bsp@6f82fd66a099cfd388cf9376ca1c5d6dcc98381e` 的GT1151源与公开头，按Git blob核验，确认与原归档逐字一致。记录在 `evidence/gt1151-lcdev2-20261112/source-references.json` 和verified-reference.json。未安装或复制整套组件、未修改SDK。

改动限于共享lcd_ev_display中Board 2的初始化、CMake、本板manifest与profile说明；新增原Espressif Apache-2.0全文，导出脚本附带许可但未运行Docker／实际导出。FT分支保留原组件，GT911轮询源码未改。

参考源把产品求和校验称为checksum，但实际判断是“和非零”；它与触摸报告的“和为零”不同。本轮忠实保留既有构造条件，不将其改成推测的算法，也不凭产品格式宣布真实控制器身份。产品校验含义、固件修订及有效寄存器数据仍需实机确认。

报告读取逻辑原文保持，仅更新IO归属注释。它没有解析ready位，正常count0会被清除并当作松手；count0没有完整CRC、多指只取消而不读取全部点。status与payload间变化、长按、报告ready节奏、清除竞争、CRC／ACK故障、真实释放和坐标均未运行验收。不能按相近寄存器地址套GT911轮询，也不能把这次移除依赖称为解决所有触摸协议边界。

Board 1.5回归保留SUB2 GC9503 480×480 RGB16MHz、三线初始化／43条原命令、FT5x06和16kHz双codec；它不替Board 2证明800屏、GT1151或24kHz。其它main、lcd_ev_board功放／扩展器、音频／引脚、显示UI、人工决定、配网绑定和OTA摘要均保持。

原背光限制继续存在：厂家固定背光，不驱动GPIO19（USB D-），无亮度／夜间调光／空闲熄屏，显式亮度请求返回不支持。USB host／UVC、状态LED4、SD、睡眠、电池和模组自动识别未实现。只有微雪1.8实物；板卡引脚修订／实际FlashPSRAM、RGB稳定性／颜色、GT1151所有上述行为、PA／音频时钟／采样／增益／静音、AEC／唤醒／自然插话、媒体、绑定／提醒／同板OTA均未实机验收。
