# 项目与日常事务管家首轮交付

本轮是源码候选，尚未应用真实数据库迁移、重载网关或刷固件。真实语音理解、明日定时到达和设备屏幕阅读仍须在上线后验收；离线通过不代表已上线。

## 本轮闭环

- `create_project_tasks` 按用户给出的项目名与事项，一次原子保存1至20项。事项保存在原 `tasks` 表，提醒、完成、取消、改名和改期继续使用已有工具。普通无项目待办不要求迁移。
- `list_tasks(project="小燕子")` 精确读取当前设备的项目任务，可与状态、日期和游标分页组合。返回的 `metadata.position` 是项目内序号，改期引起的行顺序变化不会改变“第二项”的身份。继续追加项目任务会取得新序号，归档后也不复用。
- `update_task_progress` 保存该事项最新进度摘要，最多1000字，可用空字符串清除；只更新未完成项目事项，不把记录进度当成执行、完成或改期。只保存一条最新摘要，不增加进度历史平台。
- 提醒沿用原租约和确认流程，设备通知标题包含项目、原序号、事项和最新进度摘要，按固件容量限制到180个UTF-8字节。完整进度仍从任务查询读取；本轮没有给既有屏幕提醒新增自动语音播报。
- Realtime 和 Chat 均由服务端生成批量创建的工具幂等身份，不接受模型自定身份控制去重。原有两句答复、人格、自动记忆和授权规则未改。

## 可复现验收

1. 用户给出“小燕子”项目的三项真实内容和明确时间，例如“明天15点提醒”。缺少事项内容或“明天下午/周末”的具体时刻时先询问，不编造计划或提醒钟点。
2. 调用 `create_project_tasks`，核对返回的三个task_id及position=1/2/3。用户说“第二项完成”时先读取该项目，按position=2找到真实ID后调用原 `complete_task`。
3. 用户报告第一项实际进度时，先读取updated_at，再调用 `update_task_progress`。用户要求“第三项推到周末”时先明确日期和时间，再用原 `reschedule_task`，保留原task_id和position=3。
4. 到期投递只包含仍未完成、未取消且租约有效的事项；通知带当时保存的最新进度。重放创建请求不会复建三项，也不会覆盖进度、完成或改期。
5. 取消第三项后不再领取它的到期租约。任务已显示提醒仍不等于已完成，已确认提醒的事项更新进度也不会重新触发同一次提醒。

## 并发、租约与保留边界

项目序号计数与整批创建置于同一个SQLite写事务中；任何一项非法或超过4096字节metadata限制，整批回滚，序号不前移。项目、序号、进度和内部请求指纹为受控保留字段，普通 `create_task` 不接受它们。

进度写入使用真实updated_at比较。活跃投递租约期间拒绝更新，避免旧通知已开始发送时替换内容；租约过期后允许更新，清除旧token并推进revision，后续重新领取会携带新进度，旧缓存无法通过租约复核。已完成或已取消事项拒绝修改进度。

批次回执只保存请求哈希与180天到期时间；创建新批次时按设备、过期时间索引最多清理100条。回执清理后，仍存任务的确定性子任务键及初始请求指纹继续阻止重复创建。若回执仍存但子任务已按既有90天终态策略归档，重放明确拒绝，不补建缺项。回执与所有子任务均已过保留期并清除后，旧请求键不再保证去重；调用方不可把过期调用当成新任务重发。项目计数是持久业务状态，保留以避免序号复用。

## 显式离线迁移

迁移文件为 `tools/migrations/project_tasks_20261107.sql`，由管理员在维护窗口对**确认属于当前网关的SQLite数据库**执行；本轮没有执行。先停网关、创建包含已提交WAL内容的完整SQLite快照，再通过SQLite工具执行该SQL，成功后才能重新加载候选代码。不要仅复制数据库主文件作为运行中数据库的备份。

确认网关及其他数据库写入进程均已停止后，在PowerShell填写真实数据库路径并执行以下命令。备份使用SQLite backup API，得到自包含的单文件快照；路径不存在或备份已存在时停止，不覆盖旧备份。

```powershell
$projectDatabase = '请替换为已确认的数据库绝对路径'
$projectBackup = "$projectDatabase.project-steward-before-20261107"
$projectMigration = 'I:\new find\desktop_voice_assistant\tools\migrations\project_tasks_20261107.sql'
python -c "import pathlib,sqlite3,sys; source=pathlib.Path(sys.argv[1]).resolve(); target=pathlib.Path(sys.argv[2]); assert source.is_file(), '数据库不存在'; assert not target.exists(), '备份已存在'; reader=sqlite3.connect(source.as_uri()+'?mode=ro',uri=True); writer=sqlite3.connect(str(target)); reader.backup(writer); writer.close(); reader.close()" $projectDatabase $projectBackup
if ($LASTEXITCODE -ne 0) { throw '备份失败，停止迁移' }
python -c "import pathlib,sqlite3,sys; database=pathlib.Path(sys.argv[1]).resolve(); connection=sqlite3.connect(database.as_uri()+'?mode=rw',uri=True,timeout=5); connection.executescript(pathlib.Path(sys.argv[2]).read_text(encoding='utf-8')); connection.close()" $projectDatabase $projectMigration
if ($LASTEXITCODE -ne 0) { throw '迁移未确认成功，保持网关停止并核对数据库' }
```

恢复时继续保持全部数据库写入进程停止，先把迁移后的库用上述backup命令备份到另一个新路径留证，再使用下方命令把迁移前快照恢复到明确的原数据库。然后恢复本轮源码编辑前的相应代码版本，再启动原来的网关命令；源文件原始副本位置见文末。恢复数据库会撤销迁移后发生的项目及普通待办写入，因此上线后产生了新记录时，应先导出并人工决定如何保留，不能直接恢复旧快照。

```powershell
python -c "import pathlib,sqlite3,sys; source=pathlib.Path(sys.argv[1]).resolve(); target=pathlib.Path(sys.argv[2]).resolve(); reader=sqlite3.connect(source.as_uri()+'?mode=ro',uri=True); writer=sqlite3.connect(target.as_uri()+'?mode=rw',uri=True,timeout=5); reader.backup(writer); writer.close(); reader.close()" $projectBackup $projectDatabase
if ($LASTEXITCODE -ne 0) { throw '恢复未成功，保持网关停止' }
```

迁移只增加项目计数表、批次回执表和表达式索引，不改变原任务内容；重复执行保持已有序号与回执。迁移前需检查历史metadata是否曾手工使用project/position/progress/project_request等字段，避免把旧的自由metadata误认为受控项目；若有冲突先人工处理，不自动猜测迁移。元数据必须为原应用写入的合法JSON。

应用启动不会加载此SQL，也不会自动创建项目表或索引。迁移缺失时项目创建、查询和进度写入明确返回 `project_storage_unavailable`，本次不写项目记录；普通待办仍可使用。

项目查询复用现有分页与排序：无状态与有状态各有匹配表达式索引；日期查询显式约束 `(due_at IS NULL)=0`，使提醒时间范围直接进入索引。定时和未定时段最多各执行一次有界SQL，深页直接按due_at/task_id或NULL段task_id定位，日期起点与游标只保留更严格的下界，避免扫描已翻过的数据。列表顺序仍按原提醒时间排列，展示或理解项目第几项必须使用position，不能用当前页行号。

本轮没有增加控制台项目专页、云端项目同步、自动执行项目、个人事实自动记忆或新的定时调度器。
