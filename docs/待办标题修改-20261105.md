# 待办标题修改（2026-11-05）

## 合同与提醒边界

新增 `rename_task(task_id, expected_updated_at, title)`，仅允许 status=pending 且未定时、或 due_at 严格晚于锁内当前时刻的任务。额外拒绝 reminder_state=leased，即使系统时钟回退让 due_at 看似仍在未来，也不修改正在投递的通知版本。已完成、已取消、已到期、正在投递或 CAS 不匹配均为已知冲突（HTTP 409）；非法标题或参数为 400，记录不存在或属于其他设备为 404。

在既有 BEGIN IMMEDIATE 写事务内读取真实 device_id/task_id 和当前版本，再读取 UTC now、检查状态及时间，只 UPDATE title、updated_at。标题沿用创建待办的 trim 后 1～200 个 Unicode 字符；版本复用 `_next_task_revision` 严格推进，同一时刻或时钟回退仍递增。fresh CAS 保存相同标题也推进版本，旧 CAS 重放冲突，不自动重试。

任务 ID、due_at、metadata 原存储、幂等键、创建/完成/取消字段、reminder_state、lease_token、lease_until 全部保留，不删除重建，不清租约、不重新投递、不抹 ACK。若已 ACK 的任务因时钟回退重新表现为未来且没有 active lease，改标题仍保留 ACK。旧 create_task 幂等语义保持：改名后重放原创建载荷会因标题不符冲突，不再创建一条任务。

rename 先取得锁且仍未到期时，后续到期 claim 使用原 ID 和新标题；claim 先取得锁时，rename 的旧版本或已到期/leased 条件冲突。API 与语音 rename 都不 pop 通知缓存，gateway 原四类清通知工具集合未增加 rename；失败后也不删除已有缓存对象。这样不因改标题使投递中的旧 revision 失效，也不会把旧通知文案假装成新标题重新发送。

## 实现范围与页面行为

本轮改动 8 个生产文件：`assistant_core/store.py`、`assistant_core/tools.py`、`llm_providers.py`、`control_api.py`、`assistant_runtime.py`、`src/assistant_app/application/screen_feedback.py`、`web/app.js`、`web/assistant.html`。没有新增表、DDL、依赖、配置或通用 patch 框架。API 为 POST `/api/tasks/{task_id}/rename`，请求严格只有 title 和 expected_updated_at；响应沿用清洗后的 task_item，不暴露租约令牌、设备身份或幂等键。

Realtime 和 Chat 复用同一个工具 schema 和分派，语音先查真实任务及版本；目标或新标题含糊先问清，不猜 ID、不删建、不自动重试。屏幕映射新增改标题动作，只有实际 pending/title/version 回执才显示“标题已保存，提醒时间不变；待办仍未完成”，错误或不完整成功响应为 unknown，不把改标题说成完成或提醒已交付。

页面新增独立 `task_rename` 能力，仅严格 true 才显示按钮；缺字段、false 或字符串 true 都隐藏。原 taskEditor 复用为 rename/add/reschedule 三模式，仍只有一个编辑槽和一个 taskWrite，沿用 unknown 写锁、409 刷新、身份代际、日期条件及游标分页。移除改名能力会关闭改名草稿，不关闭仍受支持的时间修改；刷新、换页、日期或另一任务编辑的确认文案泛化为“任务修改”。改名冲突提示“待办已发生变化”，原两种时间操作仍提示“提醒已发生变化”。

改名成功响应必须与提交的 id、pending、trim 后 title、原 due_at、原 reminder_state 一致，并提供有效、非空且不同于旧值的 updated_at，才确认保存；错误 id/title/time/state/version/status 的 HTTP 200 同样进入结果待核实，5xx 或超时也锁住后续写入直到刷新核对，不自动补发。存储负责微秒版本严格递增，UI 不用毫秒精度的 Date.parse 大小比较来误拒同毫秒的新微秒版本。

标题计数与 Python/schema 保持 Unicode 字符口径：输入 maxLength=400 容纳 200 个最长 UTF-16 编码字符，提交用 Array.from(title).length<=200 检查。200 中文和 200 emoji 均可保存；201 中文及手工 submit 绕过原生长度限制的 201 emoji 均不得发出 POST。HTML 仅将 app.js 缓存参数改为 task-rename，panel.css 文件和缓存参数都未修改。
