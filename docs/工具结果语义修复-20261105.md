## 当前实现与边界

复用 `application/errors.py` 的 `ApplicationError` 增加固定构造消息的本地错误类型。仅将已证实发生在音乐动作前的当前用户意图守卫改成 `LocalToolRejectedError`，仍兼容 PermissionError，不修改正则、授权范围或音乐 NLU。

本地个人事务工具调用存储的边界识别记录冲突、租约冲突和缺失记录，包装为可信本地错误；新类分别仍继承原 IdempotencyConflict、LeaseConflict、NotFoundError，保留直接调用者异常合同和 `raise from` 完整来源。没有在工具总出口根据所有同名异常一概断言未执行。

两条对话通道共用固定映射：本地门禁为 `blocked`，本地版本/租约冲突为 `conflict`，本地记录缺失为 `not_found`，其他异常为 `unknown`。结果含稳定 code、`ok=false`、`retryable=false` 和固定脱敏消息。普通外部 PermissionError、ValueError 甚至同名存储领域异常，都不证明动作未执行；超时也仍待核实。MusicAssistantError 原有安全 unavailable 合同保持，取消不被包装或缓存，不自动重试工具。

两入口解析 JSON 或检查参数非对象的精确边界另返回统一 `invalid_arguments`、`invalid_tool_arguments` 和“工具参数无效，请补齐或修正后再请求”，不会调用工具。不将服务内部 ValueError 泛化为参数未执行；显式空串/null 也一致拒绝，只有缺失 arguments 保留原默认对象合同。Chat 的解析故障现在保留完整堆栈。

屏幕保持原 blocked/error/unknown 枚举，不新增 conflict 设备状态。本地冲突用 error 和“记录已变化，请重新查询核对”详情；明确本地门禁或 HTTP403 用 blocked，但不承诺其他步骤已撤销。写操作抛出普通外部异常显示 unknown。

Realtime 已有同 call_id 结果缓存仍有效，回归验证重复交付不重执行。Chat 本轮没有增加裸 call_id 会话缓存：供应商可能跨响应复用 ID，正确去重需要另行绑定响应或用户回合、调用名及参数指纹，并保持有界，不能为本轮结果语义引入错误复用。
