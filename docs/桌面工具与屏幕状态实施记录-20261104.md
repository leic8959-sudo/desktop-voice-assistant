## 用户入口与功能

控制台侧栏和原助手页均新增“桌面工具”入口 `/static/desktop.html`。页面沿用共享 Cookie / 可选 Bearer、本机登录、同源与超时机制；不保存令牌。只轮询本地计时和设备回执，不自动访问第三方。离页 / 认证变化取消请求并清理私有数据。

| 功能 | 实际实现 | 操作和边界 |
| --- | --- | --- |
| 倒计时 / 番茄钟 | 页面默认25分钟，支持1～1440分钟；语音支持1～86400秒；当前工作区仅一个计时器 | 开始、暂停、继续、取消；已有运行 / 暂停计时不会覆盖。服务器生成 ID、保存 UTC 截止时刻和 revision。开始请求带 request_id；重复请求返回当前计时，同 ID 不同参数拒绝。动作校验实际 timer_id / revision，重复或旧状态请求不重复执行 |
| 重启与断线 | 原子保存到 `runtime_dir/desktop-timer.json`，只保留一条当前状态；服务端重启按 UTC 截止时间恢复 | 设备使用单调时钟计算剩余秒数；网络断开后继续已同步的本地倒计时。断电期间不能响铃；重连恢复服务端状态。离线暂停 / 继续等请求不假装成功，需要网络。不是高精度计时设备；时钟校准、通信延迟和实机时序仍待验收 |
| 到点提示 | 屏幕显示计时结束，保持到用户处理；一次本地提示音，不循环响铃 | 语音正在收听 / 播放时不抢播提示音。没有接入自动 TTS 播报，也没有新建云端语音请求。到点行为未实机验收 |
| 提醒稍后 | 到期提醒卡有“稍后5分钟 / 知道了”；桌面页可读取最多10条到期提醒并稍后 | 延后原记录，在 SQLite 事务中校验 pending、已到期和 updated_at；更新 due_at、清租约并重新投递。旧版本或重复点击拒绝，不重复顺延。“知道了”只关卡片，不把待办标记完成 |
| 提醒回执 | 新固件在卡片实际进入可见绘制路径后才通过原租约发 notification_ack，随后服务端返回新 updated_at，启用稍后按钮 | 仍只是设备绘制 / 投递回执，不代表用户已看到或完成任务。设备只缓存当前一张提醒，其他提醒留在服务端租约流程，后续重试；不在设备堆积无界列表 |
| 今日安排 | 本地摘要包括今日、逾期和未定时待办，读取最多5条，屏幕最多3条加“更多”提示 | 不把返回条数包装成全量统计。日期边界按 Asia/Shanghai；SQL 分别使用带状态/时间索引的有界查询，无大 OFFSET / 全库聚合。Google / Microsoft 日历仅点击选择来源时读取今日剩余时段，最多5条，显示最多3条；无时区的时间标“待核对”，不猜北京时间 |
| 天气卡 | 手动选择北京110000、上海310000、广州440100，通过原高德只读接口读取 `forecasts[0].casts[0]` | 显示城市、日间天气、低 / 高温、预报日期和提供商更新时间。需要有效 Web 服务 Key；不自动定位，不自动刷新。不完整结果拒绝成功卡片；读取失败可手动重试 |
| 家居反馈 | 原家居页面和语音 `execute_home_action` 的结果接入卡片 | 区分“平台报告目标状态”和“指令提交，状态未确认”；错误不自动重试控制指令。原授权 / 参数校验不改。平台状态不等同独立物理反馈 |
| 路线箭头 | 已有会议路线查询结果可显示左转、右转、直行、掉头箭头，距离和估计耗时 | 用 LVGL 线条绘制，不依赖字体里的箭头字符。只在明确指令词出现时给方向；未知不画箭头。标“路线预览 / 非实时导航”；未实现定位、路段跟踪、偏航或随设备转向的指北 |
| 一键待办 | 沿用已有语音 / 页面创建待办，补保存后的屏幕反馈 | 不新增外部任务写入，Todoist/GitHub 写入仍必须走已有服务端确认，不绕过上一轮确认机制 |

## 屏幕状态与交互

- 新 `screen_card` 协议带 card_id、kind、status、标题 / 摘要、有限数值、引用版本与 TTL；标题/正文按 UTF-8 字节截断后下发，设备再次检查字段长度 / 数值范围。不会透传原始提供商 JSON 或秘密。
- 语音收听 / 思考 / 播放 / 执行、错误与配对遮罩优先；空闲时依次显示提醒、临时信息、当前计时，再回到原点云。切到语音只隐藏卡片，不丢计时，返回空闲可恢复。
- 深色背景、紫色状态与时间、固定标题 / 正文 / 按钮区域；正文超长省略。计时显示 HH:MM:SS；触控按钮最小高度48px。天气 / 安排 / 家居等临时信息约8秒收起；暂停和结束计时保持，避免到点提示在长语音中被悄悄清掉。
- 设备只保留计时、普通信息、当前提醒三个固定槽，避免无界 UI 队列。计时心跳约5～6秒同步，同一版本不反复销毁重建。显示卡片时暂停点云绘制，减少无效帧工作量。
- 触控操作、绘制回执和提示音通过容量4的队列，由低优先级任务处理；不在 LVGL 回调中等待 WebSocket。操作请求有忙碌门闩、超时“结果待核实”，失败不假装暂停/成功，不自动重试状态变更。
- 新固件 hello 声明 `features.screen_cards=true`。旧固件不被当成支持；后台返回 `unsupported_firmware`。`sent` 表示发送成功，`shown/queued/expired` 是设备状态回执；都不代表真人已看到。页面明确显示最近回执与时间。
- 固件源码版本从0.3.7改为0.3.8，便于未来构建产物与旧固件区分；本轮没有生成新固件二进制。既有网关包含自动 OTA 路径，未来构建 / 安装应在明确维护窗口处理，不能因源码版本变化声称当前设备已更新。

## API / 语音

| 接口 | 功能 |
| --- | --- |
| `GET /api/screen/state` | 计时器状态、在线设备能力和最近绘制回执 |
| `POST /api/screen/timer` | 创建计时器：title、seconds、request_id |
| `POST /api/screen/timer/{pause,resume,cancel}` | timer_id / revision 校验后的状态操作 |
| `GET /api/screen/reminders` | 最多10条到期、未完成提醒 |
| `POST /api/tasks/{task_id}/snooze` | updated_at 校验后稍后5分钟 |
| `POST /api/screen/today` | 本地摘要，或明确选择 Google / Microsoft 只读日程 |
| `POST /api/screen/weather` | 选定城市天气读取与卡片下发 |

新 API 均在既有管理员认证 / 同源中间件下，无设备解绑、凭据编辑、任意文件读写或通用控制透传。屏幕操作只接受本地 timer 动作或提醒稍后；不能借该协议执行第三方连接器写入。语音补充 `start_desktop_timer` / `desktop_timer_status` / `desktop_timer_action`，先读真实状态再操作。Realtime 和 Chat 管道都由服务端注入计时请求 ID；Chat/DeepSeek 同样使用这些工具。
