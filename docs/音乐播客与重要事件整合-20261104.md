# 音乐播客与重要事件整合

牛牛要求由 Luna 实现音乐、播客、雨声和重要事件主动通知。本轮由两路 `gpt-6-luna` 实现、一路 Luna 交叉审查，主智能体负责共享语音接线和修正。此次没有重启当前网关、启动服务、播放音频、读取真实第三方账号或创建实际订阅；新功能需加载更新后的网关才生效。

详细实现与限制：`音乐播客接入-20261104.md`、`重要事件通知接入-20261104.md`。操作入口沿用控制台的“电脑与媒体”和“主动助理”页面。

## 共享接线

- `gateway.py`：只从本轮真实用户原话授权精确允许列表中的低风险媒体操作；订阅暂停/恢复/删除绑定对应动词，否定和引用/假设不会作为授权。上传、锁屏和其他电脑动作仍沿用控制台确认。语音幂等键由会话ID及工具调用ID生成，覆盖模型提供的键。
- 原生设备与浏览器/旧协议会话入口在`runtime.voice_lock`内先停止主动播报、暂停媒体，再登记新语音会话；媒体锁不反向获取语音锁。主动播报开始也先暂停媒体。
- 最终`response.done`无工具、状态完成、TTS发送队列和正在执行的工具全部清空后，watchdog向媒体服务标记ready，再正常结束语音会话。媒体服务继续等待该会话关闭及其他语音空闲才开始。播放请求最多等待120秒，用户新输入取消旧请求。
- `chat_pipeline.py`中间“文本+工具”轮标记`handoff_final=false`，避免还未生成最终回答就提前交接媒体；Chat工具执行计数与Realtime一致。千问Realtime、千问文本和DeepSeek都使用统一动态工具列表。
- `llm_providers.py`补充合法音源、真实音源ID、续播与通知订阅的工具引导；`scheduled`只是已安排，不能说成已经出声。外部邮件/日程/CI标题只用于通知资料，不作为模型指令或自动记忆来源。
