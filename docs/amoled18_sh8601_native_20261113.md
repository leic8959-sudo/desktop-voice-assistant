# 微雪原版 1.8 SH8601 整板接入与缓存构建记录

本批接入 `waveshare-amoled-1.8-sh8601` 的本地显示、TCA9554 复位、FT5x06 和单 ES8311 音频，并完成首次整板缓存构建；历史 1.32 SH8601 的共享回归也通过。应用名为 `assistant_sh8601`。这是源码和构建证据，尚未刷机或完成实机验收。

发行范围以小智 v2.5.2 固定提交 `49b4380b3faa0ceadd28a3e78aaf0f311c46c57e` 的发行清单为准，共 154 目录、188 变体。README 的 138／171 是旧数字。本批只有原版 1.8 新增首次整板构建通过，不增加源码入口数量。

## 本批改动

原版 1.8 从未安装的历史 Waveshare BSP 依赖切换到本地板级驱动，复用现有 `esp_lvgl_port`、SH8601 RGB565 桥接、FT5x06 1.1.1 和 codec 1.5.11。单 ES8311 使用已有检查实际驱动返回值的输入输出共用后端，保留单声道 24kHz、麦克风增益、数字静音、PA46 读回及打开状态检查。音频、绑定、提醒、媒体和 OTA 的上层协议继续使用原实现。

`waveshare-amoled-1.8` 是历史 CO5300 配置，`waveshare-amoled-1.8-v2` 也是单独修订。本批只让显式 SH8601 宏进入新路径；二者的注册身份、manifest 和旧显示／音频分支保持。不能根据“微雪 1.8”这个名字选择固件，现有实物的具体修订仍需确认。

| 项目 | 原版 1.8 本批配置 |
| --- | --- |
| 屏幕 | SH8601，368×448，RGB565，gap 0，无换轴／镜像 |
| QSPI | SPI2，mode 0，40MHz；CS12／CLK11／D0…3=4／5／6／7 |
| 初始化 | 厂商 BSP 1.1.4 的九条命令，只有最后亮度 51FF 改为 5100；软件复位 01 后等待 80ms |
| 外设复位 | TCA9554 0x20，P0／P1／P2；先锁存低电平再输出，随后 HIGH100ms／LOW300ms／HIGH150ms；保留其余引脚与极性寄存器 |
| 触摸 | FT5x06 0x38，IRQ21 输入，reset=NC；使用扩展芯片复位，不把 IRQ 当复位脚 |
| 触点读取 | 从 02 读取七字节；只接收一个合法触点，释放事件、无效事件、多触点或错误会释放／取消；恢复后先等待松手 |
| I²C | I²C1，SDA15／SCL14，寄存器操作超时 100ms |
| 音频 | ES8311 BOTH，24kHz mono；MCLK16／BCLK9／WS45／DOUT8／DIN10；PA46 |
| 电源和 SD | 原 AXP2101 ALDO1 代码保持；SD 一线 CLK2／CMD1／D0=3，不格式化 |
| 存储 | 16MB Flash、Octal PSRAM 配置；NVS 0x9000／0x4000，双 app 各 3MiB，model 4MiB |
| 唤醒及对话 | 保留“你好，小燕子”、AFE／AEC 和原自然插话路径；声学表现待验收 |

复位时序在本轮复核时纠正：固定小智原版源码要求 HIGH100ms／LOW300ms／HIGH，不能沿用本地旧路径的 LOW20ms。最终实现保留该脉冲并增加本地已有的 150ms 释放稳定时间。首次构建日志单独保存为 `initial-build.*`；正式账本只引用纠正后的重建结果。

100ms 超时和读回只能说明相应寄存器操作有返回及一致性检查，不能证明引脚电压、触摸身份或整段生命周期有界；SDK 的 SPI 实现仍有无限等待。FT5x06 初始化复用组件，触点读取使用原始报文，避免把组件截断后的坐标当成完整触点数。未宣称硬件 AEC、多麦克风波束形成或厂商电池、充电、传感器、休眠及 MCP 功能已移植。

## 实际执行及结果

使用已安装的 ESP-IDF 5.5.6，SDK HEAD 为 `880a203ae603d08a94d06aa01e0d6761958e5e9e`，保留其既有 dirty 状态。构建目录隔离，复用 17 份本地组件来源并启用离线网络 guard；没有安装或下载依赖。Ninja 并发数为 2。

最终两次实际 IDF 命令均为 `idf.py -DIDF_TARGET=esp32s3 -DASSISTANT_BOARD=<profile> reconfigure build`，详细解释器绝对路径、命令、工作目录、时间和日志摘要保存在各板 `build.json`。初次预检仅检查直接依赖，正式构建另有实际成功结果。

每项保存 330 个当前输入文件摘要、28 个产物摘要，以及八条实际产物核对命令和输出。检查使用 `readelf -h`、`nm -S -C --size-sort`、`nm -u`、`size -A -d`、`esptool image_info --version 2`、实际分区二进制解析和 SDK 只读 Git 查询。两份 ELF 均包含自定义唤醒、AEC、网络、媒体和本板驱动；原版 1.8 包含 FT5x06／SD／单 ES8311，未误链接 CO5300、CST9217、ES7210 或旧 BSP 的扩展芯片初始化路径。静态符号存在不等于功能运行验收。

镜像项目名、芯片和 Flash 配置正确，校验摘要有效；实际分区二进制保留 NVS、双 OTA 和模型分区，当前镜像尺寸可容纳。未来镜像容量和物理 Flash／PSRAM 容量仍需另验。ELF 仍有 SDK 强制保留的四个 UND：`__cxx_fatal_exception`、`esp_system_include_coredump_init`、`start_app`、`start_app_other_cores`。既有 LVGL 废弃 API 警告保留，不把缓存构建称为干净发行或启动通过。

## 总体清单与后续边界

当前仍为 152／188 官方变体有源码入口，153 个本地 profile（含一个历史入口），36 个无源码入口，4 个已知必需功能缺口。累计 115 个官方变体曾缓存构建通过；对应本次全部输入的当前构建为 2 项通过、113 项过期、73 项未执行。过期项不能当成当前源码已通过。直接依赖条件满足 116 个本地 profile，其中 115 个官方变体。

188 个变体的本轮实机验收全部 `not_run`。本批没有运行独立测试套件或类型检查，没有启动服务、Git 写操作、刷机、OTA、上传或发布。现有微雪 1.8 的屏控修订、触摸、音频时钟、AEC／自然插话、SD、绑定、提醒、OTA 回滚及资源峰值均未在本轮实测。

此前已接受 C3／C5／C6 使用固定“你好小智”，逐板保留差异；本批 S3 的唤醒词不变。无屏板仍按手机连接热点后在配网页读取六位绑定码。无 PSRAM 的有损压缩选择仍待确认，不以关闭功能来计入适配完成。
