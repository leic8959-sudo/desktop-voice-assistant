# 助手工具架构公开实现对比（2026-11-06）

牛牛要求解决“模型理解后被本地关键词再次拦截”的全项目同类问题，并对照其他助手。本文由父代理独立检查公开源码，作为Luna实施的审阅依据，不代表引入这些框架或整项目重写。最终具体修复和验证另见本次实施记录。

## 判断

现有音频设备、云供应商适配、工具服务、家居/音乐真实ID及授权、幂等和结果回读有可复用的基础，不能仅因一次播放失败认定全部从头错误。确定需要纠正的是职责交叉：模型选择工具后再用中文正则判断意图；显式工具又进入另一轮模型重新规划；语音“等用户”和“模型还在响应”共用空闲退出；跨轮历史未保留完整工具调用/结果。

目的不是让模型获得任意执行权限，而是把“理解用户的意思”和“判断这个具体动作是否具备执行条件”分开。

```mermaid
flowchart LR
  U[已验证的用户输入与对话上下文] --> M[模型选择已公布的工具和参数]
  M --> E[统一工具执行入口]
  E --> V[校验参数、真实ID、权限、确认及幂等]
  V --> D[领域服务执行与状态回读]
  D --> R[结构化结果返回模型]
  R --> M
```

取消/响应超时属于会话编排，应关联输入、响应、工具和播放身份；不能靠“没有新语音30秒”推断所有工作已经完成，也不能在无进展时无限等。不同工具的副作用与可取消性需要按实际业务处理：已经开始或完成的外部动作不因对话失败而自动重放。

## 一手源码对照

### Home Assistant：工具注册、真实能力和领域校验

检查提交`68a32468e03da47d7f12ed745fda77b83c99af6e`的[helpers/llm.py](https://github.com/home-assistant/core/blob/68a32468e03da47d7f12ed745fda77b83c99af6e/homeassistant/helpers/llm.py#L254)。`ToolInput`携带工具名/参数和调用ID，`APIInstance.async_call_tool`查找已注册工具并调用具体工具实现；`IntentTool`将结构化参数转为slots，调用既有intent处理器时`text_input=None`，沿用领域实体和上下文。

可借鉴：工具提供可执行能力，模型选定后走领域入口；已有领域参数、实体和暴露范围承担真实约束。此源码片段不证明Home Assistant所有入口都没有句法规则：它另有传统语音intent系统，不能把传统intent与LLM工具路径混为一谈，更不能据此删除本项目确认或账号授权。

### LiveKit Agents：生成、工具和会话生命周期各有所有者

检查提交`b2ea2b4e92094e0962d9971274e077f3c1f009e9`的[agent_activity.py](https://github.com/livekit/agents/blob/b2ea2b4e92094e0962d9971274e077f3c1f009e9/livekit-agents/livekit/agents/voice/agent_activity.py#L394)以及[agent_session.py](https://github.com/livekit/agents/blob/b2ea2b4e92094e0962d9971274e077f3c1f009e9/livekit-agents/livekit/agents/voice/agent_session.py)。activity持有工具执行器，结束时对可取消任务执行取消，对其他任务等待收尾；会话另有用户离开、转写超时等状态/期限选项。

可借鉴：会话退出必须知道谁仍在工作，工具是否可取消与结果如何归属；“模型活跃”与“等用户输入”应分别管理。不能简单把它的某个默认15秒参数搬来替换我们的30秒，也不能假设一个框架会替本项目实现家电确认、音乐候选或个人资料同意。

### Pipecat：工具声明、调用/结果事件及单独期限

检查提交`7f4857f4b3f87e6040f29d9f6f718141068f955d`的[llm_service.py](https://github.com/pipecat-ai/pipecat/blob/7f4857f4b3f87e6040f29d9f6f718141068f955d/src/pipecat/services/llm_service.py#L231)。函数注册项包含处理器、`cancel_on_interruption`、`timeout_secs`，可覆盖全局工具期限；调用、进行中、结果、取消以事件帧传递，另有completion timeout回调。工具schema是否公布与实际handler注册有明确同步逻辑。

可借鉴：模型看见的工具与实际处理器一致，响应和工具超时可观测；用户应得到失败反馈，而不是空闲计时静默结束。Pipecat是框架，不是已经配置好本项目业务的成品助手，不应为了借鉴其流程直接引入第二套完整音频和连接生命周期。

## 本项目应保留和纠正的边界

| 范围 | 语义与执行边界 |
| --- | --- |
| 音乐/媒体 | 模型根据当前上下文理解“原版”“随便一个”等，提交真实selection/source；服务校验候选存在、有效期、可播放权限、输出设备和状态，不能用播放关键词作为最终授权合同。 |
| PC动作 | 仅既有白名单应用、锁屏、音量和媒体键等允许能力；参数规范化、用户输入代数和调用身份仍需检查。不允许任意shell、键盘输入、点击或账号操作。 |
| 家居 | 必须是已授权且当前可用的真实设备/动作；温度范围、关机不擅自调温、开机回读再后续操作等由领域闭环保证，不能由第二模型重新解释同一个工具并顺带做其他动作。 |
| 导航演示 | 已有直接登记路径来自牛牛明确要求“别只口头答应”；若兼容快捷入口保留，必须与模型工具共用同一幂等schedule，不成为另一套独立动作执行器。 |
| 订阅/提醒 | 模型解析跨轮指代，服务校验真实ID、版本、时间、时区、容量和重复执行；持久化数据不能因响应取消被自动补建。 |
| 记忆/隐私 | 用户实际选择的“只自动记偏好与长期事项、个人事实明确手动保存”是业务授权，敏感信息、来源和隐私开关同意不是可随意删除的词表。审计必须分别说明哪些是错误语义门槛、哪些是有效隐私边界。 |
| 外发/账号/权限 | Connector scopes、一次性确认、邮箱发送确认、OAuth授权和受限服务接口继续有效；模型参数不能自我授予权限。 |
| 响应与工具生命周期 | 活跃响应不应被idle关闭；停滞和总耗时必须有单独期限，取消身份与副作用记录保留，工具执行失败/上游无响应应有明确反馈。 |

代码规模或文件名称不是这次改动的判据。继续复用现有service、调用身份和连接封装；只有出现可重复的职责冲突才提取最少的共同逻辑。没有选择迁移到Home Assistant Agent、LiveKit或Pipecat，也没有新增依赖、规则文件或部署参数。
