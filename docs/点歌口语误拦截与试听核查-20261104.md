# 点歌口语误拦截与试听核查

牛牛反馈刚才点播时报错。本次依据实际网关日志定位，不把旧调试错误当成此次原因。

## 本次直接原因

北京时间23:03:42识别到“小燕子，帮我来一首周杰伦的晴天”，23:03:44的`music_play`报`PermissionError: 需要本轮用户明确的实体设备点歌指令`。23:04:17的“呃，来首朴树的吧”同样被拦截。

ASR已经正确识别，后端白名单只支持播放/放首/来点/来个等表达，漏掉“来一首/来首”。这是本地指令校验漏项，不是设备解绑，也不是该次工具调用的QQ网络错误。

已修复`gateway.py`正向表达与对应否定表达；保留“不要来一首”“别来首”“假设帮我来一首”等拒绝路径。回归使用上述真实发言，包含在`tests/test_media_gateway.py`。

## 后续发现：此前短测实际上为试听

MA真实日志多次明确记录`QQ Music full stream unavailable ... using preview stream fallback`。QQ适配器的真实`StreamDetails.data.preview=true`，且实际时长来自试听片段；曲库条目仍可能显示269秒。

此前《晴天》4.4秒短测与暂停续播证明实体传流和设备驱动回执正常，但实际源为试听，不能证明完整269秒可播。已向牛牛更正，并更新主实施记录。不能仅凭曲库`available=true`、曲库时长和`single`流路径判断为整曲。

整曲URL不可用的具体原因没有由该适配器返回；它在所有完整音质候选均取不到URL后回退TRY。现有证据不能区分会员权限、地区或社区适配器问题，不归因账号未开会员。

扩展已在生成流地址前读取该可靠标记；若明确为试听，释放MA队列并返回typed拒绝，不交付音源URL。客户端和语音工具明确反馈“音乐服务仅返回试听音源，无法按整曲播放”，不再把它包装成成功整曲或笼统工具错误。未尝试绕过订阅/地区限制。

附带修复停止时重复状态回报竞态：客户端report与stop使用同一播放锁，过期会话不再争用；测试改为验证新resolve等待旧完成报告退出后再解析，避免旧报告清掉新会话。
