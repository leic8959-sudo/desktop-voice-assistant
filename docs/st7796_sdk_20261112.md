# 微雪 S3 LCD 3.5／LilyGO MVSRLoRa 的 ST7796 构建接入

本批推进两个已有源码入口：`waveshare-esp32-s3-touch-lcd-3.5` 原版与 `lilygo-t-display-s3-pro-mvsrlora`。它们当前都只缺ST7796组件；本批复用SDK公共DCS操作，明确发送原ST7796初始化和复位时序，移除这两板的外部ST7796依赖。实际硬件仍记为ST7796，不因工厂API名称改成ST7789。

## 原驱动与板级差异

来源是前批已归档并核对SHA256的esp-bsp固定提交 `5a39b90736dad653869d101f069a06758082a39e` 的ST7796 1.4.0 general驱动；源码、来源URL和摘要再次保存到本批evidence。这里只覆盖两块已审阅的SPI／16位板级路径，不替换通用18／24位、i80、MIPI接口。

| 路径 | 微雪 S3 LCD 3.5 原版 | LilyGO MVSRLoRa |
| --- | --- | --- |
| 屏幕／总线 | 480×320横屏，SPI3 mode0／40MHz，MOSI1／MISO2／CLK5／DC3，CS及ESP复位GPIO为NC | 222×480竖屏，SPI3 mode0／40MHz，MOSI17／CLK18／CS39／DC9／RST47 |
| 初始化 | 原17条专用表、COLMOD05，表内延时原文保持 | 原ST7796 1.4.0默认12条表，转为 `st7796_default_commands.h`，附Apache-2.0通知和许可全文 |
| 方向／窗口 | BGR、反色、swapXY、无mirror、gap0 | BGR、反色、mirrorX、无swapXY、gap49／0 |
| 背光／输入 | GPIO6 PWM、FT5x06原始count／event／坐标校验、BOOT0 | GPIO48 PWM、原CST226SE解析／同步机制、BOOT0 |

两板原驱动前导都是SLPOUT100ms、MADCTL08和COLMOD05，帧缓冲16位。新初始化回调按原顺序发送，保留表内所有延时／零tick让出，不调用SDK默认ST7789 init，因为它会额外写RAMCTRL及不同COLMOD。SDK的BGR缓存与原镜像／换轴操作一致；内部COLMOD55不参与之后的现有一次板级启动流程，实际线上格式明确写05。没有新增外部任意格式／方向变更后的通用reinit契约。

微雪原版先由既有扩展口完成板级LCD复位，再保留原ST7796软件01／120ms。LilyGO保留GPIO47低10ms、高后等120ms，并检查实际GPIO调用返回值，避免原general驱动忽略复位写入错误。绘图沿相同gap、0x2a／0x2b末坐标减一、0x2c和16位长度，双方本来都检查IO错误，不把错误传播描述为新增能力。

原ST7796无sleep／brightness回调，新工厂对应回调置空，背光仍由原板级逻辑负责。初始化使用公开 `esp_lcd_panel_t` 回调，不访问SDK私有结构或修改已安装SDK。

## 保留范围

微雪3.5B／3.49两种AXS QSPI分支、完整旋转缓冲／发送流程没有迁移，本批不构建或登记它们通过。CHD 1.3.5、CAM CH32和P4的ST7796仍是各自正式依赖，没有因型号相近删除其组件条件。

微雪原版的TCA9554方向／功放／LCD复位、ES8311、触摸异常取消和坐标变换源码保持原文。LilyGO的MIC供电、RT9080、MAX boost、CST226SE握手及数字输入16kHz／输出24kHz保持原文，不把基础语音适配描述成LoRa功能完成。

音频、完整唤醒、AEC、自然插话／媒体人工决策、绑定／NVS／配网、提醒和双OTA源码均未改。构建导出脚本仅增加：LilyGO附带ST7796默认表许可，微雪原版附带既有专用表MIT通知；未运行Docker或实际导出。
