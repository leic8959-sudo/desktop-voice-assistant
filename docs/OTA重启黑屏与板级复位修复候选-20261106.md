# OTA重启黑屏与板级复位修复候选（2026-11-06）

牛牛补充：设备装有电池、接USB，几乎每次OTA软件重启后整屏全黑，但语音仍正常。这是明确的设备显示故障，设备online和display=true均不能替代屏幕验收。当前实际固件仍0.3.18，候选源码版本0.3.19，尚未构建/OTA。

## 已确认的启动缺口

本项目`display_ui_init`直接调用BSP启动屏幕。BSP将`BSP_LCD_RST`和触摸reset配置为GPIO_NUM_NC，CO5300只能发SPI软件复位；没有调用`bsp_io_expander_init`配置板级显示复位。`esp_restart()`只负责软件重启，不能保证外设经历完整断电复位；装电池时拔USB也不保证外设断电。不能因此断言电池损坏或整机供电不足。

厂商同板参考：[board_variant.c](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/78e13f852929c2ab4f9d5e0ad1c50ea378dbf2b4/examples/esp-idf/92_qmi8658_imu/components/board_variant/board_variant.c#L26)，明确TCA9554 P0=LCD_RST、P1=DSI_PWR_EN、P2=TOUCH_RST，初始化时拉低再释放，并等待稳定。该参考适配同板CO5300/CST816和SH8601/FT3168变体。公开源码的实际commit、blob SHA和片段存于`evidence/display-reset-board-reference-20261106.json`。

另检查小智同板实现，也存在TCA9554 0/1/2初始化脉冲。本候选以厂家引脚映射和20ms低电平、150ms稳定时间为依据；不照抄小智的PMIC关全部电源和充电电流设置。

## 最小修改

`firmware/assistant_espidf/main/display_ui.cpp`新增`reset_display_peripherals`，在SPI/LVGL与触摸任务启动前通过已有BSP取得扩展器句柄，仅设置0/1/2三引脚输出、低20ms、高150ms，随后沿原显示流程初始化。复用已安装esp_io_expander API，掩码读改写由现有驱动实现，保留SD片选等其他引脚。每步错误直接返回，不把未完成复位报成功；只启动时执行一次，不增加运行期复位循环、后台线程或自动整机重启。

版本源码0.3.19。未改当前运行的网关、设备配置、亮度、PMIC、充电参数、绑定、NVS、模型或语音协议。0.3.18有限首句与导航改动全部保留。

## 不能提前下的结论

缺少板级复位是源码和厂商对照已确认的缺口，也是OTA暖启动黑屏的强候选；没有保留黑屏当刻显示心跳/面板读回，尚不能证明这是唯一根因。此前运行中黑屏是否同源也未确认。

接下来需明确构建和OTA授权。构建并加载0.3.19后，应保持USB和电池连接，验证OTA暖启动能恢复点云/文字，再做后续软件重启复现比较；还要分别确认触摸和0.3.18语音链路保持。镜像上线和扩展器写成功依旧不能替代牛牛看到屏幕亮起。
