# Chat 工具调用身份与去重（2026-11-05）

## 实际复现

原 Chat 回合逐个执行模型返回的工具索引，没有识别同一响应中重复的调用 ID；相同音乐排队调用会被执行两次。不同参数或名称的重复 ID 也可能先执行前面的动作，再产生不规范的重复 tool output。创建任务等工具的幂等键原为 session+call ID，供应商在另一个响应复用 ID 时会误冲突。

主代理实际执行初始 `python -m unittest tests.test_chat_tool_deduplication`：7 个方法、1.639 秒、7 个失败（包含冲突两个子测试），取消对照通过；证据 `evidence/chat-tool-deduplication-20261105-before.log`。使用真实 `_run_turn`、`_chat_round` 和 TTS 空队列收尾，只有模型片段与动作服务为受控替身，未调用真实音乐、账号或设备。

## 最小实现

仅修改 `chat_pipeline.py`。流式累积在新工具索引进入前限制最多 8 个槽，调用 ID 最多 256 字符、名称 128 字符、参数 JSON 最多 16KiB；非法索引或身份片段直接拒绝。结束响应后、执行任何工具前，整批解析对象参数，按排序键与紧凑 JSON 规范化，拒绝 NaN/Infinity。

同一响应中相同 ID、相同名称及规范参数仅保留一项；任意相同 ID 不同指纹拒绝整批，前面看似有效的工具也不执行。assistant 的 tool_calls 与后续执行使用同一去重结果，每个 ID 只有一条对应 tool output。未知结果的重复索引已在执行前合并，不会再次调用工具。

非流式完整 tool_calls 按兼容 API 的列表顺序补内部索引，不要求供应商在非流式格式中提供 SSE 的 index。流式响应仍使用真实增量索引；两种格式最终通过相同的整批验证与合并路径。

会话只保留一个累计新调用整数，最多 100 项；整批接纳前检查剩余预算，不保存跨响应结果缓存、任务集合或新增并发锁。预算保守计入已接纳的唯一调用，不因后续取消或失败重新放回，避免反复取消绕过上限。已有回合任务顺序执行，取消继续传播，不补偿、回放或伪造已执行动作的结果。

创建任务、重复提醒、订阅及计时等幂等工具使用 session、真实 response ID 和 call ID 的稳定 SHA256 身份，生成小于 128 字节的键；另一个响应可以合法复用相同 vendor call ID。缺失真实响应身份的私有幂等工具调用按参数错误拒绝，不随机制造身份；非幂等或只读私有调用合同不扩展。

这只保证同一模型响应中的身份重复不重复执行，不代表不同响应的语义相似动作都被去重。本修复不主动重发工具请求；未知结果在后续响应中的语义重试仍需另行约束。
