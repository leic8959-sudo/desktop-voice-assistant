# 家居通用接入：实现与独立验收

日期：2026-10-29，Asia/Shanghai。Luna（gpt-6-luna）负责实施，主代理负责独立黑盒测试、源码审查和真实平台只读验收。当前是本地电脑、Home Assistant 和 ngrok 的单家庭测试环境。

## 交付行为

Home Assistant 已接入、且属于当前支持的标准能力范围的设备，可以通过页面刷新自动发现，再由用户启用。新增同类设备不需要编辑助手配置、修改语音工具、重启服务或重新烧录固件。

设备发现与控制授权分离。现有 M40 和空调通过原配置首次迁移授权；新发现的风扇灯和电暖器默认未启用。停用后不会因为重启重新授权，更换成新的物理设备ID也不会继承旧授权。授权文件损坏、顶层类型错误或版本不支持时停止加载，保留原文件，不恢复默认授权。

## 架构与边界

- 平台适配层使用 HA 正式认证 REST 与 WebSocket 接口，读取设备、实体、房间、状态和服务目录，不依赖 HA `.storage` 文件或本机目录结构。
- 按物理 `device_id` 聚合，一个扫地机器人不会因其几十个传感器被显示为几十台设备。风扇灯等复合设备保留各实体能力，动作ID包含目标实体，避免同名“打开”指向错误部件。
- 平台标准能力映射集中在 `home_control.py`。能力描述包含动作ID、名称、目标实体、参数schema、权限、确认含义，以及主操作/附属操作分组。界面使用同一描述生成按钮、枚举与数值输入，显示字段也由平台层提供。
- 家居模型工具收敛为 `list_home_devices`、`get_home_state`、`execute_home_action`。新增设备不用增加专用模型工具。旧Python调用仅保留迁移包装，仍进入同一授权和执行路径。
- 只有明确列入安全标准映射、且平台服务与设备属性实际支持的动作才开放；不透传任意HA服务，不开放门锁、脚本、自动化、恢复出厂等未知私有动作。
- 执行前在设备锁内检查当前授权，针对目标实体读取最新状态与能力，再校验枚举、数值范围、步长和额外参数。每次指令只刷新其目标实体，避免扫描整户设备。
- 不自动重试写请求。平台接受、平台报告目标状态和实物完成分别处理；状态确认失败不使用旧缓存报成功。发现失败保留并标记旧目录，恢复成功前拒绝使用该失效目录控制设备。

本轮支持灯、开关、风扇的基础开关，空调/电暖器的标准模式和温度，以及扫地机器人实际报告的清扫、暂停、回充能力。不同平台、全新品类、调光调色或厂商私有能力仍可能需要一次能力映射扩展，不承诺所有私有功能自动可用。

## 缓存、持久化与原型规模

- 目录缓存TTL为20秒，显式刷新立即同步；列表支持名称/房间查询和游标分页，每页1～30台。
- 当前适配器上限为500个HA状态实体、100个物理设备；超限明确失败，不静默丢设备。HTTP响应和WebSocket消息也有大小与超时限制。
- 授权保存在被忽略的 `runtime/home-authorizations.json`，包含首次迁移种子与设备启停状态，通过临时文件加原子替换写入，有文件大小及条目数量限制。
- 当前按单家庭、单进程运行，未实现商业账号、多租户隔离、跨实例共享授权。商用时仍须替换为有明确商业权限的平台接入，并设计相应的服务端账户与授权存储。

## 独立验收

主代理编写的 `tools/verify_home_architecture.py` 使用独立模拟HA正式接口，覆盖24项黑盒场景，包括：

1. 多实体聚合、同类新型号发现、首次默认不授权。
2. 页面授权、撤销后重启、设备更换不继承旧授权。
3. 同名设备拒绝歧义、复合设备动作准确路由。
4. 越界温度、无效枚举、非法参数类型、额外目标参数均在写入前拒绝。
5. 任意服务、未授权、离线、实体移除、能力变更时拒绝控制。
6. 写失败不重试，状态确认失败不假报成功，平台属性不覆盖可信执行结果。
7. 分页命中缓存、单动作不全屋扫描、发现失败保留授权并停止控制、恢复后可用。
8. 分块HTTP JSON完整读取，以及损坏、错误形状或错误版本的授权文件失败关闭。

实际命令及结果记录于 `evidence/home-architecture-independent.log`、`evidence/home-architecture-regression.log` 和最终JSON：

```powershell
python tools/verify_home_architecture.py
python -m unittest discover -s tests -v
node --check web/app.js
python -m py_compile home_control.py control_api.py gateway.py tools/preview_home_architecture.py tools/verify_home_architecture.py
```

独立黑盒24项与既有回归32项均需通过，才作为本轮验收完成。故障用例中的503/504/损坏文件堆栈是注入故障的预期日志，不能据此省略错误记录。

## 页面和真实平台验证

页面验收使用 `tools/preview_home_architecture.py` 在8766启动隔离预览：仅复用真实HA的只读发现能力，授权使用临时目录，所有实物控制请求被明确禁用，云模型连接也指向禁用地址。实际点击风扇灯“启用”再“停用”后立即生效，没有重启预览服务，也没有修改真实授权文件。

已检查设备聚合、中文主状态、空调当前与设定温度、模式枚举、参数默认值、主操作与“更多功能”、离线禁用，以及页面横向溢出。最终截图为 `evidence/home-architecture-ui-final.png`。8766预览完成后停止，不作为对外服务。

本地8765及ngrok入口实际复核：无令牌访问家居接口返回401，认证后返回200；显示4台物理设备，其中M40与空调已启用，风扇灯和电暖器未启用。复核时M40在充电座、空调关闭，另外两台被平台报告不可用。硬件已重连。状态会随用户实际操作变化，以平台当前报告为准。

本轮未向真实家电发送清扫、回充、开关、模式或温度写入，未调用付费语音模型。通用模型工具契约与分发经过模拟验证，真人语音实际选择新工具及真实动作仍需按用户明确指令另外验收。
