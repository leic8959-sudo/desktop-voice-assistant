# 并发回合生命周期修复（2026-11-05）

## 问题与行为

原 `ChatBackend._start_user_turn` 先等待旧回答，再等待 `observe_user_text`，最后才登记 `_run_turn`。文字和 ASR 输入可以同时越过观察阶段，各自创建活动回合；取消或关闭也可能在观察完成前返回，随后又创建回答。ASR 静音计时器在调用该方法前清空自身引用，使观察中的输入脱离原有关闭任务列表。

本轮只修改 `chat_pipeline.py`：

- 一个回合任务拥有观察用户输入和执行回答的完整过程。
- 一个调度任务等待旧回合及其 TTS、历史恢复真正收尾，再启动新回合。
- 等待期间只保留一份最新输入，中间输入被覆盖；最多一个活动回合、一个调度任务和一份待输入，不建立输入任务集合或等待链。
- 每次新输入、取消或关闭递增输入代数；即使观察方法吞掉取消，也必须通过代数和关闭状态检查才能开始回答。
- 取消只等待调用时的旧任务，不等待取消之后新登记的回答。关闭先禁止新输入，再完整等待调度和已有资源退出；内部调用排除自身及依赖自身的调度任务。
- 关闭或取消的外层调用者自身被取消时，继续等待同一份清理结果再传播取消，不二次取消正在清理的子任务。
- 调度任务自身取消时也会取消并等待拥有的回合，避免屏蔽取消后的子任务无人清理。重复输入不重复取消正在清理的任务，取消响应 ID 集合沿用既有 100 条限制。

`ChatBackend.send_user_text` 返回表示输入已登记；观察改由回合任务负责。`gateway.device_input` 原有文字分支仍会在调用后端前观察文本，因此不宣称整个网关文字入口已完全取消等待。本轮没有改变该网关行为。
