# BigSmart GT911 轮询复用与首次整板构建

本批推进已有 `rymcu-bigsmart` 源码入口。固定小智v2.5.2板类使用GT911默认0x5D，触摸RST／INT均为NC、16位寄存器／400kHz；它没有微雪4B的扩展口选址复位过程。本批复用上轮 `Gt911Polling`，移除本板外部GT911依赖，不新增复位、0x14回退、IRQ或休眠策略。

## 来源与改动

固定来源为小智提交 `49b4380b3faa0ceadd28a3e78aaf0f311c46c57e` 的 `main/boards/rymcu/bigsmart/rymcu_bigsmart_board.cc`，已与此前source-index内SHA256核对。GT911寄存器格式继续沿上轮经Git blob核实的Espressif1.2.1来源；现有 `gt911_polling.h/.cpp`保持原文，没有复制第二份驱动。

共享SPI显示文件仅为BigSmart增加独立轮询消费分支；CMake在该板选择既有polling.cpp，移除其GT911组件，manifest只删本板这一项依赖。原PCA9557、音频、ST7789、引脚和容量选择未改；profile身份不变，只追加当前实现范围说明。立创SZPI仍用自己的FT5x06路径，CHD继续使用其GT911／FT探测和正式组件，没有因共用文件误迁移。

| 情况 | BigSmart行为 |
| --- | --- |
| 原始坐标 | 只接受 `rawX<240, rawY<320`，原变换 `(rawY,239-rawX)` 保持；零起点端点落在320×240内 |
| 初始按压 | 必须先收到实际已ACK的零点报告才接受按下，首次not-ready不能当作松手 |
| 多指 | 保留五点真实count；任何count≠1的非零报告取消并等待释放，不再经只取一点的接口截成一指 |
| 错误／越界／异常 | INDEV_RESET取消当前动作并重新等待真实零点释放，不将恢复后的第一份按压直接接回旧动作 |
| 健康not-ready | 沿用上轮轮询器的最后已确认快照；无有效快照则仍返回错误，不清除可能后到的新报告 |

GT911 IO增加明确的每次100ms超时，保持400kHz和16位命令；一次poll可能读status、payload、ACK三次，不能当作总100ms。polling由单个LVGL消费者使用，初始化在其启动前完成，IO生命周期仍由板级持有；没有新任务、动态队列或逐次分配。

轮询器的状态／ACK检查和限制同上轮：最多5点／40字节，payload和ACK均成功才发布，异常count／重复track ID／不支持的状态标志拒绝。产品／配置字段只记录实际读取值，不声明硬件身份已验收。长期not-ready保留按压快照的风险仍存在，未增加卡死检测、自动复位或猜测释放。

## 保留的板级行为

显示仍320×240 ST7789、SPI3 mode2／80MHz，GPIO42低有效背光、swapXY／mirrorX／反色。PCA9557仍只拥有LCD control bit0和PA bit1，保留摄像头及其它位，实际读改写／回读路径未改。

ES8311输出＋ES7210输入，I2C1 SDA1／SCL2、ADC8bit地址0x82；24kHz、TDM4采MIC1／slot0、MCLK38／BCLK14／WS13／DIN12／DOUT45，原PA静音门控及30dB／播放12dB增益保留。不将硬件参考、相机、LED或电池未实现项当作完成。

完整自定义唤醒、AFE／AEC、自然插话／媒体人工决定、绑定／NVS／配网、提醒与双OTA源码均未改；只有现有微雪1.8可实机验收。上游默认RST／INT为NC不证明用户实际板卡已上电、地址正确或无需复位，真实BigSmart修订仍需验机。
