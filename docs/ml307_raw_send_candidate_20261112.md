## 原始发送入口

候选API接受连接ID0–5、非空载荷1–4096字节、请求时限1–60000ms。使用try-lock竞争共享command_mutex，发送与MIPRD不能交错占用同一命令事务；锁忙或残余接收数据时不发起新命令。UART事件／接收任务不得调用阻塞读写方法，回调只能通知网络owner。

调用前必须由独占网络owner完成模块身份／固件匹配、ATE0关闭回显、所有连接接收缓存模式和原始格式设置／查询确认，并停止旧HEX消费者。**这些步骤本轮仍未实现或实机确认。** 开关仍沿上轮名称 `EnableMl307RawReceive()`，本批让它同时分配读写状态；调用开关本身不配置模组。

| 阶段 | 候选行为 |
| --- | --- |
| 准备 | 清旧完成／错误／提示符事件，登记连接和本次长度 |
| 命令 | 发送 `AT+MIPSEND=id,length` 和命令CRLF |
| 提示符 | 专用事件只由本次等待中的 `>` 唤醒；允许提示符后单个可选空格跨片到达 |
| 载荷 | 直接发送原始字节，不HEX编码，不附加CRLF、CTRL+Z或其他数据 |
| 结果 | 必须同时取得本次连接、完全相同的整数接受长度和最终OK |
| 返回 | 只返回本次接受长度；任何部分失败不隐式重试 |

`>` 与最终OK分开，不再复用旧 `wait_for_response_` 提示符和命令结果。最终OK和MIPSEND确认可按任意先后记录，但两者都到齐才允许完成；这只是候选容错设计，尚未验证真实固件打印顺序。

发送成功只表示**模块协议栈接受了这些字节**，不等于TCP服务器已收到、TLS应用已处理或小燕子动作已完成。TCP ACK与业务回执仍是各自层面的证据，不能用发送返回长度替代。

## 共用截止时刻和故障路径

命令TX、等提示符、载荷TX和等最终结果共用一个esp_timer截止时刻，各I/O阶段只取剩余时间；返回前再次检查是否到期。获取锁用try-lock，不为一个竞争请求无限阻塞。任务抢占、调度粒度、日志／字符串分配和实际串口流控均未测量，因此不能称为严格实时总耗时保证。

本批归档精确UART-UHCI 0.4.0参考包，读取其公开 `Transmit(buffer,size,timeout,cancelled)` 实现：它同步填UART FIFO并等待TX idle，失败／取消时复位发送FIFO。候选idf_component.yml将原 `^0.4.0` 改为精确 `0.4.0`，确保接口依据可追溯；参考包没有安装。

新原子取消标志由会话poison及DMA丢失ISR置位，原始读命令TX和发送的两次TX都传入它。调用方必须保留载荷直到API返回；参考实现没有在返回后继续从调用方内存发起DMA，但这仍需目标链接、UART硬件和取消时序验收，不能据源码证明实际不会残留字节。

重复／错误阶段提示符、重复OK、类型或连接／长度不匹配、任一TX失败、缺提示符／确认、请求到期和当前socket断开均会锁存整个原始UART会话错误。错误后不清poison继续发送，也不扫描数据里的OK尝试恢复；模块可能仍处在等待定长输入或半包状态，后续owner必须负责安全重启／关闭和资源重建。

原始模式下旧 `SendCommandWithData` 对MIPSEND／MIPRD前缀直接拒绝，要求使用专用读写状态机，避免旧提示符标志旁路。普通AT命令仍保留其原有分阶段时限和其他共享状态实现，本批没有宣称全部命令调度和生命周期问题都已解决。

模组没有逐次发送序列号，连接ID＋长度也不能区分所有迟到／重复确认；尤其下一次恰好相同长度的陈旧确认，仍需真实连接owner、ID隔离和固件行为证据。现有草稿的保守锁存减少超时后的复用风险，**不证明任意事件重排都能正确相关**。

## 与上轮接收的关系

接收保留4096字节显式MIPRD上限、96字节数字头、8192字节逻辑RX大小限制、按声明长度消费二进制、尾界和OK检查，以及空缓存只OK处理。读写状态必须互相空闲；缓存通知仍以 `ML307_CACHE_AVAILABLE` 转交owner，不交给旧HEX socket回调。

`MIPSEND` 确认在原始模式被专用发送状态消费，不再让其他旧socket回调误取得该确认。当前正在读写的socket收到disconn时，唤醒等待并停止会话；其他socket状态仍需owner处理。FIFO／接收队列丢段继续在ISR置loss标志，解析和交付前检查，ReceiveTask仍归还DMA租约。

固定4096响应数组和8192逻辑RX限制不包含std::string capacity、返回对象、DMA池、任务栈、TLS和发送者载荷，不能相加当作完整内存峰值。
