# Realtime 发送背压与回合恢复（2026-11-05）

## 问题与保证边界

原 Realtime._send 直接 await cloud.send_json，没有本地发送期限。已安装 aiohttp 3.12.15 的 WebSocketWriter.send_frame 达到写缓冲阈值且协议暂停写入时会等待 _drain_helper，后者没有发送期限。`evidence/realtime-send-backpressure-baseline-20261105.json` 是受控 Event 基线：send 已进入且一直 pending，成功 append 计数为 0，外部取消能传到 send。它证明缺少本地期限，不能称为真实供应商故障或自然唤醒根因。

本轮只修改 gateway.py，不新增云请求、自动重试、后台 close 任务、队列、全局 HTTP 关闭或配置。发送超时可能发生在部分或全部帧已写出之后，不能说明对端没有收到；工具动作也可能已经执行，不能因此重做、回滚、补发回执或自动续答。当前完整唤醒无响应问题仍未定位，本轮是独立的发送稳定性修复。

## 发送所有权与回合终止

RealtimeBackend 每实例增加一个发送锁、一个 sticky 失败标记和公共只读 send_failed 属性。每次 _send 只有一个 5 秒 asyncio.timeout，覆盖等锁和完整 send_json；取得锁后再次核对 connected。锁内发送异常或发送中取消，先把失败标记置真，再释放锁；connected 随即为 false，已排队和后来的发送都不能继续写同一连接，避免不完整帧后续写入。

还没取得锁的外部取消原样传播，不置失败标记、不取消健康 owner。等锁本身超过总期限会抛专用传输错误结束该语音回合，但不假称该等待者已经写帧，也不直接把正在发送的 owner 标记为损坏。若回合收尾随后取消真实写入 owner，该 owner 再按写入中取消规则作废连接。发送成功仍沿原路径增加 append 计数，失败不冒称发送或 ASR 确认。

RealtimeTransportError 只向设备暴露固定安全提示，原始异常通过 cause 和完整堆栈保留，不把底层错误 message 或请求载荷拼入设备 alert。该保证针对设备文案；本地异常日志仍保留原 cause/stack，不能夸大为全部日志都没有底层异常文本。首个 session settings 改为复用 _send；仍先等待 session.created，再加载记忆/发送 settings、等待 session.updated 后才标 ready。原 HTTP total=20、sock_connect=10 和 wait_cloud 的 20 秒期限保持，原 close 的 3 秒总期限保持；5 秒发送与 3 秒关闭是各自阶段预算，不承诺所有其他清理工作也在合计 8 秒内完成。

VoiceSession.connect 遇专用传输错误先完整 await 旧后端关闭，再传播并结束本回合，不自动 fallback；原普通配置拒绝仍沿既有关闭确认和供应商顺序处理。finish_unhandled_control 正常与兜底两个宽 catch、process_tools 业务调用 catch、execute_tool 包装 catch 都优先传播专用传输错误，不把它改写成可继续的本地 unknown 或“解析失败、动作没执行”。原工具身份墓碑保留，已完成动作不重放，尚未执行的同批动作终止。

run 复用原 0.2 秒监督循环读取公共 send_failed，即使独立发送任务的取消已被调用方消费，也会结束本回合并沿原资源清理释放 owner；没有增加轮询任务或定时器。工具入口在屏幕 start 前、start await 后复核失败标记；直接 execute_control_plan 在取得控制锁后、异步计划返回后、每步执行状态反馈返回后复核，错误均在动作 try/catch 外传播。这样阻止失败后尚未开始的动作，不撤回已经开始或完成的动作，也不改既有计划或执行结果。没有 send_failed 或其为 false 的 Chat 路径保持原业务错误合同。
