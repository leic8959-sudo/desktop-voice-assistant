# 任务游标分页（2026-11-05）

管理页面原来固定读取前 30 条任务，忽略 `next_cursor`，第 31 条以后没有入口。本轮单页最多 30 条并替换当前列表，提供“下一页”和“返回首页”；只保留当前及下一游标与页序，不使用无限追加、历史栈、全库总数或 OFFSET。

顶部摘要明确为“本页”，不再把当前页未完成数量描述成全部或今天所有任务。读取中禁导航；失败保留当前页、游标与行内容，在分页状态区说明失败并允许重试。切页会先提醒关闭未提交草稿。创建、完成、取消、改期成功以及改期冲突统一返回首页核对；未知写入结果仍锁定导航，只能显式刷新当前页核对后再次编辑，不自动重发。

列表及写入结果检查认证代数，旧身份结果不触发新身份首页刷新或成功提示；旧 GET 也不能覆盖较新的页面结果。旧在用网关可能给精确末页返回一个多余游标，页面兼容该空页，明确显示“本页暂无任务”，允许返回首页，不误称全库为空。

三种任务写入口登记时立即使此前的列表请求失效，写前已发出的 GET 不能在未知写结果后解除锁。任务写入复用现有 API 封装和统一 15 秒等待期限；创建、完成/取消及改期超时均视为结果待核实，必须重新显式读取当前页后由用户决定下一步，不因请求挂起无限锁住导航或自动重发。

任务写封装还在读取响应后核对 AbortController 状态，避免 HTTP 已返回 200、JSON 正文仍挂起时被全局旧封装吞掉读取取消并误报成功。浏览器回归用本机服务器真实发送 200 响应头和半段 JSON，再触发 15 秒期限，断言仍为结果待核实、只有一次 POST，显式刷新当前页才解锁，没有为测试改变生产超时或服务器。

`AssistantStore.list_tasks` 改为最多读取 `limit+1` 行，仅返回前 `limit` 行，并只在确实存在额外一行时生成下一游标。游标仍取最后返回记录的 due_at/null 和 task_id，排序、状态过滤和设备范围保持原实现，不修改表结构。
