# 原生会话结束状态与占用释放（2026-11-05）

## 实际复现

原 `NativeDevice.run_conversation` 结束时从运行时集合移除会话，并向设备发送 custom idle，但没有同步 `runtime.last_device_state`。因此已经拒绝或结束的语音回合可能在只读状态中仍显示 listening；设备在线与云连接状态不能据此混为是否忙碌。

另一个关联边界是 `start` 创建任务后立即 `end_conversation`：任务尚未首次调度就被取消，协程内的 try/finally 不会进入，运行时会话集合可能泄漏占用。原 end 还在等清理前清空 task 引用，使同一设备可在旧回合发送 idle 的等待期间启动新回合，再被旧 idle 覆盖。

主代理实际执行初始 `tests.test_native_session_idle` 与现有真实 WebSocket 唤醒拒绝用例，共 11 项、1.331 秒、10 个失败、退出 1；日志 `evidence/native-session-idle-20261105-before.log`。包含 API 的 listening 不等于预期待机、未首次调度的占用泄漏，以及清理中启动和锁后所有权场景。没有使用真实云端或设备。

## 最小修复

仅修改 `assistant_runtime.py`。NativeDevice 保存当前 owner 的 session 引用；正常 run.finally 与 end 等待后的未启动兜底共同调用一个 `_finish_conversation` 方法。清理先移除该会话，再进入发送锁，复核 session 和 task 仍属于当前 owner，旧 owner 不能发布待机或清掉新 owner。

当前 owner 结束且没有其他未关闭的实体语音会话时，本地设备状态置 idle；浏览器会话不会阻止实体设备恢复待机，其他仍活动的实体会话保留 speaking/connecting 等真实状态。设备已经断线时只同步本地状态，不向断线 socket 发送；发送失败前已经完成本地待机和占用释放，异常仍传播，不吞错误。

`end_conversation` 保留 task 引用直到取消与清理完成，再对没有进入协程 finally 的 owner 执行幂等兜底；最终只清除仍属该任务的引用。已经完成的任务也可回收，之后可再次启动。没有跨等待持有全局 voice_lock，不建立独立状态机、API 字段或自动重试，不修改门禁、固件或人工决策代码。
