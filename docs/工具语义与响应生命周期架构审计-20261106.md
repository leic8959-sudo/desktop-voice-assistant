# 工具语义与响应生命周期架构审计（2026-11-06）

牛牛要求Luna修复音乐二次关键词门禁、活跃响应被idle关闭，并类推审计全项目工具路径；父代理监督。范围是语义解释与业务校验的职责、上下文、工具身份及生命周期，不重写设备协议或引入agent依赖。

## 真实故障与证据边界

北京时间11:05:18，用户转写“随便来一个放就行了”；19秒进入thinking，48秒idle关闭，没有usage/tts/executing。旧watchdog只有executing_tools排除条件，current_response未保护；旧music_play正则确实不接受该句和“原版”。这两项分别是确定的代码缺陷。

但该现场日志只能证明响应未进入response.done处理，不能证明模型没生成工具参数、正则已经实际执行，或provider卡在哪一阶段。新增response_started/tool_progress/finished/dropped/timeout与tool_started/finished记录响应ID、epoch、输入轮次、generation、工具名、参数字节数/字段名和状态，不记录参数值、密钥或内部推理。没有把“删regex”冒充现场provider停滞已证实根因。

| prose-only控制兜底 | 没有工具调用也可在后台执行动作 | 从response.done移除自动后台规划入口。仅口头答应不再触发动作，system明确没有工具回执不得声称完成。旧execute_control_plan/plan_voice_control保留为兼容内部代码，不在模型/自动响应执行路径使用 |
| 导航 | 模型start_navigation_demo也被关键词拦；已有人工决策要求明确导航演示不要只口头答应 | 模型工具入口去词表、保留非空用户上下文/零参数。原直接dispatch快捷匹配保留，它是有意兼容入口，schedule对同会话幂等，与模型工具复用同一pending，不能启动两次；否定/引用的快捷路径回归保留 |
| 通知订阅/持久任务 | gateway对subscribe/action再做中文语义匹配 | 移除第二套词表；业务层仍核对真实订阅ID/revision、提供商、筛选条件、幂等键/容量。场景预览不执行，管理员确认执行接口保持 |
| 待办/提醒/计时 | 未发现同类中文语义门禁 | 保留真实task_id、updated_at冲突、带时区时间、未来/到期状态、幂等、队列及投递租约。Gmail草稿与任务修改不因此取得发送或任意账号权限 |
| 手动记忆/隐私 | QUESTION含“吗/如何/什么”，正向词表会拒绝“把这个偏好保存一下，可以吗” | 语音仍为manual入口，不新增页面确认。模型理解意图，服务器核对非空真实用户发言、字段类型、敏感资料、value逐字来源、真实device范围内ID/key及一致性；隐私enabled严格布尔。更新/删除假ID或ID与主题不一致拒绝 |
| 自动记忆 | 正则/模型提取有独立来源与范围限制 | 保留只自动偏好/长期事项、不自动个人事实、敏感/临时/问题/引用过滤、evidence与value来源、用户关闭/删除抑制。它是自主采集隐私合同，与用户主动调用manual工具不同；不靠本次音乐修复放宽自动事实采集 |
| Gmail | 原专用工具只有查询/草稿，无发送工具，未发现二次中文NLU | 专用草稿原可语音写保持；发送只走原prepare/confirm，外部邮件不能作为授权。真实草稿版本/确认失效机制不动 |
| generic connectors/workflows | schema声称语音可写/发送并传confirmation_id，但执行实际要求server confirmation_verified | 语音generic context只给READ；schema只承诺只读connector和meeting-travel。逐个manifest核对所有WRITE/SEND/DEVICE_CONTROL都原本requires_confirmation=True，原语音没有可信confirmed，故修正能力宣告，不移除已工作的语音写路径。外发写继续已有prepare/confirm API；model传confirmation_id不能自行确认 |
| 确定性拒绝与不明结果 | generic connector权限拒绝、音乐非法/过期候选发生在调用前，却可能被普通PermissionError/ValueError判作unknown并暂停整链 | gateway先检查真实注册action/scope/confirmation，用已有LocalToolRejectedError/NotAvailable类型表示确定未执行；music候选/字段预检同样typed。实际调用提供商后发生PermissionError/超时仍保持unknown和暂停，不把可能发生的副作用伪装为安全拒绝 |
| Chat上下文 | 工具call/result未进入_history，下轮“原版”丢真实selection | 完整用户轮保存成对assistant.tool_calls/role=tool，按用户轮淘汰，避免从tool中间截断。正常历史20消息目标上限，单轮由4轮×8工具/回复等上限约束；取消或失败保留本轮已返回/未知工具事实和完整前史，不把副作用回滚成未执行，不自动重做 |
| Chat ASR/输出队列 | 满时丢最旧PCM/事件，可能改变指令或丢response身份 | ASR溢出明确报错结束；输出溢出清队列后只发单一error并终止生产，不继续播放无身份帧。进度事件最多每秒一个 |
| 响应watchdog | 30秒idle可关闭current_response；工具/流式细碎事件也可能无限等 | active response、等待created、chat turn、工具、播放队列不算idle；等待创建/无进展45秒、单response绝对120秒、工具执行120秒，达到期限可见错误并清理，不自动重试动作。原会话总时长上限保留 |
| 响应归属/失败 | response.done在晚转写或新输入之间可能混淆身份；failed/incomplete不应执行半截工具 | created记录独立input_turn_serial+generation，同轮ASR晚到只改epoch可合法绑定；新speech-start换serial，旧done丢弃。没有created归属的工具、failed/incomplete/cancelled输出不执行，并给可见反馈 |
| refresh_memory_context | STT后spawn更新Realtime指令，与active response可能重叠 | 增加epoch校验，慢旧请求不回写新输入；记录更新时active response，未认定它导致现场provider沉默。不增加第二模型或伪造session.updated解释 |

人工决策08:13:40的导航直接分流、PC四类允许动作、自动只偏好长期、试听可播放、简短话术均保留原意；本次单模型工具编排/自然选曲补人工决策注释。没有改变完整唤醒词门禁、尾音保护、用户记忆同意、邮件发送确认。
