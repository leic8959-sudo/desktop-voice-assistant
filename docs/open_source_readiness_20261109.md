# 小燕子开源准备评估与执行路线（第一阶段）

评估日期：2026-11-09，Asia/Shanghai。定位：个人／家庭助手优先。本轮只读调查源码、现有交付记录和官方许可资料，只新增规划文档。

## 1. 结论与范围

项目已有相当多的业务实现，可以沿用 Python、模块化单体、SQLite 和现有连接器向产品化推进。但目前适合称为“有历史验收记录的个人原型源码”，尚不能称为陌生用户可直接安装的公开 Alpha。最先要做的是发布物边界与许可清理、可复现安装及显式迁移，再验收浏览器独立使用的核心闭环。

路线固定为 **A 发布基线 → B 可安装产品 → C 核心闭环 → D 公开 Alpha**。主线是日常事务、可管理记忆、可靠家居控制；浏览器是基础入口，ESP32 是可选终端。邮件、协作平台、知识、音乐及电脑动作保留为可选／实验性能力，不扩展为本轮主线。

初期范围是一个所有者、一份受控的数据空间、可配多个终端、单服务实例。多个终端不等于多个独立家庭成员；不能根据声音、终端名称或模型猜测发言人身份。独立成员身份、各自私密记忆、访客和儿童权限后续评估。这里是产品边界，不代表当前源码已经落实。

本轮没有读取真实配置、环境变量值、授权库、私人记忆、运行数据库或录音；没有连接在用网关，也没有重新执行历史测试、安装、构建、服务启动、付费模型、家电控制、固件或账号操作。本文不是完整安全审计或安装通过报告。

## 4. 单所有者、多终端与共享记忆

当前 `adapters/auth.py` 将配置中的设备 Bearer 令牌映射为 `subject="device"`、角色 admin；管理 Cookie 最终也复用该身份。已有端侧配对凭据与撤销机制，不能笼统说“所有终端只能使用一个令牌”，但管理身份和设备身份的职责仍未完全分离。

`AssistantStore` 和自动记忆使用服务配置 `device_id` 作业务范围；多台传输终端不会自然形成多个人的隔离区。初期建议保留数据值和既有分区键，明确把它解释为所有者空间，再单独记录终端身份；先完成映射与迁移设计，避免直接改列名或重写存储。

共享边界建议：同一所有者授权的终端访问同一待办和允许共享的记忆；界面清楚说明“这些终端共享此助手的数据”。不自动将所有家庭成员的发言归入所有者偏好，不通过声纹或模型猜身份。共用房间终端的记忆写入／敏感召回策略须由所有者选择；未决前建议只允许管理端明确保存，房间端不自动提取个人偏好，也不播报敏感资料。独立成员身份以后评估，不先上多租户体系。

一般做法是把“谁管理、哪个终端发起、可执行什么”分开，并在入口收紧权限。可复用现有 Principal、ConnectorContext、配对与确认机制；不需要为一个家庭引入微服务或分布式缓存。单实例仍必须防重复执行、处理超时未知结果；明确禁止同一运行目录启动两个网关，直至有经过验证的互斥与恢复机制。

## 6. 干净环境安装路径：仅静态梳理

下列是从源码推导的操作顺序及阻塞，不是本轮执行的安装步骤。后续真实安装由牛牛授权后在隔离环境进行；依赖安装由牛牛执行。

### 6.1 最小浏览器路径

1. **获取源码与选择平台。** 建议第一条受支持路径为 Windows＋Python 3.12＋浏览器，理由是现有安全存储／电脑能力依赖 Windows；Linux／Docker先列受限预览。仓库尚未提供可安装 Python 包／发布归档，`pyproject.toml` 不存在。
2. **准备依赖。** `requirements.txt` 为 `aiohttp==3.12.15`、`av==19.0.2`。官方 PyPI 和 PyAV 版本文档都写明 av 19.0.2 要求 Python ≥3.12，README 的 3.11+ 不成立。Windows 干净 Python 通常还需 IANA 时区数据；代码直接使用 `ZoneInfo("Asia/Shanghai")`，当前清单没有 `tzdata`，属于待复现的安装风险，不能用现有电脑成功推断陌生环境成功。Web 为现有静态 HTML／CSS／JS，未发现基础页面所需的 npm 构建；Node／Playwright 是开发验收工具，不能强迫普通用户装它们。
3. **创建示例配置。** `tools/init_config.py --lan-ip 127.0.0.1` 可生成随机设备／引导令牌，拒绝覆盖旧文件；LAN IP 模式会把监听设为 `0.0.0.0`。直接复制 example 仍有 `REPLACE`，不能直接启动。只在本地编辑，不把令牌贴入公开问题。`start.ps1` 优先使用 `.venv\Scripts\python.exe`，否则系统 python，只查导入后启动，不自动安装。
4. **配置服务与费用。** 浏览器自然语言入口需要有效模型服务。默认千问；DeepSeek 推理需另配 key，现有浏览器 Chat 连接仍需要阿里语音凭据。模型 ID、区域、空间、额度由本人账号确认。无 key 时管理／手工待办／记忆页面应可用，是待验收目标，不能在未启动前宣布已成立。不要把“有配置”当作授权或连接成功。
5. **显式初始化与迁移：当前阻塞。** `AssistantStore._initialize()`、AutoMemory、Knowledge、Productivity 和管理会话模块都会在构造／启动／连接时创建表；只有项目待办提供 `tools/migrations/project_tasks_20261107.sql`。该 SQL 依赖基础 `tasks` 表，不能直接作为全新空库初始化脚本。需先设计独立、可重复执行的离线 init／upgrade／status 入口，再禁止正常服务自动 DDL。当前没有一条可以如实推荐为“纯显式迁移、然后正常启动”的全新安装命令。
6. **启动与入口。** 现有入口是 `python gateway.py --config config.local.json` 或 `start.ps1`；`/` 提供 index，`/admin` 提供控制台，`/static/assistant.html` 提供个人助手页，API 在 `/api/`，浏览器 WS 在 `/debug/ws`。后台一并初始化可选服务，尚无经过验证的最小能力启动配置。首次启动的写库和调度副作用必须在空目录验证。
7. **本机／局域网浏览器。** 管理端现有本机登录与 Bearer／Cookie；`/api/auth/local-login` 检查 loopback 对端、固定本机 Host、同源及 Sec-Fetch-Site，但该函数没有显式拒绝转发头，不能照搬秘密配置接口的转发头防护结论。部署代理时需专门验证它不能把远端请求伪装为本机登录。LAN 端需明确认证；HTTP 局域网地址通常不满足麦克风安全上下文，远端浏览器语音需 HTTPS/WSS 和正确代理边界。localhost 与 LAN、页面能开与麦克风能用要分别验收。不直接把原型端口暴露公网。
8. **基础功能验收。** 从零手工待办、到期提醒、记忆关闭／纠正／删除，再分别授权短时付费文字／真人语音验收。浏览器关闭／电脑休眠／服务停止时不保证提醒送达；需定义恢复后补交付和“提醒显示／本人确认／已完成”的独立语义。不是安装一成功就推断日常可用。

### 6.2 Docker 与可选硬件

Dockerfile 使用 `python:3.12-slim` 和 `COPY . .`，本轮确认没有 `.dockerignore`。`.gitignore` 不过滤 Docker 上下文；在有本地配置、runtime、下载 SDK 的工作区打包时，存在把它们带入构建上下文／镜像层的风险。现有注释“镜像不包含本地运行状态”不能代替技术隔离。尚未构建／检查任何实际镜像，**没有证据称历史镜像已经泄露**。

`docker-compose.yml` 将端口绑定 loopback，读取 `.env`、只读挂载配置、以 named volume 保存 runtime。但 `.env` 不存在时和 Python 本地入口的环境读取方式不同：Compose 注入环境，不等于 `python gateway.py` 会自动加载 `.env`。新空 volume 不会导入 Windows 的状态；DPAPI 配置／Gmail／续期凭据不能直接在 Linux 容器解密，电脑动作也报告不支持。需明确支持矩阵与秘密存储方案，不能宣布 Docker 与 Windows 功能等价。

ESP32 可选路径：Waveshare ESP32-S3 Touch AMOLED 1.8 对应板型、16MB Flash、PSRAM、麦克风／喇叭及 Wi-Fi；详见工程默认配置和已有硬件记录，不承诺任意 ESP32 通用。需本人准备 Docker／ESP-IDF 5.5.2、串口权限和烧录工具、板型对应恢复备份，再做构建→校验地址／分区／模型→烧录→配对→实机验收。

硬件路径的静态阻塞：`tools/build_firmware.ps1` 同步 main 和顶层配置时没有复制仓库 `dependencies.lock` 到新构建 volume；main 多个组件仍是范围约束，空 volume 可能解析成别的版本。脚本导出的 lock 不能反过来证明初始构建已使用仓库锁。脚本也向被忽略的 evidence 输出日志，新克隆未必有该目录。`flash_native.py` 指向未随仓库分发的 esptool.exe，要求已有完整 16MB 备份；[烧录指南](../evidence/FLASHING_GUIDE.md)在本地存在但不受 Git 跟踪。语音模型分区、首选 mn6_cn／回退 mn5q8_cn、0.3.21 与历史 0.3.23 的发布物需单独确定。本轮没有执行这些脚本。

### 6.3 备份恢复、费用和联网边界

备份须覆盖 SQLite 一致快照及其 schema／应用版本、所有者范围键、授权与配对状态、偏好和用户自备资源；SD memory_snapshot 只是有界缓存，不是权威备份。运行中不能只复制 SQLite 主文件忽略 WAL。DPAPI 材料绑定 Windows 用户／机器上下文，跨机器恢复优先重新授权，不承诺拷贝文件即可恢复。恢复前停写、确认路径与版本，保留新数据，区分程序回退与数据库恢复；当前只有分散维护记录，没有陌生用户可操作且演练过的统一恢复流程。

## 9. 本轮实际检查与交付状态

实际执行的是 PowerShell 只读命令，工具调用中的多条语句仅为批量读取：

- `Get-Location`、`Get-ChildItem -Force -Name`、`Get-Item -LiteralPath ... -ErrorAction SilentlyContinue`；`rg --files --hidden --no-ignore -g AGENTS.md ...`：核对目录和适用规则；初次无匹配的 rg 返回1，表示没有找到文件，不是构建失败。
- `git status --short`、`git status --porcelain=v1`、`git log -5 --format="%h %ad %s" --date=iso-strict`、`git ls-files ...`、`git diff --stat`：核对干净起点、源码提交和受跟踪资源；未执行任何Git写操作。
- `Get-Content <明确源码／示例／文档／锁文件路径>`、`rg -n <模式> <明确源码目录>`：读取本文引用入口、依赖、DDL、认证、调度、构建脚本、测试源码和历史记录；没有执行被读取脚本。PowerShell 对 `tests/test_*.py` 和 `src/assistant_app/integrations/*.py` 的两次参数查询报文件名语法错误，随后改用目录配 `-g '*.py'` 查询，未影响源码。
- `Get-Content tools/font_converter/package-lock.json -Raw | ConvertFrom-Json -AsHashtable`：读取固定 npm 依赖；首次不带 `-AsHashtable` 因空字符串根键解析失败，改用该选项后成功；这是数据读取，不是Node安装或构建。
- `Test-Path -LiteralPath <选定证据／文档／.dockerignore路径>`：确认列出的5份本地历史证据存在；`.dockerignore`、整体LICENSE、pyproject及本轮目标文档在写入前不存在。
- `Invoke-WebRequest -Uri <本附表官方URL> -TimeoutSec 15/20 -UseBasicParsing`、`Invoke-RestMethod https://pypi.org/pypi/{包}/{版本}/json`：只获取公开许可／元数据，不带私人账号凭据、不下载或安装包。ESP-SR GitHub猜测tag、dl_fft版本license页、aiohttp LICENSE-MIT、lv_font_conv猜测tag的原文URL返回404；改用官方固定版本组件页、固定commit、npm元数据或明确标待核实，没有把404推断为无许可。
- 新增本文及第三方清单后，分别执行 `git diff --no-index -- NUL docs/open_source_readiness_20261109.md` 和 `git diff --no-index -- NUL docs/third_party_inventory_20261109.md`：返回1，表示新文件存在差异；检查到两份文档均为整份新增。两份文档各自的 `git diff --no-index --check -- NUL <文档>` 也返回1，没有报告空白错误，只出现Git的LF将转换为CRLF提示，不能把返回1写成检查退出0。普通 `git diff --check` 返回0，但不包含未跟踪文件。`git status --short`仅列出这两份未跟踪文档，`git diff --stat`为空。未为检查diff执行暂存。

没有执行构建、测试、类型检查、预检脚本、安装、服务或设备验证。没有业务代码、配置、规则、依赖、LICENSE变更；没有数据库／网关／固件／OTA／家电／账号写入，没有 Git add／commit／push、上传、发布或可见性切换。公开前全历史敏感检查、许可疑点闭合、干净环境安装、当前服务和真人／实机验收均为后续任务。
