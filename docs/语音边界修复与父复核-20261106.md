# 语音边界修复与父复核（2026-11-06）

牛牛批准按公开实现对照方案实施，并指定 Luna 执行。本轮三项实施/研究子任务均使用 gpt-6-luna，父代理独立检查差异、竞争窗口、全量回归和隔离编译。方案见《最新语音故障公开实现对照与方案-20261106》。本记录区分本地代码、编译候选与设备实际加载。

## 改动

### 手动录音

- NativeDevice 创建会话时即确定 manual；千问初次配置关闭服务端 VAD，确认配置后才放行。原生手动模式当前仅支持 qwen_realtime；qwen_chat/DeepSeek 的现有 ASR 结束机制不提供同样的显式提交合同，因此在建连/ready 前明确拒绝，防止尚未松键就执行。浏览器已有 Chat 路径保留。
- 新能力 `manual_input_ready_v1` 使用独立 `manual_id`，与唤醒早上传协商分开。固件复用同一有界 sender 顺序发送 start、PCM、stop；按钮只发布按下/松开意图，采音 owner 管理录音与结束，媒体暂停回执绑定按钮代数。
- ready 回调以原子数值身份构造局部比较串，只发布 ack token；capture owner 验证当前代后才开启发送，避免读取可并发修改的全局字符串或由旧 ready 跨代放行。
- 手动开始前清理旧 PCM/VAD 与前端 pending，使旧 AFE fetch 代际失效；松键冻结最终 AFE 输出 ring 的 generation、样本位置和字节数，先排空这段已输出 PCM，再发送结束标记。新生成的 PCM 不加入已冻结尾段。溢出、短写、缺帧、代际变化、未知回执归属和超时均保守结束，不提交残缺片段或重放动作。
- 网关按本轮实际成功 append 字节计数，与 stop 字节核对；重复 stop/committed 不重复创建回答。200ms 是本地防误触下限，不是千问官方最低时长保证；短轮清缓冲并提示重录，不补静音凑长度。
- 未决 commit 的取消、10 秒提交回执超时会先同步作废本地 pending/turn/uploading，再结束会话，防监督取消前的迟到 committed 触发回答。松键刷新活动时间，pending 计入活跃状态，避免长录音刚结束就被旧的 idle 计时关闭。
- 固件设置 4 秒 ready 等待、30 秒采集、松键后 8 秒尾部/发送排空期限；超限不自动提交截断指令。它们是本地工程期限，不是上游时延保证。

### 唤醒片段

- 当前实际口令检测是 MultiNet，不是启用的 WakeNet，未获得精确词级起止时间。保留完整“你好，小燕子”验证、纯口令缓存、连说请求和首句超限不执行工具等已有人工决策；未改成任意位置 contains。
- AFE 输出将 VAD 标签与 PCM 同序保存在既有 ring 旁，新增有界 4KiB 标签；同锁读写，帧在标签变化处拆分，输出 generation/sample_index/连续性。溢出、reset、旧 fetch 不得伪装成连续样本。
- 只有连续、有效标签确认 500ms 静音时才裁去已结束旧段，保留最近 300ms 前导，清理旧 MultiNet pending 后保留当前整段人声。没有可靠分隔的连续背景、无效 VAD 等继续保守验证；不承诺所有“前面有其他声音”的口令都会被接受。

### 点歌上下文和试听

- 代码证据证明本地缓存问候没有向云端表达该问候已由设备安排；它是上下文缺口，不能单凭此证明模型当时回答“我在”的唯一根因。
- 千问已查公开 schema 未证实可创建 assistant 文本消息，因此没有照搬 OpenAI 消息格式。使用受支持的 session.update，说明本地独立安排问候、后续输入是新请求；同一事件消费者有界等待确认，保留中间事件，确认后按续话缓存→新音频顺序放行。正常内存上下文刷新继续保留该提示。
- 对歌手＋歌名等省略表达提供上下文说明，同时保留资料咨询、引用、假设、否定/取消的区别。没有新增关键词自动执行器、第二模型复判或漏调用后强行播放。
- 保留平台只有试听时播放试听并告知的既有人工选择。只读确认现有 Music Assistant 2.10.9 / QQ API 0.7.2 的真实整流→TRY 试听降级路径；本轮未查询私人账号或请求新音流，尚不能确定《晴天》整流为空的具体原因。没有把试听权限说成已修复为整首。

## 父复核发现与纠正

保留失败证据，不把不同实现的通过数相加。

1. 独立探针复现：未确认的旧 commit 被取消后，未知旧 item_id 可冒领新轮 pending。先改为结束会话；继续复核又发现抛错与监督取消之间的窗口仍能发 response.create。最终先同步作废可执行 pending，再结束；并发用例保持 cloud_output 活跃后注入迟到回执，确认不创建回答。
2. 独立探针复现：开始时刻 100、松键 129、watchdog 131，旧 last_activity 仍为 100，刚松键 2 秒就 idle。最终松键刷新时间并为 pending 单独设置期限。
3. 媒体暂停入队后才清 ready 存在抢先回执被覆盖风险，已改为入队前发布等待状态，并校验按钮代数。
4. 只排空 sender 仍会丢掉最终 AFE ring 内尚未 read 的 PCM，已增加原子快照和有限尾段排空。
5. 首轮全量 659 项中 1 项错误：自动记忆的迟到转写夹具仍使用 20ms 录音，正确被新短录音规则拒绝。备份原测试后改为有效 300ms，保留原超时，不降低产品阈值；本用例继续验证迟到转写入库。
6. 第二轮全量 661 项有 1 失败/2 错误，记录另存 `evidence/voice-boundaries-parent-regression-concurrent-build-failure-20261106.log/.json`。其中一个媒体网关测试绕过构造器创建 VoiceSession，遗漏新增 pending 字段，已补齐真实对象形状。两个媒体时序失败在停止编译后仍可复现，不能归因为编译压力：实测首个 1 秒 progress 可在首 PCM 前合法报告 0；0.05 秒源循环 4 次会启动 4 个真实 PyAV 子进程，探针一次耗时 7672ms，接近原 8 秒测试期限。保留原超时和精确内容/位置断言，将屏障改为实际正进度；循环夹具改为 0.15 秒源、总预算仍为 0.2 秒，检验完整首遍和截断第二遍。没有改媒体生产代码或简单延长超时，计时证据在 `evidence/media-decoder-timing-gateway-check-20261106.json`。
