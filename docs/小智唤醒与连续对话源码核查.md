# 小智唤醒与连续对话源码核查

核查日期：2026-10-29。对照固定版本`78/xiaozhi-esp32 v2.5.2`，不是未核实的产品宣传。新增下载的源码、原始URL和SHA-256保存在`evidence/xiaozhi-review-v2.5.2/source-manifest.json`。本轮只读核查与保存文档，没有重新烧录或启用电脑唤醒。

## 结论

小智已有板端自定义唤醒词实现，可以使用中文拼音注册口令，不必先改用电脑或云端识别。应优先对齐其完整采音和识别链路，再验证“你好，小燕子”。仅看到模型启动，不能算唤醒成功；当前自有固件仍未通过真人唤醒验收。

小智在ESP32-S3上的关键实现：

| 环节 | 源码行为 | 对自有固件的意义 |
|---|---|---|
| 固定唤醒 | AFE配合WakeNet，使用预训练口令 | 与自定义口令分开选择 |
| 自定义唤醒 | `CustomWakeWord`配合MultiNet，中文使用空格分隔拼音 | 可以配置`ni hao xiao yan zi` |
| 自定义阈值 | Kconfig默认20%，类默认0.2，资源包可覆盖 | 当前曾用0.9、诊断用0.5，均高于小智默认；仍需实测命中与误唤醒 |
| 处理器 | S3默认240MHz | 当前160MHz是实时预算差异之一，不代表唯一根因 |
| 语音SDK | ESP-SR 2.4.7 | 自有固件目前2.0.0，接口和模型行为不能假定完全相同 |
| 采样转换 | `esp_ae_rate_cvt`执行硬件采样率到16kHz的转换 | 自有固件当前抽点转换不能视为等效实现 |
| 任务划分 | 采音任务与AFE处理任务分开，输入帧10ms | 不宜将高耗时识别直接阻塞在持续采音路径 |
| 自定义输入 | AFE的fetch输出通过`FeedMono`送入MultiNet | 应对齐前端和分帧，不只抄命令词注册 |
| 唤醒缓存 | 支持缓存、编码和发送唤醒词附近的音频 | 降低唤醒后语音头部丢失，允许服务端作出唤醒响应 |

AFE不是“自动具备全部降噪和回声消除”。核查版本明确关闭NS，AEC是否启用取决于输出参考等硬件条件；不能把接上AFE写成已解决远场、回声或自然插话。

## 连续对话

小智区分`manual`、`auto`和`realtime`。`GetDefaultListeningMode()`在AEC关闭时选择`auto`，有AEC时选择`realtime`。收到TTS结束时，手动模式返回待机，自动/实时模式返回倾听；自动模式还等待播放队列排空，避免语音尾部被截断。

因此“唤醒一次，不长按，轮流连续聊天”可以独立实现，并不要求先解决全双工AEC。“助手说话时随意插话”是另一项能力。当前Waveshare AMOLED 1.8 V2不在所查配置的设备AEC板型列表内，实际声学能力也未验收。

## 静默待机

端侧在音频通道关闭后切回Idle，关闭语音上行处理并重新启用唤醒检测。所查`Protocol::IsTimeout()`有120秒未收到服务端消息的通道超时；这是连接活性判断，不能解释成“用户沉默120秒”。本次没有核查小智服务端实现，不能给其业务静默时长下结论。

自有桥接仍按已配置的30秒有效活动超时处理。需用静音输入、持续回复及待机后再次唤醒三个路径验收，不能每收到PCM包就延长会话，也不能在正常播放时提前结束。

## 后续实施顺序

1. 保持设备端自定义唤醒方向，清理临时启动诊断，区分测试配置与正式配置。
2. 对齐CPU、采音与AFE任务、重采样和模型配置；不要只降低阈值。
3. 先验证标准正样本能命中、普通句子不触发，再验证真人近距离和实际桌面距离。
4. 通过后串联自动对话、30秒无有效活动待机、再次唤醒；同时检查点云帧率和语音缺帧。
