# 虫洞 BOX 双触摸路径接入与 2.8 版构建

后续更新：虫洞BOX3.5已完成首次完整缓存构建，使用核对过的ST7796默认初始化及SDK DCS操作；BOX2.8与LilyGO回归通过。GT3.5的+80坐标偏移及实机验收仍未完成。见[本批记录](chd35_st7796_sdk_20261112.md)。

本批推进已有 `chd-esp32s3-box`（2.8版）完整终端候选，复用现有 `Gt911Polling` 接入可选GT911，同时保留FT6336正式组件。共享源码也覆盖 `chd-esp32s3-box-lcd35`，但3.5版仍缺ST7796 1.3.5，不能据2.8构建或单文件编译给它记整板通过。

## 探测与指针生命周期

原探测顺序不变：I2C1先FT0x38，只有NOT_FOUND才试GT0x5D，再只有NOT_FOUND才试GT0x14，每次probe100ms。全部NACK才按原可选硬件语义继续无触摸／BOOT卡片；其它总线错误、已发现设备的初始化失败都停止本次启动，不切换驱动掩盖故障。

CHD固定源码和现有配置中RST／INT均为NC；轮询不操作任何GPIO，不借用4B的扩展口复位，也不借用Guition的IRQ选址流程。已选地址交给现有panel IO，GT用16位命令、FT用8位，均400kHz，本批明确设置每次IO100ms；完整poll可能有多次传输，不能称总100ms。

原通用GT911使用 `g_touch` handle，native轮询则不创建该handle，因此只判断旧指针会漏建GT触摸pointer。本批以“FT handle存在或GT轮询Init成功”判断实际已初始化触摸，应用于pointer创建、分配失败和重复进入显示初始化的结果。仅探测过GT、或全部NACK而留下的选择标志，不会被当成初始化成功。

## 坐标与输入状态

| 控制器／屏幕 | 保留的raw到画布变换 |
| --- | --- |
| FT 2.8 | `(y,x)` |
| FT 3.5 | `(y,319-x)` |
| GT 2.8 | 先rawX+80，再按320宽镜像／换轴，结果`(y,239-x)` |
| GT 3.5 | `(y,x+80)`，原可见Y=80..319限制保留，未声称全高标定完成 |

GT保持有符号中间值，变换后检查真实显示范围，不做uint16回绕或夹取有效坐标；FT先校验raw范围再变换。两条输入路径均在初始、读取错误、多指或越界后等待真正零点释放，INDEV_RESET取消原动作，恢复后的按压不直接接回旧点击。

GT完整保留轮询器最多五点的count、状态／payload／ACK检查；健康not-ready只能使用上次已确认快照，首次未知或失败后not-ready不算松手。FT仍调用已安装FT5x06组件，但读取最多两点以发现普通多指，不再将多个点通过单点视图截成一指；读取错误后也消费点缓存，主结果仍保持错误。通用FT组件对保留事件／畸形点数的所有边界未在本批补齐或验收，不将两点视图等同原始协议错误注入覆盖。

共享GT轮询器源码、两板屏控与原命令表、音频、PA46、BOOT0、模型、AFE／AEC、完整唤醒、自然插话／媒体人工决定、绑定／NVS／双OTA均保持原文。BigSmart和立创的各自触摸分支不改变语义，另作完整回归。
