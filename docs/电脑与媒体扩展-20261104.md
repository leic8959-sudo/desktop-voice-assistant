# 电脑与媒体扩展（2026-11-04）

本轮新增独立模块，不修改设备固件、凭据文件、设备绑定或既有连接器。所有已实现动作均尚未做本机或真实账号验收；没有实际锁屏、打开应用、发媒体键、播放声音或向 Google / Microsoft 发请求。

## 接入合同

- 应用层：`src/assistant_app/application/desktop_actions.py` 的 `DesktopActionsService(config, store, runtime, http)`，`await start()` 只加载本地 DPAPI 并建立媒体协调任务，`await close()` 停止本模块音轨并清理临时白噪音；不会构造时访问第三方。
- API：`src/assistant_app/api/desktop_actions.py` 导出 typed `DESKTOP_ACTIONS_KEY` 与 `register_routes(app)`。必须先加载既有 `api_boundary`、管理员会话、审计及 `ConfirmationStore`，再将服务放入 app 并注册扩展路由。
- 页面：`/static/computer.html`；依赖既有 `admin_console.css`、`console_api.js`。共享 HTTP 客户端需支持 `request(path, {method, multipart: FormData, timeout})`，multipart 时不添加 JSON Content-Type。全局请求容量应至少16MiB，单文件仍限10MiB。
- `tool_schemas` 是 OpenAI 风格的 function schema；`invoke(name, args, subject='voice')` 对读状态立即返回，对任何变更始终只给预览与 `confirmation_required`。`subject`、自然语言“确认”、模型参数均不能替代服务器凭证。
- 只有 API 在消费同一管理员、同一动作、同一规范参数的一次性凭证后，才调用 `execute_confirmed(..., confirmation_verified=True)`。确认可重放原结果，不重复执行，进程重启后失效；按单实例使用。

## 实现范围与实际含义

固定允许列表：计算器、记事本、资源管理器；系统目录由 Windows API 取得，不接受用户命令、命令参数或可执行路径。通过 `ShellExecuteW` 请求打开固定应用，不启动 shell 子进程。打开与锁屏只报告 Windows 已接受请求，未读取窗口状态。媒体键支持播放/暂停、上一首、下一首、静音和音量增减，音量按 Windows 步长调节，最多20步，不声称知道当前音量百分比或播放器曲目。

本地媒体使用 Python 标准库生成 PCM 白噪音，Windows `winsound` 异步循环播放。用户音源必须从当前页面明确选择并上传；不连接付费音乐账号、不爬取曲库、不接受URL或服务器文件路径。支持用户自备 WAV、MP3、OGG、FLAC、M4A，每个原始文件最多10MiB、最长30分钟，源采样率8～48kHz、1～2声道；WAV继续兼容16bit PCM。压缩格式复用项目既有 PyAV（requirements中的av==19.0.2），本机流式转换成24kHz、单声道、16bit PCM WAV，转换后最多90MiB。缺少PyAV或冻结可执行程序无法启动固定解码模块时，压缩格式明确不可用，不降级为虚假上传成功。播放项按1～240分钟的定时长度循环；队列最多8项，空闲时确认加入队列会立即开始，已有音轨时顺序等待，定时结束后自动下一项。开始/替换不清空既有队列；停止会停止本模块音轨并清队列。

播放通过服务所在电脑的默认音频输出，网页不播放音频。暂停使用真正的 `PlaySound(None, 0)` 停止输出并保存剩余时长；继续从音源开头播放剩余时长。`runtime.voice_sessions` 只要存在未关闭会话，或 `runtime.proactive_speech.active` 为真，就拒绝开始/继续；协调任务每100毫秒检查一次，新对话或主动播报开始后暂停本地音轨，不自动恢复。该轮询无法保证0毫秒音频重叠，且不控制用户在其他软件启动的音乐。系统媒体键与本模块播放为两种入口，前者作用于 Windows 当前媒体接收者。

上传先计算原始文件 SHA256，再生成预览，确认后校验原始文件名/大小/摘要；服务器只写随机 UUID 文件名，忽略上传文件路径，不允许路径穿越。压缩格式由固定Python模块在无shell、Windows CREATE_NO_WINDOW子进程中转换，显式45秒超时，超时终止并等待进程退出。HTTP请求取消后会shield等待转换任务真正退出，再清理占用文件。av.open主输入是已确认上传文件的只读file对象，按后缀固定mp3/ogg/flac/mov解复用器，protocol_whitelist=file,pipe，并用io_open回调拒绝所有额外本地或网络打开；M4A禁用外部数据引用。仅选一条音轨，拒绝超过4条流，按后缀限制MP3/Vorbis/Opus/FLAC/AAC/ALAC编码，不解码封面视频。每个压缩包最多1MiB、最多20万个包/帧、单帧最多262144样本，解码与重采样均逐帧写临时WAV；同时按实际样本硬限30分钟和90MiB输出，不依赖不可信时长元数据。只有完整转换、WAV校验、转换后库容量核对全部成功，才原子替换为正式音源；异常与取消清理原始/转换临时文件。音源数量最多32项，按转换后WAV统计总容量200MiB；临时上传、转换产物和白噪音崩溃残留超过24小时在启动时清理。正式音源无自动删除入口，满额时由服务管理员维护媒体目录。上传锁独立于播放锁，慢速上传或转换不会阻塞语音暂停。媒体状态与队列为有界进程内状态，不跨重启或多实例同步。

## API

| 方法与路径 | 行为 |
| --- | --- |
| GET `/api/computer/status` | 本地媒体、允许列表、OAuth配置状态；不访问第三方 |
| POST `/api/computer/actions/{action}/prepare` | `{arguments:{...}}` 返回真实预览、规范参数、一次性凭证和到期时间 |
| POST `/api/computer/actions/{action}` | `{arguments:{...},confirmation_token}` 消费凭证后执行 |
| POST `/api/computer/media/upload` | FormData 按顺序包含 metadata JSON 字符串、file；metadata包含预览返回的arguments与confirmation_token |
| GET / POST `/api/computer/oauth/{provider}/config` | 只读脱敏状态 / `{values:{...}}` 安全保存；空白保留 |

`action`：`desktop_open_app`、`desktop_media_key`、`desktop_volume`、`desktop_lock`、`media_play`、`media_pause`、`media_resume`、`media_stop`、`media_queue`、`media_clear_queue`、`media_upload`（只走上传专用执行接口）、`oauth_refresh`。不存在任意 shell 或任意文件接口。

## OAuth 续期与既有适配器

`src/assistant_app/integrations/token_refresh.py` 的 `TokenRefreshService` 复用现有 `DpapiTokenVault`，写独立 `runtime/calendar-oauth.dpapi`，无 Windows DPAPI 时不降级明文。仅支持 `google_calendar`、`microsoft_calendar`；微软邮件和日历共享后者。配置字段为提供商前缀加 `client_id`、`client_secret`、`refresh_token`、`access_token`、`expires_at`、`tenant_id`；到期时间必须带时区，内部转换UTC。元数据只回显非秘密字段，所有 Token 与客户端秘密不回显、不写前端持久存储。由环境变量管理的提供商不会被本模块覆盖，必须在维护窗口解除环境覆盖后使用可轮换的本地配置。

调用者通过 `service.token_refresh` 获取实例。父层为 Google Calendar、Microsoft Calendar、Microsoft Mail 的构造器添加可选 `token_service=None`，在每次 `_request` 读取 Bearer Token 前调用：

```python
if self.token_service is not None:
    token = await self.token_service.ensure_access_token('google_calendar')
else:
    token = self.config.get('google_calendar_access_token', '')
```

微软两个适配器都使用 `'microsoft_calendar'`。也可在父层 `initialize_extensions` 之后给既有注册实例设置 `connector.token_service = service.token_refresh`。有效期剩余大于90秒直接返回现存Token；到期或未知到期且具备Refresh Token时串行向官方Token端点刷新，超时20秒，禁止重定向，响应上限64KiB，保存轮换后的Refresh Token成功后才更新内存。一个提供商一把锁，另有DPAPI文件锁防止两个提供商覆盖彼此。不存在账号凭据时明确报未配置；旧的仅Access Token配置继续沿用原Token交由原API判断，不声称完成续期。不要自动重试业务写请求，避免重复创建日历事件或发送邮件。

页面还提供 `oauth_refresh` 的真实预览确认入口。配置保存与刷新成功不代表日历权限、邮件权限或账号身份已经验收。Refresh Token若被提供商轮换而本地保存失败，后续可能需要重新授权；不能把网络成功推断为凭据持久化成功。当前不提供授权码回调/新账号登录流程或多用户身份系统。

## 检查与状态

本轮仅执行 PowerShell `Get-Content`、`Get-ChildItem`、`rg` 等静态读取并检查新增源码。`git status --short` 返回“not a git repository”，因此没有可报告的Git diff，也没有Git写操作。按照当前规则没有运行测试、构建、类型检查、AST/编译命令或长期服务，没有安装依赖，没有上传、部署或发布。Windows实际应用启动、音频输出/暂停、锁屏、Token真实刷新和账号权限仍需牛牛明确安排的验收。
