# 自有桌面助手 V1：交付与验收

日期：2026-10-29，Asia/Shanghai。

## 目标和本轮边界

本轮开始建立自有系统，先补齐聊天之外的个人事务，再替换终端固件。当前设备仍保留已烧录的小智 v2.5.2；新固件未经 ESP-IDF 编译、实机音频和显示验收，不直接烧录。

“赶上小智”不能仅按功能名称判断。本项目的首版比较基线是：配网、本地唤醒、实时语音、按键打断、连续对话、屏幕反馈、断网恢复、受控工具。长期记忆、独立提醒、可管理的个人事务是本项目重点增加的能力；完成这些代码不代表已经超过小智所有产品或达到可销售状态。

## 文件入口

- `gateway.py`：千问接入、兼容小智 Opus、浏览器音频、自有 PCM 终端。
- `assistant_core/store.py`：个人事务与记忆数据库。
- `assistant_core/tools.py`：语音工具契约。
- `assistant_runtime.py`：常驻终端、提醒分发、运行状态。
- `control_api.py`：面板 API 与鉴权。
- `home_control.py`：家居平台边界。
- `web/`：原生 HTML/CSS/JS 面板，无新增前端依赖。
- `firmware/assistant_espidf/`：自有固件源工程。
- `docs/firmware_v1.md`：板卡、构建与设备协议细节。

## 已有设备如何继续使用

Windows 桥接地址仍为 `http://192.168.3.8:8765`。配置继续使用 `config.local.json`，密钥未复制到固件或静态页面。原型电脑必须开机、不休眠。

网页从电脑打开 `http://localhost:8765`。连接面板填本地配置中的 `device_token`；这个操作只认证管理 API，不建立云端语音会话。点击录音或发送文字才打开语音连接。

已安装的小智终端继续使用 `/xiaozhi/v1/`，可调用新的个人事务工具，但不能获得新固件的任务卡和常驻提醒通知界面。自有终端使用 `/device/v1/`。

不要将阿里 API Key 填入 `device_token`；两者用途不同。也不要把 `config.local.json` 或数据库导出到公共目录。

## 自有协议概要

连接 `/device/v1/`，请求头 `Authorization: Bearer <device_token>`。首帧：

```json
{
  "type": "hello",
  "version": 1,
  "transport": "websocket",
  "audio_params": {
    "format": "pcm_s16le",
    "sample_rate": 16000,
    "channels": 1,
    "frame_duration": 20
  },
  "features": {"custom_ui": true}
}
```

服务端返回输出 `pcm_s16le`、24000Hz 单声道及 `custom.state=idle`。控制连接持续存在，空闲不建立模型会话。设备唤醒后发送 `listen/start`，再上传 16kHz PCM 二进制帧；服务端输出 24kHz PCM。`abort` 清理当前回答；`session_end` 结束语音回合，保留控制连接。

`notification` 含 id/title/due_at/lease_token；设备实际显示成功后回 `notification_ack`。超时不确认由租约恢复，允许重复投递，设备可按 id 做展示去重。提醒确认仅代表展示交付，不代表用户完成待办。

`memory_request` 的 request_id 最多64字符；`memory_snapshot` 是最多约5KB条目加协议封装的缓存，含 partial 标识，不代表全部长期记忆或离线完整个人助理。

## 固件构建阻碍及安装步骤

当前主机没有 ESP-IDF、CMake、Ninja，也没有现成的 ESP-IDF Docker 镜像。按牛牛的依赖安装规则，本轮没有自行安装。

由牛牛通过 [ESP-IDF 官方 Windows 安装说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/get-started/windows-setup.html)准备 ESP-IDF 5.5.5 及对应工具链。然后在 ESP-IDF 终端执行：

```powershell
cd 'I:\new find\desktop_voice_assistant\firmware\assistant_espidf'
idf.py set-target esp32s3
idf.py build
```

构建会按 `main/idf_component.yml` 下载托管组件和模型资源。出现依赖解析冲突、API 差异、模型超过分区时，先修源码和分区，不使用强制烧录跳过。

需要验收的产物：bootloader、partition-table、应用、语音模型，以及构建自动生成的 `flash_args`／`flasher_args.json`。不能把 `app.bin` 当完整镜像写到0地址；按构建给出的地址执行。

本轮不提供“已编译成功”的声明，也不以源码扫描替代固件编译。安装环境后，依次做构建、资源校验、保留现有备份、实机刷写和功能验收。

## 必须完成的实机检查

1. 屏幕和触摸、中文字体、状态卡、待机省电。
2. 本地唤醒、连续对话、按键打断、断网恢复。
3. ES8311 播放采集、24k时钟与16k上行转换；无AEC时不承诺自然双讲。
4. SD快照失败恢复，缺卡仍可对话，partial 缓存有明确边界。
5. 无语音会话时到期提醒，展示成功才确认；重启和掉线后恢复。
6. 真实家电动作与平台回报分开确认。
7. 30轮连续使用及24小时待机，记录延迟、误唤醒、内存和费用。
