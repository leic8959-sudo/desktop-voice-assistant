# 唤醒与打断：开源复用核查

核查日期：2026-10-30。只读检查公开仓库指定提交，未下载大型仓库、未安装依赖、未修改固件。

## 1. LiveKit Agents：可复用的是“中断句柄”语义

来源：LiveKit Agents `main`，提交 `11c8ad8d74c272cf046e65d83cfe7be46abaec64`。

- [speech_handle.py](https://github.com/livekit/agents/blob/11c8ad8d74c272cf046e65d83cfe7be46abaec64/livekit-agents/livekit/agents/voice/speech_handle.py)
- [agent_activity.py](https://github.com/livekit/agents/blob/11c8ad8d74c272cf046e65d83cfe7be46abaec64/livekit-agents/livekit/agents/voice/agent_activity.py)
- [许可证](https://github.com/livekit/agents/blob/11c8ad8d74c272cf046e65d83cfe7be46abaec64/LICENSE)：Apache-2.0

`SpeechHandle.interrupt()` 通过 future 发出一次性中断信号，保存 `allow_interruptions`、中断来源，并给未结束任务最多 5 秒完成；超时才取消内部任务。`AgentActivity` 另有 VAD/自适应插话、false interruption 暂停后恢复和可取消工具任务的状态管理。

这套代码依赖 LiveKit 的 RTC、STT/VAD、TTS、LLM 任务调度和 Python 事件循环，不能直接部署到 ESP32，也不能直接替代当前 Qwen WebSocket 协议。可借鉴的边界只有：一次中断令牌、旧播放代次失效、区分真实用户插话与误判后恢复。当前 `control_protocol.cpp` 的 generation、`gateway.py` 的 `cancelled_playbacks`/`response.cancel` 已覆盖相同原则；不应重复引入整套 LiveKit 服务。

## 2. ESP-Skainet：可复用的是板端 AFE/WakeNet 调用顺序

来源：ESP-Skainet `master`，核查时分支提交 `97885d425d951b41a50747e2c33743d0e233a3e3`。

- [WakeNet 直接调用示例](https://github.com/espressif/esp-skainet/blob/97885d425d951b41a50747e2c33743d0e233a3e3/examples/wake_word_detection/wakenet/main/main.c)
- [AFE WakeNet 示例](https://github.com/espressif/esp-skainet/blob/97885d425d951b41a50747e2c33743d0e233a3e3/examples/wake_word_detection/afe/main/main.c)
- [示例说明](https://github.com/espressif/esp-skainet/blob/97885d425d951b41a50747e2c33743d0e233a3e3/examples/wake_word_detection/afe/README.md)
- [许可证](https://github.com/espressif/esp-skainet/blob/97885d425d951b41a50747e2c33743d0e233a3e3/LICENSE)：Espressif MIT License

直接 WakeNet 示例的机制是：`esp_srmodel_init("model")` → `esp_srmodel_filter` → `create` → `get_samp_chunksize` → 分块 `detect`。AFE 示例则把 `get_feed_chunksize` 与输入通道数相乘，独立 feed task 调 `feed`，独立 detect task 调 `fetch`，在 `wakeup_state == WAKENET_DETECTED` 时处理结果。当前固件已有独立采音/AFE/feed/fetch 任务，调用形态与该示例一致。

该示例面向 WakeNet，不包含当前“你好，小燕子”自定义 MultiNet 命令图，也不提供 Qwen 会话取消协议。因此它适合核对 AFE 线程与 chunk 边界，不能直接解决当前中文 MultiNet 真人漏唤醒。

## 3. 结论

- 可直接复用：LiveKit 的中断状态原则、ESP-Skainet 的 AFE feed/fetch 任务结构和生命周期顺序。
- 不宜直接引入：LiveKit 整套实时 Agent 服务；它与 ESP32+Qwen WebSocket 协议、当前网关状态机不兼容。
- 当前项目已有两阶段插话候选/确认协议；公开源码没有同等本地阈值可直接替换。后续应由 root 结合现有现场日志验证 generation、播放 ID 清理和 AFE 前端链路。
