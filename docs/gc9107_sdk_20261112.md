# AtomS3R 底座／Magiclick 2.5 专用屏幕路径构建

后续更新：本页保留两次Magiclick失败的历史记录；其原始DSP编译命令后续重放成功，未改源码／依赖／优化，完整IDF/Ninja再次编译该文件并完成首次整板构建。GCC崩溃根因仍未知，最新证据见[恢复记录](magiclick_gcc_recovery_20261112.md)。

本批推进 `m5stack-atoms3r-echo-base`、`m5stack-atoms3r-echo-pyramid`、`magiclick-2p5` 三个已有源码入口。它们此前缺GC9A01组件，自身尚未编译；这次复用SDK公共DCS操作，保留原GC9107专用命令与屏幕识别，移除三板的外部GC9A01依赖。没有套用上批默认42命令圆屏表。

## 两套命令与识别

| 分支 | 保留的初始化 | 识别与方向 |
| --- | --- | --- |
| AtomS3R Echo Base／Pyramid的GC9107 | 原19命令、两条14字节gamma、零长度FE／EF；SLPOUT100ms、BGR08、COLMOD55 | 原三线SPI读ID选择，未知ID停止；两底座各自镜像／gap／LP5562背光保持 |
| Magiclick 2.5A的GC9107 | 原24命令、两条14字节gamma；SLPOUT100ms、RGB00、COLMOD55后按表覆盖05，像素缓冲仍16位 | 原ADC1 channel2取样与阈值选择；中间未知区间停止，RGB、不镜像、gap0、低有效PWM保持 |
| 两系列ST7735修订 | 继续原ST7789兼容默认驱动，不使用GC9107回调 | 各自原ID／ADC选择、反色、镜像和gap不变 |

两份既有命令头文件均未改动；编译期检查其有效载荷、无MADCTL覆盖及预期COLMOD值。GC9107回调只替换原GC9A01适配器的一次板级启动序列，不调用SDK默认ST7789初始化，避免额外RAMCTRL写入。硬件复位10／10ms、软件复位20ms、DCS窗口和像素长度复用相同行为的SDK操作。原GC9A01无sleep／brightness回调，继续置空，保留板级LP5562／PWM控制。

该接入覆盖既有owner的一次启动；没有提供在外部任意修改mirror／format后重复初始化的通用驱动契约，错误后也没有新增自动重试。Magiclick的COLMOD05保留为原线上命令，而16位帧缓冲大小沿原工厂保持；这不是对真实面板像素格式的实测。实际两修订仍需分别验收。

## 保留的板级行为

Echo Base仍使用8MB／Octal PSRAM、I2C1／ES8311的BCLK派生时钟和PI4IOE43 P0功放门控。Pyramid仍使用独立Si5351／STM32／AW87559及ES8311＋ES7210路径，保留外部6.144MHz时钟参数、锁定检查、STD2帧与MIC1采集、实际静音回调后开PA。没有因为都用AtomS3R而合并音频底座。

Magiclick仍保留自己的24kHz ES8311、PA4、按键21／47／0、LED39和未启用模组40的原状态。原按键、绑定、提醒、完整自定义唤醒、AEC、自然插话、媒体和双OTA源码未改。

无PSRAM的 `m5stack-atoms3-echo-base` 保留独立的GC9A01依赖和现有手动语音候选，本批不构建它，不将其登记成完整唤醒／AEC适配。其内部RAM完整语音和Opus取舍仍未解决。

## 执行与来源

证据位于 `evidence/gc9107-sdk-20261112/`：三个新目标分别为 `echo_base/`、`pyramid/`、`magiclick/`，另以 `freenove/` 保存共享显示文件默认分支回归。新目标使用新stage、现有SDK5.5.6-dirty／Xtensa14.2.0、17份现有本地组件override和Python外网保护，各设置两个构建任务。没有下载或安装组件。

实际入口是每个目标目录下 `build_cached.py`／`collect_build.py`，以及本批 `inspect_sdk_limits.py`、`finalize.py`。完整板型参数、工作目录、命令、退出码和输入／产物摘要逐板保留，不把一板或空入口工程当作三板通过。

| 实际目标构建 | 结果 |

| `idf.py -DIDF_TARGET=esp32s3 -DASSISTANT_BOARD=m5stack-atoms3r-echo-base build` | 退出0，应用2246496字节、模型2203819字节；8MB内双2688KiB OTA及2304KiB模型分区核对通过 |

三个成功目标各271项当前输入、24份产物快照；实际readelf／nm／size、esptool及分区解码退出0，项目身份、checksum／validation hash、分区容量和来源核对通过。AtomS3R两板分别保留真实底座功放／亮度／识别入口，Pyramid还保留ES7210和独立时钟板级init，不能互相替代。

Magiclick两次完整失败日志均保留，未改库源码或优化选项、未复制另一板object绕过编译。用其真实compile_commands参数单独编译当前 `waveshare_spi_display.cpp`、`main.cpp`、`audio_io.cpp`，三项退出0，只证明这些编译单元可编译，不能代表最终链接。另以原编译参数预处理Magiclick和成功EchoBase的DSP文件，函数定义部分文本一致；这不解释寄存器分配失败的根因，不能据此称是内存不足或工具链已修复。

第一次调用重跑包装脚本时仍引用了模板的Freenove成功记录，前置断言在启动IDF前停止；纠正为Magiclick真实失败记录后才执行1job重跑。这个包装脚本错误与两次真实构建失败分别记载。当前Magiclick仍登记为failed_cached_sources，不将对象编译或两款AtomS3R通过转写成它的整板成功。
