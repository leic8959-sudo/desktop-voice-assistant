# 自然插话：公开实现参考与小燕子方案

核查日期：2026-10-29。范围是公开源码和官方开发文档；没有修改运行代码、调用云端模型或烧录设备。OpenAI Realtime API机制不等同于ChatGPT客户端内部实现；小智按v2.5.2固定版本核查，其余按本次访问的公开文档/源码。

## 参考实现

| 实现 | 核查到的具体机制 | 应借鉴的部分 |
|---|---|---|
| 小智v2.5.2 | AEC关闭时默认auto，有AEC时选realtime；自动模式回答结束回到倾听；采音、AFE和播放分工，硬件参考条件影响AEC启用 | 设备音频任务、状态和能力门控；不能把全部小智板型都当成已支持自然双讲 |
| WebRTC Audio Processing Module | 采音输入`ProcessStream`；实际渲染流输入`ProcessReverseStream`；示例设置`set_stream_delay_ms`；建议APM靠近音频硬件HAL | 使用实际播放参考，管理延迟和双流时序。软件PCM参考合法，不要求必须硬件回采；放到电脑并不会自动修好远端ESP32的播放时序 |
| LiveKit Agents | 支持语音持续时间、识别词数门槛（需STT）、自适应插话判断；VAD检测后没有转录可判误触发；支持误触发后从中断处续播 | 区分候选/确认，保存续播位置。语义插话判断与AEC负责不同问题，不能取代回声消除 |
| OpenAI Realtime API | VAD事件可以触发中断；WebSocket客户端须停止本地播放并记录实际已播放位置，再用支持的事件截断对话历史；WebRTC/SIP服务端管理输出缓冲并自动处理未播放部分 | 分开取消生成、清除实际播放、同步历史三件事；云端生成完毕时本地仍可能在播，不能只发送cancel |

LiveKit文档特别说明：Realtime模型使用服务端轮次检测时，部分插话参数可能不适用。不能直接给千问套用某个LiveKit参数就断言生效，需要核实当前千问协议与客户端可控制范围。

## 当前小燕子和参考实现的差距

0.1.7为解决回答被截断，播放期间只识别完整唤醒词，其他上行PCM清零；这是任意内容不能打断的直接原因。初版仅凭VAD连续8帧就取消回答，残余回声导致助手打断自己，因此已经撤下。

当前软件AEC已接通且有参考数据，播放测试无欠载，但还没有同步麦克风/播放参考/处理后音频来验收回声减量。现有混合时间窗RMS不能直接当ERLE。

还缺少独立的插话候选状态、误判续播、明确的实际播放位置、插话首部缓存和云端上下文协调。云端知道“用户开始讲话”，也不代表它能区分设备自身扬声器残余回声。

## 建议采用的组合

### 1. 设备端参考WebRTC的双流时序原则

保持I2S实际采音和实际播放分别计数；以设备时钟给参考、采音和播放完成位置打标。参考应来自送入输出路径的PCM，并覆盖音量、重采样和排队延迟；不能以“桥接已发出字节数”代替“用户实际听到位置”。

先记录本机三路同步音频，分只有助手说话、只有用户说话、双方同时说话三组测量。时序正确后，再比较现有ESP-SR与成熟AEC实现；若用电脑APM做对照，必须把ESP32参考时间、队列和时钟漂移一起处理。

### 2. 桥接参考LiveKit的插话管理

候选语音出现时保留用户前置音频和助手续播位置，可短暂压低/暂停声音；使用消回声后的语音持续性、转录或专用分类器确认是否真在插话。不要把等待识别到完整句子作为唯一条件，否则响应会慢，也会漏掉“停”“等等”等短指令。

确认后才永久取消旧回答；误触发时从正确位置续播。ASR/语义可以辅助区分附和词、噪声与插话，但扬声器回声若被识别成词仍会误判，所以不能绕过AEC验收。

### 3. 借鉴Realtime的取消和播放位置闭环

确认插话后立即停设备输出、清旧队列并递增播放代数；桥接取消旧模型响应、丢弃迟到音频，再上传缓存和后续用户音频。按千问当前实际支持的协议处理历史；OpenAI的`conversation.item.truncate`只是公开参考，不能假设千问支持。

云端生成结束、本地还未播完的情况也必须能打断。误判续播与最终取消应有各自状态，避免一暂停就不可恢复，或旧回答重新响起。

## 工程选择

优先顺序是：现板修时序并采证据 → 用电脑成熟处理做A/B对照 → 按结果决定是否增加音频前端硬件。可参考LiveKit的控制策略，不必立即把整套框架、服务和供应商替换进项目。

若现板在高音量下出现ADC削顶、功放非线性或严重结构串音，软件可能达不到目标。此时再评估麦克风与喇叭隔离、降低音量、增加参考通道或专用音频处理器。不能只凭设备价格或AEC初始化日志决定换板。

验收目标沿用：远端独播误触发、近端独播首字完整、真实双讲命中/延迟、误触发续播、长回答完整、点云稳定和30秒静默待机。200–400毫秒停播可作为目标，不能当成已实现成绩。
