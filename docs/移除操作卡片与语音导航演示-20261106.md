# 移除操作卡片与语音导航演示

牛牛要求彻底移除“操作已返回结果”卡片，并修复语音“演示一下导航”不能执行的问题。本次北京时间 2026-11-06 07:44 已加载到现有网关，设备固件仍为0.3.16，无OTA。

## 根因

通用反馈由 `AssistantRuntime.operation_screen_feedback` 从工具与后台API统一触发，固件把 completed 状态显示为“操作已返回结果”。此前只精简话术，没有移除此下发路径。

导航演示原来只有 `/api/workflows/navigation-demo` 和命令行入口，语音模型没有对应工具。07:35日志中，“演示一下导航”被回答成需要目的地，之后又要求位置；并未进入已有演示。

## 修改

- `assistant_runtime.py`：通用操作的开始/结果/失败都不再调用 `send_screen_card`。后台完成记录保持有界32条与24小时过期，专用提醒、计时、天气等卡片仍独立运行。无需更新固件即可使该通用卡片不再出现。
- `src/assistant_app/application/navigation_demo.py`：复用原七句固定模拟路线与 `ProactiveSpeech`，集中后台与语音入口，首句明确“模拟导航”。单进程一个演示，无队列；待交接请求120秒过期，语音关闭与设备会话清理最多等待15秒，独立播报仍用现有超时。
- `gateway.py`：新增 `start_navigation_demo` 工具，校验当前真实请求中的演示意图；拒绝真实导航、否定、引用、翻译及解释类问题，支持“能不能演示一下导航”。工具只登记，回答结束并关闭当前会话后才运行；新输入、取消、重新唤醒、关服务会取消旧请求，已登记的演示不补跑电脑/空调兜底。
- `control_api.py`：后台接口复用同一服务，不另起一套播报。
- `extensions.py`：服务生命周期；`llm_providers.py`：明确演示无需定位或目的地，必须调用工具，不能只口头承诺。
