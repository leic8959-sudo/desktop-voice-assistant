# 虫洞 BOX 3.5 的 ST7796 源码接入与构建记录

后续更新：CAM四种屏幕已分别完成首次整板缓存构建，采用核对过的CH32协议，3.5保留ST7796默认初始化；CHD3.5回归通过。整端口复位、外围未接入和实机限制仍在。见[本批记录](ws_cam_native_20261112.md)。

本批覆盖已有 `chd-esp32s3-box-lcd35` 源码入口。它此前缺少ST7796 1.3.5组件，只完成共享显示单元编译；本批复用现有SDK的DCS绘图操作，并显式替换成核对过的ST7796复位／初始化流程。另对BOX2.8与LilyGO MVSRLoRa分别执行完整构建回归。构建和实机验收分别记录。

## 来源与实现范围

已归档的ST7796 1.3.5 general驱动与1.4.0 general驱动的默认12条初始化命令逐项一致。1.3.5再次通过只读 `gh api` 核对固定提交 `espressif/esp-bsp@618b05297dae1aa3fab986d5ca7b89b328e1919a` 的 `components/lcd/esp_lcd_st7796/esp_lcd_st7796_general.c`，返回Git blob `f20854f8b26eec8c86b623cc6bc87f1b8ae14de8`，文件SHA256为 `dc67f5511567c20ca48ef1190a680504efb2653dfc14ad8312e9d7288cb6a440`，与旧参考逐字相同。

本次只覆盖已审阅的SPI、BGR、16位缓冲、默认表及现有一次板级启动路径。创建SDK ST7789公共操作后立即替换reset/init，不调用其默认初始化，因此不会追加RAMCTRL或改用其默认COLMOD。硬件型号继续登记为ST7796；上游代码曾使用ST7789工厂，不能据API名称证明真实屏控型号。

| 项目 | BOX3.5 | LilyGO回归 |
| --- | --- | --- |
| 复位 | 板级reset为NC，发送软件0x01后等待120ms | GPIO47低10ms，高后等待120ms，保留返回值检查 |
| 初始化 | SLPOUT后100ms、MADCTL08、COLMOD05、原默认12命令 | 相同默认表和原时序 |
| 绘图 | 原16位缓冲与DCS窗口、gap、方向操作 | 原16位缓冲、方向与gap49／0 |
| sleep／brightness | 保持原general驱动未提供的API范围，回调置空 | 原范围保留，背光仍由板级控制 |

SDK内部COLMOD缓存55不会在当前后续绘图／方向调用中重写实际发送的05；本批没有提供任意外部格式变更或通用重新初始化能力。原general和SDK绘图路径均检查IO错误，不能把原来已有的错误传播算成新增功能。未迁移CAM3.5的CH32流程、P4 SPI3.5或其它18／24位、i80、MIPI路径。

源码修改限于共享显示文件、main构建依赖、默认表来源注释、BOX3.5组件声明与该profile的实现说明；导出脚本只扩展已有许可复制条件，使BOX3.5同时附带ST7796 Apache-2.0许可，未执行Docker导出。没有新增profile或复制第二套默认表。

## 触摸与完整终端边界

BOX2.8／3.5触摸源码保持上一批原文：FT0x38 → GT0x5D → GT0x14，仅NACK才继续，FT正式组件和GT轮询共存；全NACK保持可选触摸语义；错误、多点和越界取消操作，初始与恢复等待真实松手；pointer按FT handle或GT Init成功创建。

GT3.5仍使用 `(y,x+80)`，有效可见Y只有80..319。这个全高坐标限制没有因整板可编译而解决。GT2.8与两条FT映射也未改。音频、完整唤醒、AEC、自然插话／媒体人工决策、配网／绑定／NVS和双OTA源码摘要均与本批开始时一致。

只有现有微雪1.8可用于实机验收。BOX3.5实际屏控、gamma／颜色／COLMOD05／方向、Flash／PSRAM、GT／FT型号和地址、复位、端点／多指／首次按住／释放／错误恢复、24kHz双codec／TDM4、PA46、AEC／唤醒／自然插话、媒体、绑定和同板双OTA尚未实机验收。没有将摄像头、蜂窝、供电或电池等原范围限制改记完成。
