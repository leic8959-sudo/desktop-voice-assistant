新增文件：`src/assistant_app/application/productivity.py`、`src/assistant_app/api/productivity.py`、`web/productivity.html`、`web/productivity.js`、`web/productivity.css`。没有修改规则、凭据、设备绑定、固件及父应用入口。

## 接入合同

- `ProductivityService(config, store, runtime, http)`；`await start()` / `await close()`；`tool_schemas` 使用现有 `{type: function,name,parameters}` 结构，完整描述输入字段。
- `PRODUCTIVITY_KEY = web.AppKey('productivity_service', ProductivityService)`。父应用把服务放入 `app[PRODUCTIVITY_KEY]`，调用 API 模块 `register_routes(app)`，并把页面通过既有 `/static/` 路由展示。
- `invoke(name,args,subject='voice')` 提供 `create_routine`、`list_routines`、`routine_action`、`daily_summary`、`subscribe`、`scene_preview`。API与语音是同一个本机owner；subject字符串不授予写权限。
- 场景确认不属于模型工具：仅独立的已认证管理员接口能调用 `confirm_scene`，不接受模型伪造确认标志。
- 依赖现有 `store.screen_tasks(end,limit=10)` 返回 `{tasks,truncated}`、`runtime.home`、`runtime.connector_registry`、`runtime.send_screen_card` 以及注入的 aiohttp 会话。

## 可以操作的能力

重复提醒支持每天、每周、每月和间隔分钟；首次时间必须带时区，默认使用 `store.business_timezone`。每月没有指定日期时采用月末。夏令时缺失分钟顺延，重复时刻取第一次。支持暂停/恢复、跳过下一次、完成/跳过指定本次、取消和删除已取消规则。固定计划与“完成本次后再计时”分别计算；同时最多保留一个未处理实例，离线不补发无限历史提醒。完成必须绑定本次ID、规则revision及幂等键，不会重复推进下一次。

早晚摘要默认关闭；页面可分别启用、设置时间/时区、选择Google或Microsoft日历与天气城市，并立即读取。摘要仅聚合真实结构化数据，明确是本次最多10条的列表，不把截断列表计数说成总量。第三方失败显示unknown；不会伪造模型摘要、自动发邮件或抢占语音。

GitHub CI订阅读取最近10次workflow运行；HA订阅只读管理员明确填写的单个 `sensor` / `binary_sensor` 实体。首次读取建立基线，之后有变化才通知。支持暂停/恢复、立即读取和删除、匹配状态以及关联场景。订阅采用轮询，可能遗漏两次读取之间的瞬时状态；本模块没有声称WebSocket实时事件或完整CI历史覆盖。

家居场景从已授权设备与已发现动作选择，参数按既有schema生成选项或数值输入，无需手写JSON。最多10步，支持排序、编辑、删除、真实动作预览和独立确认。随机确认凭证绑定owner、场景版本和参数，有效5分钟；执行前持久写入账本。逐步执行，任一步未观察到目标、网络异常或超时即停止。已执行步骤不自动补偿；同一凭证重复提交回放持久结果。重启丢失尚未消费的内存凭证时必须重新预览；执行中断返回unknown，不会自动重试。HA报告目标状态不代表独立物理确认。传感器订阅关联场景只提供通知中的预览入口，不自动执行写动作。

## 持久性与边界

按设备ID散列使用独立 `runtime/productivity-<scope>.sqlite`；UTC存储绝对时刻，业务日界按选定IANA时区计算。SQLite事务、固定事件ID、条件更新和共享文件租约避免重复领取；重启补建已领取但未生成事件的本次提醒。屏幕卡片先持久记录再尝试发送一次；服务崩溃在持久化之后、发送之前会留下无交付回执的事件，用户可在页面看到，不能保证恰好一次设备显示。

容量：200规则、32订阅、64场景；每个规则最多1个待处理实例；已处理实例最多2000条/30天；通知最多500条/30天（页面最近50条）；幂等请求4096条/30天；执行账本1024条/30天，未消费预览5分钟过期。容量满会拒绝新增。调度每15秒处理有界批次；单文件适用于本机/共享SQLite文件的实例，同一数据放到多主机独立磁盘不具备分布式协调。所有外部读取/执行有显式超时，写操作未知时不重试。

## HTTP

- GET `/api/productivity/{routines|summaries|subscriptions|scenes|events|home-catalog}`
- POST `/api/productivity/{routines|summaries|subscriptions|scenes}`；本地写请求带`idempotency_key`，更新已有对象带`revision`。
- POST `/api/productivity/routines/{id}/{pause|resume|cancel|complete|skip|delete}`
- POST `/api/productivity/subscriptions/{id}/{pause|resume|delete|check}`
- POST `/api/productivity/scenes/{id}/{preview|delete}`
- POST `/api/productivity/scenes/confirm`：`confirmation_id`和显式`confirmed:true`，同时必须通过现有管理员认证。
- POST `/api/productivity/summary`；POST `/api/productivity/events/{id}/ack`。

API不另建认证旁路，必须放在父应用既有 `api_boundary` 下，沿用同源及管理员边界。前端复用 `web/console_api.js`，令牌只保留输入框，不持久化。

## 补充：默认关闭的主动语音播报

新增 `src/assistant_app/application/proactive_speech.py`。`ProductivityService`持有 `self.speech`，构造时登记 `runtime.proactive_speech`，随生产力模块启动和关闭。`ProactiveSpeech.active`是独立子任务，`await stop()`仅取消并等待该任务，不取消调度主任务；stop及清理不获取voice_lock。开始播报在runtime.voice_lock内检查会话并登记active后释放；父应用的NativeDevice.start与gateway.open_session也在同锁内先stop再登记新会话，从而串行交接音频通道。另以50ms监测及每20ms帧发送前检查兜底，用户对话优先。

页面早晚摘要区新增主动播报授权checkbox，默认关闭；明确勾选并保存后才启用。可以分别选择早晚摘要、重复提醒和订阅变化；默认类别仅摘要。GET/POST `/api/productivity/speech`读取/保存设置；POST必须通过既有管理员认证，启用还需要confirmed:true、revision及idempotency_key。此设置不暴露给模型invoke，不允许模型自行打开播报。

播报遵守现有设备免打扰时段（设备偏好目前使用Asia/Shanghai）、提醒静音/零音量、会话静音/零音量、现有会话及设备忙碌；无单一在线设备、未知协议固件或TTS未配置都跳过。仅选择一台在线、声明屏幕卡片能力且固件版本至少0.3.5的设备，多台在线不广播。90秒以上的错过计划只保留屏幕和事件，不补播；没有播报队列、不自动重试，事件先落盘，同一事件不会重启后重新播报。

TTS适配器继承现有ChatBackend，只复用 `_open_tts`、`_tts_feed`、`_tts_read` 和既有鉴权，不调用connect，不开ASR、聊天或工具会话。合成使用现有chat_tts_model/chat_tts_voice及阿里凭据，用户授权的提醒文本会发送现有TTS供应商。文本最多120字符，完整音频合成后才允许发设备；PCM16单声道24kHz，最多30秒/1,440,000字节（小于2MiB），超限拒绝整段发送。云单消息限制2MiB、合成总超时35秒、整个播报70秒、设备单次发送2秒、云关闭2秒；按20ms帧节拍发送，事件循环延迟时不突发追赶。开始标记尝试发送即登记播放阶段，失败或取消发送带旧playback_id的interrupt；成功发送tts stop并保留300ms排空窗口。临时云连接、子任务和音频缓冲在结束或异常时释放。

固件源码 `control_protocol.cpp`已有tts state=start/stop、interrupt playback_id以及PCM24二进制播放路径，可直接复用，无需为这条软件路径修改固件；实际已连接设备仍需后续授权验收。其TTS输出走会话音量通道，没有字段选择提醒音量通道，因此服务额外尊重会话静音，不擅自改音量配置；不能宣称精确使用提醒音量。固件audio_stats没有playback_id，NativeDevice也不存储这次TTS播放确认，所以事件只记录sent/skipped/cancelled/failed/unknown及device_playback_confirmed:false。sent严格表示音频及结束标记已发送，不表示扬声器已出声或完整播放；显示和音频分别验收。

本轮新增播报代码仅读取源码并核对调用合同；没有运行任何检查命令、测试、编译、服务、真实云请求或播音，也未安装依赖、写Git、上传或发布。互斥锁适用于同一网关进程；不要把多个独立网关进程的内存voice_lock当作跨主机音频仲裁。

同时将前端幂等键改为crypto.getRandomValues生成32位hex，避免局域网HTTP下crypto.randomUUID不可用。
