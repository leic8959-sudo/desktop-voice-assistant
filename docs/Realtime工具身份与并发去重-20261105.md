# Realtime 工具身份与并发去重（2026-11-05）

## 真实复现

原 `process_tools` 用裸 call_id 查会话结果缓存，在等待状态发送和真实工具执行后才写结果。两个并发批次可以同时看见缓存为空并分别执行。相同 ID 的不同名称或参数也会误用旧结果，真实新用户输入复用同 ID 则可能收到上一请求结果。

主代理实际执行初始 `python -m unittest tests.test_realtime_tool_identity`：5 个方法、0.215 秒、6 个有效失败（含冲突子例），证据 `evidence/realtime-tool-identity-20261105-before.log`。使用真实 VoiceSession、RealtimeBackend、FakeCloud 和仅记录动作的服务，没有调用真实云端或设备。

## 当前实现

仅修改 `gateway.py`。实际 `response.done` 分支在第一次等待前快照真实 response_id、已接受输入代数和 generation，再显式传给工具处理；发送 usage 后检查该 scope 仍有效，旧响应不能继续改新播放队列、完成标记或启动工具任务。没有用 response.created 时刻提前绑定，以免合法的转写晚于响应创建时误拒绝首句；私有工具调用必须显式提供稳定 scope，没有随机或当前响应兜底。

每批最多 8 个调用，ID 最多 256 字符、名称 128 字符、JSON 参数最多 16KiB；参数必须对象且规范 JSON 有限。整批预检后，在首次等待前预留身份。相同 ID、名称及规范参数在同批合并；后置冲突也拒绝整批，不能先执行前面有效工具。混合新调用和已登记调用的批次同样拒绝，不让新写入越过仍在等待结果的旧动作。

冲突“整批零动作”只指新收到并被拒绝的该批；此前已经开始的独立 owner 不在撤销范围，不能据此推断既有动作已补偿或取消。

身份记录以已接受输入代数和 call_id 定位，并校验 response_id 与参数指纹。当前没有已验证供应商证据允许同一用户输入里跨响应复用 call_id，故保守拒绝这类复用；新的真实用户输入是独立 scope，可合法复用 ID。创建任务等本地幂等工具使用 session、输入代数、响应、调用 ID 的稳定短 SHA256 键，不因长 vendor ID 超出存储限制或错误撞上上一请求。

重复入口直接退出，不建立 Future、后台执行任务、等待者或跨等待的大锁，由先到执行者唯一发布结果和请求后续回答。重复调用不会阻塞新输入，也不会取消原执行者。会话最多 100 个身份记录，包含取消/旧输入退出的墓碑；取消继续传播，可能已经执行的身份不能重新执行或被伪造成成功。未知结果暂停和旧输入不回填合同保留。

非法 scope、非列表或超大批次只发一条固定本地提示，不向无效响应发送逐调用结果；合法最多 8 项、ID 可识别的冲突批次返回固定参数错误，最多 8 条，不回显参数原文。

## 回归与边界

`tests/test_realtime_tool_identity.py` 当前 14 方法，覆盖受控并发动作一次和唯一云结果、指纹冲突、后置冲突、零等待者/取消终态、新输入复用、同输入跨响应拒绝、真实 SQLite 两条任务和长 ID、usage 阻塞期间新输入与播放状态保护、会话容量、参数有限性、同批合并和 1000 项超大批次零动作/零云回执；另验证首个无效批次结果已发、等待期间有新输入后，不再发送余下旧结果或旧 response 请求。

原红色最后一项的“取消重复等待者”合同在审阅后改为零等待者设计：重复调用直接结束且不发云消息，owner 仍阻塞；取消 owner 后再重复仍无动作、无成功。动作一次的核心断言保留，并新增正常并发只发布一条 tool output 和一个 response.create。

旧 `test_tool_activity.py`、`test_tool_outcomes.py`、`test_unknown_tool_chain.py`、`test_media_gateway.py` 的私有调用补显式 response scope，内部缓存检查改为 tuple 身份记录；原外部输出、执行次数和未知结果断言保留。编辑前副本在 `runtime/review-backups/realtime-tool-identity-20261105-luna/`。实施代理未执行测试或构建，主代理独立审阅并执行以下实际回归。
